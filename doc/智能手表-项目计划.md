# 智能手表 — 项目计划文档

> 项目：**AI 智能手表**（先完成基础智能手表功能，再叠加 AI 语音）
> 硬件：Waveshare ESP32-S3-Touch-LCD-1.69
> 框架：ESP-IDF v5.5.4 + LVGL 8.4（后续叠加 ESP-Brookesia）
> 文档版本：v1.0　｜　日期：2026-10-06

---

## 一、项目目标

### 最终目标

> 做一块**能用语音指挥 AI 干活的智能手表** —— 「现在几点了」「我今天走了多少步」「测一下心率」，AI 听懂后调用设备上的服务，把结果念给你听。

### 分阶段目标

| 阶段 | 目标 | 产出 |
|---|---|---|
| **P1** | **普通智能手表** | 能看时间、能计步、能设置的手表 |
| **P2** | **联网手表** | 能连手机、能同步时间、能推送通知 |
| **P3** | **AI 语音手表** | 能听会说，能语音查数据 |
| **P4** | **健康监测** | 加 MAX30102，能量心率血氧 |

**本文档覆盖 P1 和 P2。**

## 三、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| **RTOS** | FreeRTOS（ESP-IDF 自带） | 官方支持，够用 |
| **GUI** | **LVGL 8.4** | 事实标准；和后续 Brookesia 一致 |
| **显示驱动** | `esp_lcd` + `esp_lcd_panel_st7789` | 官方组件 |
| **LVGL 移植** | `espressif/esp_lvgl_port` | 官方维护，省去自己写任务/锁 |
| **触摸驱动** | `esp_lcd_touch_cst816s` | 官方组件 |
| **构建系统** | CMake + idf.py | ESP-IDF 标准 |
| **图形设计** | 手写 LVGL 代码（后续可上 SquareLine/EEZ Studio） | 可控 |

### 为什么不用 ESP-Brookesia（暂时）

| 原因 | 说明 |
|---|---|
| 1 | Brookesia 是**应用框架**，需要先有能跑的硬件层 |
| 2 | 你的板子**不在官方支持列表**，要先自己写板级适配 |
| 3 | 分步走更好调试 —— 先证明硬件通了，再叠加框架 |
| 4 | LVGL 代码**可以原样迁移**到 Brookesia |

**策略：P1/P2 用纯 ESP-IDF + LVGL 打基础，P3 再迁移到 Brookesia。**

## 五、验收标准

### M1 屏幕点亮

- [ ] 上电后屏幕亮起，显示设计好的表盘界面
- [ ] 手指点击屏幕，界面有响应（页面切换）
- [ ] 串口能看到启动日志，无报错

### M2 表盘

- [ ] 时间准确显示时:分
- [ ] 日期/星期正确
- [ ] 断电重启后时间不丢失（RTC 有纽扣电池或超级电容）
- [ ] 能通过串口设置时间

### M4 计步

- [ ] 正常走路 100 步，误差 < 10 步
- [ ] 静止放置 10 分钟，步数不增加
- [ ] 摇晃设备，不会大量误计

### M7 BLE

- [ ] 手机蓝牙能搜索到设备
- [ ] 能连接并读取设备信息
- [ ] 能通过 BLE 同步时间到手表

## 六、工程结构

```
firmware/smartwatch/
├── CMakeLists.txt
├── sdkconfig.defaults          # 默认配置（芯片/Flash/PSRAM/LVGL）
├── partitions.csv              # 分区表
├── main/
│   ├── CMakeLists.txt
│   ├── idf_component.yml       # 组件依赖
│   └── main.c                  # ★ 主程序
├── components/
│   ├── bsp/                    # ★ 板级支持包（屏幕/触摸/背光）
│   ├── rtc/                    # (M2) PCF85063 驱动
│   ├── imu/                    # (M4) QMI8658C 驱动
│   ├── battery/                # (M3) 电量采样
│   └── ui/                     # (M3) LVGL 界面模块
└── README.md
```

**设计原则：每个硬件模块一个组件，主程序只做业务逻辑。**

## 七、风险与应对

### 7.1 ⚠️ 已实测确认的问题（试编译踩出来的）

| # | 问题 | 现象 | 解决 |
|---|---|---|---|
| **1** | **中文路径** | CMake 报 `FileNotFoundError`，路径乱码 | **工程放纯英文路径**（推荐），或设 `PYTHONUTF8=1` |
| **2** | **sdkconfig.defaults 中文注释** | `Missing required kconfig option after retry` | **该文件用纯英文注释**（代码文件中文没问题） |
| **3** | **Python 环境版本不匹配** | `export.ps1` 报找不到 py3.12 环境 | 改用 `Initialize-Idf.ps1 -IdfId ...` |

> 详见[实施文档](./智能手表-实施文档.md)开篇「三个已踩过的坑」。

### 7.2 预判风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 4 | 组件下载失败（网络） | 编译不了 | 设国内镜像 `IDF_COMPONENT_REGISTRY_URL`；或手动放进 components/ |
| 5 | ST7789 显示偏移/花屏 | 屏幕不能用 | 三个关键调用：`mirror(true,true)` + `set_gap(0,20)` + `invert_color(true)` |
| 6 | 触摸坐标不对 | 点不准 | 调 `swap_xy` / `mirror_x/y` |
| 7 | **RTC 掉电丢失** | 每次开机要重设时间 | 原理图里**没看到 RTC 备份电池**，需实测确认；没有就靠 BLE/WiFi 校时 |
| 8 | 计步算法不准 | 数据不可信 | 先用简单峰值检测，再逐步调参 |
| 9 | 中文字体占 Flash 太多 | 空间不够 | 用 `lv_font_conv` 只提取用到的字（PC 上已验证） |
| 10 | LVGL 内存不足 | 卡顿/崩溃 | 已开 PSRAM + `LV_MEM_CUSTOM` |
| 11 | LVGL 多任务崩溃 | 随机死机 | 碰 UI 前必须 `bsp_display_lock()` |
| 12 | 烧录不进去 | 卡住 | 按住 BOOT 再上电进下载模式 |
