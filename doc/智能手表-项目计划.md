# 智能手表 — 项目计划文档

> 项目：**AI 智能手表**（先完成基础智能手表功能，再叠加 AI 语音）
> 硬件：Waveshare ESP32-S3-Touch-LCD-1.69
> 框架：ESP-IDF v5.5.4 + LVGL 8.4（后续叠加 ESP-Brookesia）
> 文档版本：**v2.1**　｜　日期：**2026-10-08**
>
> **v2.0 改了什么**：第一版（v1.0）是**动手写代码之前**写的计划，
> 现在 P1 已经全部做完（固件 v0.6.0），所以这一版做三件事：
> ① 计划里的每一项都标上**实际状态 + 在哪个版本做的**；
> ② 补上**计划外做掉的东西**（当时没想到、后来按需求加的）；
> ③ 把风险表从"预判"改成"**已发生/已解决/仍在**"，并把踩过的坑归类——
> 这部分比原计划更有价值，因为它是实测出来的。
>
> **v2.1 改了什么**：固件推进到 **v0.6.1** —— 这一版**不加新功能**，做的是
> 「A 批：缺陷修复 + 性能配置」（12 项，见 `doc/version/v0.6.1.md`）：
> 修掉 2 个**确认的内存安全缺陷**（WiFi 页定时器 use-after-free、LVGL 事件回调里删祖先对象）、
> 1 个**让 WiFi 卡死的状态误判**，编译从 `-Og` 提到 `-O2`，
> 并补齐 coredump + `taskmem/stats/bt/crash` 四项调试设施（**真机已验证**）。
> 本版新增的教训见 7.4 节。

## 一、项目目标

### 最终目标

> 做一块**能用语音指挥 AI 干活的智能手表** —— 「现在几点了」「我今天走了多少步」「测一下心率」，AI 听懂后调用设备上的服务，把结果念给你听。

### 分阶段目标

| 阶段 | 目标 | 产出 | **实际状态** |
|---|---|---|---|
| **P1** | **普通智能手表** | 能看时间、能计步、能设置的手表 | ✅ **已完成**（固件 v0.6.0，M1~M6 全达成）；v0.6.1 又做了一轮缺陷修复与性能配置 |
| **P2** | **联网手表** | 能连手机、能同步时间、能推送通知 | 🔶 **做了一半**：WiFi 连接页 + SNTP 校时已做（v0.4.0，v0.6.1 修掉"失败被误判成主动断开"的卡死）；BLE 未开始 |
| **P3** | **AI 语音手表** | 能听会说，能语音查数据 | ⬜ 未开始（等 I2S 麦克风 + 功放） |
| **P4** | **健康监测** | 加 MAX30102，能量心率血氧 | ⬜ 未开始（界面占位页已留好） |

**本文档覆盖 P1 和 P2。**

## 三、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| **RTOS** | FreeRTOS（ESP-IDF 自带） | 官方支持，够用 |
| **GUI** | **LVGL 8.4** | 事实标准；和后续 Brookesia 一致 |
| **显示驱动** | `esp_lcd` + `esp_lcd_panel_st7789` | 官方组件 |
| **LVGL 移植** | `espressif/esp_lvgl_port` | 官方维护，省去自己写任务/锁 |
| **触摸驱动** | `esp_lcd_touch_cst816s` | 官方组件 |
| **构建系统** | CMake + idf.py | ESP-IDF 标准 |
| **图形设计** | 手写 LVGL 代码（后续可上 SquareLine/EEZ Studio） | 可控 |

### 实施中补上的三条做法（v1.0 时没写，但已经成了硬约束）

| 做法 | 为什么必须 |
|---|---|
| **组件全部本地化到 `components/`**，`IDF_COMPONENT_MANAGER=0` | 不再依赖联网下载组件；换机器/断网都能编译（对应风险表 #4） |
| **界面层零 ESP-IDF 依赖** + 平台能力用函数指针钩子注入 | 同一套界面源码能在 **PC 模拟器**里跑（`lvgl_sim/`），改界面不用烧板子 |
| **平台端与界面端分开验证**：PC 模拟器负责逻辑与画面，实机负责触摸手感/帧率/颜色 | 我这一侧没有实机，必须把"能自动验证的"尽量前移 |

### 为什么不用 ESP-Brookesia（暂时）

| 原因 | 说明 |
|---|---|
| 1 | Brookesia 是**应用框架**，需要先有能跑的硬件层 |
| 2 | 你的板子**不在官方支持列表**，要先自己写板级适配 |
| 3 | 分步走更好调试 —— 先证明硬件通了，再叠加框架 |
| 4 | LVGL 代码**可以原样迁移**到 Brookesia |

**策略：P1/P2 用纯 ESP-IDF + LVGL 打基础，P3 再迁移到 Brookesia。**

## 六、工程结构

> ⚠️ v1.0 里画的结构（bsp/rtc/imu/battery/ui 五个组件）是**动手前的设想**，
> 实际长成了 22 个组件。以实际为准：

```
firmware/smartwatch/            ← git 仓库根目录
├── README.md                   # ★ 项目门面（功能/硬件/编译/设计要点）
├── CMakeLists.txt
├── sdkconfig.defaults          # 默认配置（芯片/Flash/PSRAM/LVGL/滚轮页数）
├── partitions.csv              # 分区表
├── build.ps1                   # 构建脚本（build / flash / monitor / clean）
├── main/                       # 入口
├── doc/
│   ├── 智能手表-项目计划.md        # 本文档
│   ├── 智能手表-实施文档.md        # 实施细节 + 已踩的坑
│   ├── QMI8658C-计步方案.md       # 寄存器表 / 算法推导 / 调参流程
│   ├── images/                 # README 用的界面截图（模拟器生成）
│   └── version/                # ★ 一个版本一个文档（v0.1.0 ~ v0.6.0）
├── tools/                      # ★ 开发工具（都是脚本，不是固件代码）
│   ├── gen_font.ps1            #   中文字库按需抽字
│   ├── check_all_literals.py   #   校验：界面里出现的汉字都在字库里
│   ├── check_fonts.py          #   校验：没有"ASCII 字体 + 中文文案"的组合
│   ├── check_glyphs.py         #   校验：字库覆盖
│   ├── gen_dino_sprites.py     #   精灵图 PNG → 2bpp C 数组（含核对图）
│   └── serial_*.py / imu_dump.py / step_*.py   # 串口、IMU 导出、计步调参
└── components/                 # 22 个组件
    ├── board/                  # ★ 全工程唯一知道 GPIO 号的地方
    ├── bsp/                    # 屏幕 / 触摸 / 背光 / LVGL 移植
    ├── ui_port/                # UI 平台端口（实机版 / PC 版各一个实现）
    ├── watch_ui/               # ★ 界面框架：主题/控件/轮播/手势/模态/控制中心
    │                           #   时钟服务、到点提醒层、画布绘图、游戏宿主
    ├── watch_ui_pages/         # ★ 具体页面 + 游戏本体（含生成的精灵位图）
    ├── fonts/                  # 生成的中文字库（14/16/20px）
    ├── data_hub/               # ★ 设备状态唯一真源（UI 只读它）
    ├── event_bus/              # 组件间事件
    ├── settings/               # 所有可持久化配置（NVS）
    ├── motion/                 # 步数/距离/卡路里 业务层
    ├── imu/                    # QMI8658C 驱动 + 计步算法
    ├── rtc_pcf85063/           # RTC 驱动
    ├── battery/                # 电量采样
    ├── buzzer/                 # 蜂鸣器（GPIO42）
    ├── power/                  # 息屏/唤醒/活动计时
    ├── wifi_service/           # WiFi 连接 + SNTP 校时 + 凭据自愈
    ├── imu_logger/             # IMU 数据录制（存 flash，可导出）
    ├── app/                    # 应用层：装配上面所有东西 + 串口命令行
    └── lvgl / esp_lvgl_port / esp_lcd_touch*   # 本地化的第三方组件
```

**设计原则（实测下来这几条最值钱）**：

1. **每个硬件模块一个组件**，主程序只做装配和业务；
2. **`board.h` 是全工程唯一写 GPIO 号的文件**，换板子只改它 + bsp；
3. **`data_hub` 是设备状态的唯一真源**，UI 只读快照，不直接碰驱动；
4. **界面层与平台层之间只走函数指针钩子**（亮度/设置/WiFi/蜂鸣器/时间/息屏），
   所以界面代码能在 PC 上原样跑；
5. **中文字面量集中登记**，加中文 = 写文案 + 跑字库脚本 + 跑三个校验脚本。

### PC 模拟器（`lvgl_sim/`，仓库外）

| 项 | 说明 |
|---|---|
| 作用 | 直接引用 `components/watch_ui*` 的**同一份源码**，编译成 Windows 程序 |
| 能力 | 逻辑自检（轮播/时钟/游戏，共 3 段）、PNG 截图、手动推帧、整树诊断 |
| 收益 | 改界面几秒见效；**v0.5.0/v0.6.0 用户报的问题，静态检查全过，只有看画面/跑自检才发现** |
| 退出码 | 自检模式返回"失败项数"，可以直接当自动化验收门槛 |

### 7.3 开发过程中的教训（值得保留的做法）

| 做法 | 起因 |
|---|---|
| **改动前先翻 LVGL 源码**，不靠印象 | 多个坑都出在"想当然"上（滚动、点击、画布布局） |
| **配置类改动先看 kconfig 有没有真正生效** | 改 `sdkconfig.defaults` 不 clean 不生效；改完要在生成的 `sdkconfig` 里确认 |
| **不要在 shell 里回写源码文件** | 两次事故：PowerShell 5.1 把 UTF-8 写成 ANSI；`Set-Content -NoNewline` 把整个文件压成一行 |
| **自检的断言本身也会错** | 假泄漏、"跨页比对象数"、"动画没跑完就量布局"都发生过 —— 报错时先怀疑测试 |
| **验证工作分两半，界面能自动化的尽量自动化** | 用户只做"必须人手做的"：烧录、触摸手感、颜色、最终确认 |
| **修 bug 时把修复临时"藏起来"再跑一遍自检** | v0.6.1 的 A1：藏掉修复后模拟器直接**段错误**，证明这个 P0 是真的、断言也真的抓得住。**能抓住 bug 的断言才算断言** |

### 7.4 v0.6.1 新增的教训（都是这轮实测出来的）

| # | 教训 | 具体经过 | 以后怎么做 |
|---|---|---|---|
| 19 | **"置个标志等事件来消费"的模式很脆** —— 事件可能根本不来 | WiFi 连接失败被误判成"用户主动断开"：`hook_connect` 无条件置标志、指望紧随的断开事件消费它，但**断开空闲站点压根不产生事件** → 标志残留 → 真正的认证失败被吞掉，**既不报错也不清坏密码**，用户永远卡在"一直连不上" | 这类标志一律**带上"该不该期待事件"的判定**，并在等待窗口结束后**强制清掉**；别假设事件一定会来 |
| 20 | **在事件回调里删"祖先对象"= 读已释放内存** | `w_modal_close()`/游戏退出都在按钮回调里删自己的祖先。LVGL 的 `_lv_event_mark_deleted()` 只在"被删对象**就是**事件 target"时置位，而事件循环返回后仍会读 `current_target->parent` | 删祖先要么 `lv_obj_del_async`（先隐藏防闪帧），要么**把整个收尾推迟出事件派发**（`lv_async_call`）。**同一棵树上不要排两个延迟删除**（顺序不保证 —— 这轮我踩了，模拟器立刻崩） |
| 21 | **编译器优化等级会"暴露"老代码的问题** | 从 `-Og` 提到 `-O2` 后立刻 3 处编译失败：`strncpy` 不补 `\0`（两处）、`snprintf` 源串可能不保证终止、我新写的 `char core[5]` 装不下 int —— **全是真问题，不是误报** | 定期用 `-O2` 编译一次（本项目现已固化）；顺手把 `-Werror` 留着，别关 |
| 22 | **布局要按"内容区"算，不是屏幕高** | 功能列表 5 行一屏：按 280 算出行高 46 能放下，实测**溢出 22px** —— 页面根有 `pad_all = 12`，内容区只有 256 | 算布局先确认父容器的 padding/边框；改完**用自检量出来**（这次就是自检报的"可滚 22px、末行底部 289"） |
| 23 | **模拟器与实机语义必须一致，否则那条路测不到** | 模拟器的 `sim_screen_activity()` 是**空实现**（灭屏时不会亮屏），于是"息屏→触摸→亮屏"这条路径在模拟器里永远走不到，"第一下触摸穿透"这个 bug 也就测不出来 | 写平台钩子的桩实现时，**语义要和实机对齐**，不能只写个空函数糊过去 |
| 24 | **"AP 侧问题"要留证据、别急着下结论** | WiFi `reason=2` 一路查到"我们的认证通路正常、是 AP 不回应"，而当用户重输密码就好了（**没动路由器**）时，那个"AP 按 MAC 过滤"的推测就不成立了 | 报告里把**已证实的**和**最可能的解释**分开写（v0.6.1 §8.5 就是这么记的）；一行命令能定论的就别猜 |
