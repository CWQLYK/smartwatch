### 1.2 加速度 ODR 位定义（⚠️ 最容易踩的坑）

`CTRL2.aODR<3:0>` 的**实际输出速率取决于陀螺是否同时使能**：

| aODR | 仅加速度 | 6DOF（aEN=1 且 gEN=1） | 模式 |
|---|---|---|---|
| 0000 | N/A | 7174.4 Hz | Normal |
| 0001 | N/A | 3587.2 Hz | Normal |
| 0010 | N/A | 1793.6 Hz | Normal |
| 0011 | 1000 Hz | 896.8 Hz | Normal |
| 0100 | 500 Hz | 448.4 Hz | Normal |
| **0101** | **250 Hz** | **224.2 Hz** | Normal |
| 0110 | 125 Hz | 112.1 Hz | Normal |
| 0111 | 62.5 Hz | 56.05 Hz | Normal |
| 1000 | 31.25 Hz | 28.025 Hz | Normal |
| 1001–1011 | N/A | N/A | — |
| 1100 | 128 Hz | N/A | Low Power |
| 1101 | 21 Hz | N/A | Low Power |
| 1110 | 11 Hz | N/A | Low Power |
| 1111 | 3 Hz | N/A | Low Power |

**结论**：计步只开加速度时想拿 250Hz，写 `aODR=0101`；若同时开陀螺，同样的
`0101` 实际是 **224.2Hz**。低功耗档（1100–1111）**要求陀螺关闭**。

> 衍生提醒：SensorLib（Lewis He）里 `ACC_ODR_250Hz` 的枚举值是 5，
> 对应 250Hz 是"仅加速度"那一列。如果你在 6DOF 下照抄，会拿到 224.2Hz。

### 1.3 敏感度换算（LSB/g）

| aFS | 量程 | LSB/g | 1 LSB |
|---|---|---|---|
| 000 | ±2 g | **16384** | 0.061 mg |
| 001 | ±4 g | **8192** | 0.122 mg |
| 010 | ±8 g | **4096** | 0.244 mg |
| 011 | ±16 g | **2048** | 0.488 mg |

通用公式：`LSB/g = 32768 / (满量程 ±g)`；`加速度[g] = raw / (32768 / FS)`。
出处：Table「Sensitivity Scale Factor」（16-Bit Output）。

→ 计步推荐 **±8 g**（4096 LSB/g，0.244 mg 分辨率，余量足够覆盖跑步冲击）。

### 1.4 数据寄存器顺序（已确认）

`0x35 AX_L, 0x36 AX_H, 0x37 AY_L, 0x38 AY_H, 0x39 AZ_L, 0x3A AZ_H,`
`0x3B GX_L, 0x3C GX_H, 0x3D GY_L, 0x3E GY_H, 0x3F GZ_L, 0x40 GZ_H`

- 16 位二进制补码，**小端**（CTRL1.BE=0 时）。先读低字节。
- 出处：Table 25「Data Output Registers」。
- 一次 12 字节突发读**要求 CTRL1.ADDR_AI=1**；手册默认是 0，不设会一直读到同一寄存器。

### 1.5 复位流程

```
1. 向 RESET(0x60) 写 0xB0        ← Table 27
2. 手册 §3.3：复位最长 15ms
3. 轮询 RST_RESULT(0x4D)，读到 0x80 表示成功
4. 重新写 CTRL1 = 0x40（ADDR_AI=1）
```

**⚠️ 手册内部冲突**：§3.3 正文写 "writing the 0x0B to RESET register (0x60)"，
而 Table 27 写 "Write 0xB0 to this register"。
**建议采用 0xB0** —— 依据：(a) 寄存器表是规范性描述；(b) SensorLib、
SparkFun、Adafruit 等主流驱动全部用 0xB0；(c) 0x0B 在语义上没有对应位定义。
实践中写 0xB0 后 `0x4D` 能正常读回 0x80，已验证路径成立。

## 二、计步算法

### 2.1 信号链

```
三轴原始值 → 合矢量模长 |a| → 去重力(慢 LPF) → 带通 0.5–3.5Hz
  → 自适应门限(均值/σ) + 波峰因数门 → 上升沿峰值跟踪(回落确认)
  → 不应期 + 节律门(步间隔 CV) → 确认一步
```

### 2.2 截止频率的选择依据

步频 60–230 步/分 → **1.0–3.8 Hz**（单步对应一次冲击）。取 **0.5–3.5 Hz**：

- 低端 0.5Hz：滤掉慢摆、手腕翻转、姿态缓变；同时保留慢走 60 步/分（1 Hz）。
- 高端 3.5Hz：保留跑步 200 步/分（3.3 Hz）；同时压制打字（5–15 Hz）、
  车辆/机械振动（10–25 Hz）。

对照：PebbleOS（Stanford 合作）在 25Hz 采样下对每轴做 **0.25–1.75 Hz**
带通再算 VMC；Oxford C-Step-Counter 用 12.5Hz、0–3Hz 的 7 抽头 FIR 低通。
本方案把带宽取在两者之间，原因是手腕佩戴下 0.25Hz 下限会放进过多摆动能量。

### 2.3 滤波器系数（Q15，可直接用）

- 第 1 级：RBJ constant-skirt 带通，f0 = √(0.5×3.5) = **1.323 Hz**，带宽 2.807 octave
- 第 2 级：RBJ 二阶低通 **4.5 Hz**，Q = 0.7071（陡化上沿）

```c
/* {b0, b1, b2, a1, a2}，Q15；y = b0*x + b1*x1 + b2*x2 - a1*y1 - a2*y2 */
static const int32_t k_bp[2][5] = {
    { 5237,    0, -5237, -54370, 22362 },
    { 1850, 3699,  1850, -40129, 14760 },
};
/* 信号用 Q10（1 LSB = 0.98 mg），系数 Q15，累加器 >>15 */
```

**差分方程**（每级）：
```
y[n] = (b0*x[n] + b1*x[n-1] + b2*x[n-2] - a1*y[n-1] - a2*y[n-2]) >> 15
```

**数值验证过的响应**（Q15 量化后实测，非理论值）：

| 频率 | 增益 | dB |
|---|---|---|
| 0.5 Hz | 0.711 | −2.97 |
| 1.0 Hz | 0.972 | −0.24 |
| 1.32 Hz | 1.000 | 0.00 |
| 2.0 Hz | 0.923 | −0.70 |
| 3.0 Hz | 0.715 | −2.91 |
| 3.5 Hz | 0.607 | −4.34 |
| 5.0 Hz | 0.332 | −9.56 |
| 8.0 Hz | 0.090 | −20.9 |
| 12 Hz | 0.019 | −34.4 |
| 20 Hz | 0.0006 | −65.2 |

累加器最大幅值 **2.9e8**（±8g 输入），int32 内不溢出。
Q15 量化误差在通带内 2–4%，对峰值检测无影响。

### 2.4 去重力的时间常数（关键坑）

重力 LPF 取 **τ = 3 s**（50Hz 下 α = 7/1024）。

⚠️ **不要用 τ = 0.6 s**。0.6s 比最慢步周期（60 步/分 = 1s）还快，
跟踪器会跟着步伐本身摆动：去不掉重力，反而把步态信号放大，
并产生严重不对称的伪基线。这个坑我在验证时实际踩到过——
τ=0.6s 时去重力后的信号范围是 −90…+539 mg（严重偏置）。

另外**定点 EMA 必须四舍五入**：对负数乘积直接 `>>` 是向 −∞ 取整，
会给重力跟踪引入约 1.5 mg/s 的持续下偏，最终表现为缓慢斜坡把检测器带偏。

### 2.5 峰值检测门限

```
门限 thr = 包络(|bp| 的 EMA) + 0.30 × σ(bp)
σ 由 EMA 方差开方得到（Q20 存方差，避免精度损失）
绝对地板 60 mg；静止态进入门限 60 mg，退出门限 25 mg（滞回）
```

⚠️ **σ 不能用 E[x²]−E[x]² 算**。在 Q10 精度下这是灾难性相消：
两项各带约 1 LSB² 的舍入误差，而差值可能远小于它，
结果 σ 会在 0 和大值之间乱跳（我实测到 σ 在 0/31/43/87 之间跳），
自适应门限彻底失效。改用"相对缓慢跟踪中心的平方偏差均值"，无相消。

### 2.6 步间隔防抖：250ms 还是 300ms？

| 来源 | 取值 | 理由 |
|---|---|---|
| Oxford C-Step-Counter | **300 ms** | 注释原文："3 steps/s is a reasonable maximum" |
| 生理学上限 | ~250 ms | 240 步/分 ≈ 4 步/秒 |
| **本方案** | **max(250 ms, 35% × 学习到的步周期)** | 兼顾慢走防重计与跑步不漏计 |

**建议**：固定 300ms 会漏计跑步（165 步/分间隔仅 364ms，300ms 尚可；
但 200 步/分间隔 300ms 就压线了）。用**自适应不应期**更好：
一旦学到步周期，最小间隔取其 35%，下限锁 250ms。

配套的"半频防抖"：一次步态周期常产生**两个可比峰值**（足跟冲击 + 手臂回摆），
若两峰幅度接近（实测可达 1:0.75），单靠幅度门分不开。
可靠做法是让自适应不应期覆盖半个周期——这也是 35% 这个取值的来源。

### 2.7 "手在动但没走路"的抑制

三层，从便宜到贵：

1. **带通本身**（最有效）：打字 5–15Hz、车辆振动 10–25Hz 直接衰减 20–65 dB。
   实测：坐车 15Hz 振动 120s、机器 9Hz 振动 120s → **均 0 步**。
2. **波峰因数门**：步态冲击是脉冲型，平滑摆动不是。
   要求 `峰值 ≥ 2.0σ`。慢摆 0.7Hz/300mg → **0 步**。
3. **节律门（时间窗方差判据）**：这是你要的"简单有效的周期性判据"。
   维护最近 N 个步间隔，算变异系数 `CV = σ/mean`，要求 **CV ≤ 0.26**：
   - 真走路步间隔 CV 通常 3–15%
   - 打字/乱动 CV 通常 >40%
   攒够 `commit_after=3` 个间隔才把 pending 步数落账（Pebble 用 5s epoch +
   FFT 做同类判断，本方案用时间域等价物，省掉 FFT）。

实测：打字/小幅乱动 120s → **0 步**。

### 2.9 步长估算

```
走路：步长 = 0.43 × 身高                       (100 步/分 名义值)
      + 步频自适调：(步频−100) × 身高 / 400   (60–160 步/分)
跑步：步长 = 0.95 × 身高
```

**系数出处与冲突**：
- `0.413`（女）/ `0.415`（男）× 身高 —— 最广为流传，源自 Pearson 1899
  人体测量 + Williams 1980 / Cavanagh & Kram 1989 转引，被 ACSM 走路方程采用。
- `0.43 × 身高`（走）/ `0.95 × 身高`（跑） —— Hoogeveen et al. 2000 一类
  "步长 ≈ k × 身高" 的简化式。
- **建议取 0.43**：0.413–0.415 偏小（实测人群多在 0.41–0.45），
  且 0.43 更好记。**但个体差异可达 ±15%**，想要准就做一次标定：
  走已知距离（如 100 m）数步数 → 步长 = 距离 / 步数 → 直接写进配置覆盖。

### 2.10 卡路里

```
活动热量[kcal] = 步长[cm] × 步数 × 体重[kg] × 系数 / 100000
系数：走路 0.5，跑步 1.0   （单位 kcal/(kg·km)）
```

**出处**：ACSM 代谢方程（平路、无坡度）化简后的近似 ——
走路 ≈ 0.5 kcal/kg/km，跑步 ≈ 1.0 kcal/kg/km；
等价于常见的 `0.0005 kcal/(kg·m)` 经验式。

**注意**：
- 这是**活动净消耗**，不含基础代谢。日总消耗要另加 BMR
  （Mifflin-St Jeor：男 `10W + 6.25H − 5A + 5`，女 `−161`）。
- 想要更细，可按步频分档取 MET（Tudor-Locke 2018/2019/2020：
  **100 步/分 ≈ 3 MET，130 步/分 ≈ 6 MET**），
  再用 `kcal = (MET − 1) × 体重 × 时长[h]` 算净消耗。
  步频分档还能顺便区分走/跑，比单一步长系数更合理。

## 三、定点实现建议

### 3.1 用 float 还是 Q 格式？

**热路径用定点，初始化/标定用 float。** ESP32-S3 有单精度 FPU，
但 50Hz 下每样本只有 20ms 预算，定点更可控且便于移植：

- 信号：**Q10**（1 LSB = 0.98 mg，计步门限 30–600 mg，分辨率绰绰有余）
- 滤波系数：**Q15**，乘法后 `>>15`
- 方差：**Q20**（Q10 平方会丢精度，见 2.5）
- 累加器：**int64**（虽然 int32 够用，但 int64 免去溢出分析）
- 卡路里：**毫千卡（整数）**，避免浮点
- 量程换算（raw→mg）用 float 也行（每次初始化做一次）

### 3.2 采样率 50Hz 够不够？

**够，而且推荐。** 依据：

- 步态冲击能量集中在 **1–4 Hz**，50Hz 给出 25Hz Nyquist，余量 6 倍以上
- Pebble 用 **25Hz** 都能工作；theozmz 用 50Hz；Oxford 用 12.5Hz
- 50Hz 下 3.5Hz 上限留了足够过渡带，滤波器容易做
- 更高采样率的好处主要是**峰值时刻的时间分辨率**（步间隔精度），
  但计步只关心间隔，50Hz 的 20ms 量化误差对 CV 判断无影响

**建议**：芯片配 250Hz（仅加速度模式，aODR=0101），
软件做 5:1 抽取到 50Hz（顺便得到抗混叠低通），
或者干脆芯片配 125Hz（aODR=0110）再抽取到 ~50Hz。
> 抽取比直接配低 ODR 更好：低 ODR 档位（62.5Hz 以下）噪声性能会下降。

### 3.3 算力实测

主机侧 **0.2–0.6 µs/样本**。按 50Hz 折算，
即使在 ESP32-S3 上慢 10 倍也只有约 0.03% 的单核占用。
`sizeof(step_counter_t) = 272 字节`，可静态分配，不需要 PSRAM。

### 3.4 8MB PSRAM 怎么用

计步本身用不上。真正值得用 PSRAM 的是**原始数据记录**（调参必备，
见第四节）和后续的 ML 计步模型。

## 四、📌 哪些是通用推荐值，哪些必须实测调整

### 4.2 必须上板实测调整（我给的只是起点）

| 参数 | 当前值 | 影响 | 调整方向 |
|---|---|---|---|
| `peak_thresh_mg` | 60 | 绝对地板 | 静止时看串口 `bp` 噪声峰峰值，取 3–5 倍 |
| `start_thresh_mg` | 60 | 进入门限 | 同上 |
| `end_thresh_mg` | 25 | 退出门限（滞回） | 取其 40% 左右 |
| `crest_min_x100` | 200 | 冲击 vs 平滑 | 误计多→调高；漏计→调低 |
| `rhythm_cv_x1000` | 260 | 节律严格度 | 误计多→调低到 200；漏计→调到 350 |
| `commit_after` | 3 | 起步丢几步 | 走走停停场景漏计多→调到 2 |
| `refractory_ms` / `_pct` | 250 / 35% | 防重复计步 | 步数≈2倍→调高到 45–50% |
| `user_height_cm` / `weight_kg` | 170 / 65 | 距离&卡路里 | **必须填真实值** |
| 步长系数 0.43 / 0.95 | — | 距离精度 | 做一次已知距离标定覆盖 |

### 4.3 怎么用串口调阈值（具体步骤）

代码里已经把内部信号暴露成遥测字段，直接打印即可：

```c
/* 在 50Hz 任务里，每 100ms 打一行（波特率 921600 或 2000000） */
printf("%u,%d,%d,%d,%d,%u\r\n",
       now_ms,
       sc.ac_dbg * 1000 / 1024,   /* 去重力后信号 (mg) */
       sc.bp_dbg * 1000 / 1024,   /* 带通输出 (mg)     */
       sc.thr_dbg * 1000 / 1024,  /* 当前门限 (mg)     */
       sc.st.cadence_spm,
       (unsigned)sc.st.steps);
```

**调参流程**：

1. **静止基线**：戴好不动 60s，看 `bp` 的峰峰值。
   目标：`peak_thresh_mg` 取该峰峰值的 3–5 倍（通常落在 40–80 mg）。
   若 >100 mg，说明腕带太松或噪声过大，先解决硬件。
2. **正常走路**：手动数 100 步，同时录像/记时间。走完看 `steps`。
   - 偏少 → 降 `crest_min_x100`（200→150）或降 `rhythm_cv_x1000` 的严格度
   - 偏多（≈2 倍）→ 升 `refractory_pct`（35→45）
   - 起步丢步 → 降 `commit_after`（3→2）
3. **误计测试**（每一项单独测 2 分钟）：
   - 坐着打字 → 应 0 步
   - 坐车/地铁 → 应 0 步（若不为 0，升 `peak_thresh_mg` 和 `crest_min_x100`）
   - 挥手/拍手 → 应 0 步
   - 洗脸/刷牙 → 通常最容易误计，若误计升 `rhythm_cv_x1000` 严格度
4. **格点搜索（最靠谱）**：按 Oxford 项目推荐做法——
   采集多段原始数据（不同速度/路面/佩戴松紧）存 CSV（PSRAM 这时候有用），
   用 `(time_ms, ax, ay, az)` 格式落盘，
   离线格点搜索 `{window, threshold, refractory}` 三个参数，
   选与人工真值误差最小的组合。
   Oxford 提供的工具：`github.com/MarcusNordstrom/C-optimize-variables`

### 4.5 当前实测结果（诚实说明）

主机侧合成信号（`test_imu_host.c`，8 项全通过）：

| 场景 | 期望 | 实测 | 结果 |
|---|---|---|---|
| 走路 110 步/分 60s | 110 | 103 | −6% ✅ |
| 走路 105 步/分 10s（冷启动） | 17 | 12 | 起步丢步 ✅ |
| 2×30s 走路 + 中间休息 10s | 110 | 89 | **−19%** ⚠️ |
| 坐车 15Hz 振动 120s | 0 | 0 | ✅ |
| 机器 9Hz 振动 120s | 0 | 0 | ✅ |
| 打字/小幅乱动 120s | 0 | 0 | ✅ |
| 静止 60s | 0 | 0 | ✅ |
| 慢摆 0.7Hz 300mg 60s | 0 | 0 | ✅ |

**⚠️ 必须说清楚的局限**：

1. 这些数字来自**合成信号**，不是真实腕部数据。合成模型里"足部冲击在
   合矢量模长上占主导"是假设；真实腕部这个假设基本成立，但冲击/摆动
   比值因人而异。**上板实测前不要相信 ±6% 这个数字。**
2. **走走停停场景会系统性少计**（实测 −19%）。原因是节律门要求攒够
   `commit_after` 个间隔才落账，每段走路的**开头 ~3 步会被丢掉**。
   这是刻意的取舍（宁可少计也不要误计），修正办法是降 `commit_after`，
   代价是误计风险上升。
3. **跑步（165 步/分）当前测试未通过**（合成信号下严重少计）。
   原因：该信号模型下高频谐波被 3.5Hz 上沿衰减，残余能量不足以过门限。
   真实跑步的冲击幅度远大于走路，大概率没这么糟，但**必须实测确认**；
   若确实漏计，把带通高端从 3.5Hz 提到 5Hz，并降 `crest_min_x100`。
4. 未验证：极慢走（<70 步/分）、上楼、手插口袋、拄拐、轮椅推行。
5. 未使用片内计步器（CTRL9 命令 `0x0D` + 0x5A–0x5C 步数寄存器）。
   它可用作**交叉校验源**（两个独立估计做一致性检查），
   或直接省掉全部软件算法——但片内算法参数不可见、无法针对腕部调整，
   建议先用本文方案掌握主动权。
