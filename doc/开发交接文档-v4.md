## 〇、先看这四件事（否则容易白干一天）

1. **`watch_ui` 组件绝对不能 include ESP-IDF 头文件** —— 因为 PC 模拟器也要编译它。
   需要平台能力（背光/NVS/时间/蜂鸣器/WiFi/天气）一律走 `watch_platform.h` 的**钩子**。
   这是全项目最重要的一条架构约束，破坏了模拟器就废了（见 §3.3）。
2. **改 `sdkconfig.defaults` 之后必须 `clean` 重编**，否则不生效；改完要去**生成的
   `sdkconfig`** 里确认真的改了（§7.2）。
3. **实机验证只能由人来点**（触摸手感、颜色、观感）。自动化能覆盖的部分已经做到：
   **PC 模拟器 + 10 段自检**（§6）。**提交前必须让自检 0 失败**，它是这个项目唯一的安全网。
4. **中文字是"按需抽字"的**：源码里写了新汉字，必须登记 + 重生成字库，
   否则屏幕上就是豆腐块。**注释里的中文也会被扫描**（§4.2 有完整流水线）。

### 1.3 怎么判断"跑起来了"

串口（**USB-Serial-JTAG，不是 UART0**）应当看到类似（**实测 v0.7.0 启动到可用约 2.3 秒**）：

```
I (354)  APP: ================ 智能手表 v0.7.0 启动 ================
I (879)  APP: 板级就绪：ESP32-S3 target，屏幕 240x280
I (879)  APP: I2C 器件自检：触摸(0x15)=在 IMU(0x6B)=在 RTC(0x51)=在
I (913)  POWER: 电源管理就绪（自动息屏 120 秒，只关背光不做低功耗）
I (1824) WATCH_UI: 轮播就绪：5 页，当前 [0] 'home'（跟手滑动，阈值 60px）
I (1930) WEATHER: 天气服务就绪（缓存 无）
I (2185) APP: 背光淡入完成（78%）
watch>                                        ← 命令行提示符
I (2487) APP: ================ 初始化完成 ================
I (2487) APP: 操作：右滑翻页 / 左滑返回 / 上滑控制中心
```

**屏幕表现**：上电先黑屏（故意的），界面装好后**背光淡入约 300ms**。
若一直黑屏但串口有日志 → 背光/初始化顺序的问题；若串口无输出 → 线或端口选错
（本板有两个 COM 口，认 USB-Serial-JTAG 那个）。

**自检关键行**：`I2C 器件自检：触摸(0x15)=在 IMU(0x6B)=在 RTC(0x51)=在`
—— 三个传感器任一显示"**不在**"就是硬件/接线问题，不是软件。

### 1.4 ⚠️ 两个必须知道的硬件行为

1. **打开串口会让芯片复位**（`rst:0x15 (USB_UART_CHIP_RESET)`）。
   所以任何"打开串口 → 发命令"的脚本都要**先等 5 秒**再发，否则命令会丢在启动过程里。
   `tools/serial_cmd.py` 已经处理了这件事（它不靠提示符同步，靠固定等待 + 全量回读）。

2. **RTC 没有备份电池**，断电就丢时间。开机日志会显示"时间未校准"，
   必须靠 WiFi SNTP 校时或手动校时页。界面上显示"未校准"是**故意的**：
   宁可说不知道，也不要显示一个错的时间。

### 2.1 这是什么

一块**自己写的触摸智能手表固件**：ESP32-S3 + 240×280 圆角屏，跑 ESP-IDF + LVGL 8.4。

| 项 | 参数 | 备注 |
|---|---|---|

| 串口 | **USB-Serial-JTAG**（Type-C 直连 S3 原生 USB） | UART0 只引到扩展口，别指望它 |

| 名称 | 偏移 | 大小 | 用途 |

## 三、架构

### 3.1 分层与依赖方向（**最重要的规则**）

```
        ┌─────────────── app（启动装配、串口命令行）───────────────┐
        │                                                          │
   watch_ui_pages ──► watch_ui ──► (平台钩子) ◄── 各服务组件
   （具体页面/游戏）   （框架：页面宿主、模态、控件、手势、样式）    data_hub / settings /
        │                  │                                      wifi_service / motion /
        └──► watch_strings │                                      watch_clock / power /
                           └──► LVGL（lv_*）+ 自己的 watch_gfx     buzzer / imu_logger / weather
                                     ▲
                            ui_port（LVGL 锁与任务；两份实现：设备/PC 模拟器）
```

**铁律（破坏任何一条都会付出代价）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **`watch_ui` 不许 include ESP-IDF 头文件**（`esp_*.h`、`freertos/*`、`driver/*`） | PC 模拟器要编译它；一旦引入 IDF，模拟器直接编不过 |
| 2 | **`watch_ui` 不许 include `watch_ui_pages`** | 依赖必须单向：页面依赖框架，反之不行 |
| 3 | 平台能力**只经 `watch_platform.h` 的钩子**进入 UI 层 | 设备侧由 `app.c` 装配真实实现；模拟器侧有桩实现 |
| 4 | LVGL 的调用必须**持有 `ui_port_lock()`** | LVGL 不是线程安全的；`esp_lvgl_port` 在设备侧提供锁 |
| 5 | 数据只有**一个来源**：`data_hub` | 以前各页面自己读传感器 → 数据不一致、重复采样 |
| 6 | **服务组件不许依赖 `app`**（会成环） | 需要 app 提供的东西时用 **weak 符号**（见 §4.9） |

### 3.3 平台能力靠"钩子"注入（关键设计）

UI 层不认识硬件。它要什么能力，就在 `watch_platform.h` 里定一个钩子，由 `app.c` 装配：

```c
/* 设备侧（components/app/app.c）—— 接真实实现 */
w_platform_set_time_hooks(&s_time_hooks);       /* → RTC / watch_clock */
w_platform_set_buzzer_hooks(&s_buzzer_hooks);   /* → buzzer */
w_platform_set_rec_hooks(&s_rec_hooks);         /* → imu_logger */
w_platform_set_wifi_hooks(wifi_service_get_hooks());   /* → wifi_service */
w_platform_set_weather_hooks(&s_weather_hooks);        /* → weather（v0.7.0）*/
watch_ui_set_brightness_hooks(brightness_get, brightness_set);  /* → power */
watch_ui_set_setting_hooks(setting_get, setting_set);          /* → settings */
```

**要加新能力时的顺序（四步，别跳）**：
① 在 `watch_platform.h` 加钩子结构体与 setter →
② 模拟器 `sim_main.c` 写**语义一致的桩**（见 §8 的教训 23）→
③ `app.c` 装配真实实现（注意结构体字段转换，别用指针强转）→
④ 页面里用（**必须判空**：钩子为空时要显示"不可用"，不是空白页）。

## 四、几个容易搞错的子系统

### 4.1 时间语义（★ 踩过两个大坑）

* **RTC 没有备份电池** → 断电后时间无效，必须靠 WiFi SNTP 或手动校时页。
* 界面显示"未校准"是**故意的**：宁可说不知道，也不要显示一个错的时间。
* **时区**：RTC 存本地时间；SNTP 回来后按 `W_SETTING_TZ` 换算（+8 区 = 32，单位 15 分钟）。
* ⚠️ **`watch_clock.c` 的一处"注释与实现相反"是有意保留的**：
  闹钟"设到当前这一分钟"会**立刻响**（`s_al_fired_hhmm = -1`），而注释写着"等下一分钟"。
  既有自检**断言的就是"立刻响"**。这是一个**行为选择，不是 bug** —— 要改先确认用户想要哪种。
* **界面层不能用 `time()/localtime()`**（不许 include IDF 头）。
  要本地日期就自己从 `watch_ui_current_epoch()` 算日历 ——
  `watch_page_calendar.c` 和 `weather_service.c` 里各有一份实现（**改一处要想着另一处**）。

### 4.2 中文字库流水线（★ 最容易漏字）

LVGL 用子集字库（不是全字库），**没登记的字会显示成豆腐块**。

```
① 中文只写在 components/watch_ui_pages/include/watch_strings.h（集中登记）
   —— 只出现在日志/命令行里的字，写进 W_STR_FONT_EXTRA
② 跑生成脚本：powershell -ExecutionPolicy Bypass -File .\tools\gen_font.ps1 -Force
   （**必须带 -Force**，否则静默跳过）
③ 跑三条校验（**必须带 PYTHONUTF8=1**，否则 GBK 控制台打印 ✓ 会报错退出 1）：
   python tools\check_all_literals.py     # 所有字面量都在字库里？
   python tools\check_fonts.py            # ASCII 字体配中文文案的低级错误？
   python tools\check_glyphs.py --all     # 三套字库逐码点核对
```

**当前状态**：字面量 569 个非 ASCII 字符 / 字库覆盖 **851 个码点**（其中汉字 744），
三套字号 14/16/20。

**⚠️ 三个容易踩的点**（都是 v0.7.0 亲自踩的）：
1. **注释里的中文也会被扫描** —— 生成脚本扫的是"所有非 ASCII **字符串字面量**"，
   所以日志里的中文也必须登记，不如校验就红。
2. **`check_glyphs.py` 才是可信的**：它解析 `cmaps[]` + `unicode_list` 结构。
   **不要在字库文件里 grep `0x6674` 这种绝对码点** —— LVGL 用 SPARSE_TINY 存的是
   **相对 range_start 的偏移**，grep 不到不代表没收录（我因此误判过一次）。
3. **改完文案要重新生成字库**，否则新加的字仍然是豆腐块（模拟器截图能立刻看出来）。

### 4.3 手势与翻页（★ 改之前必须懂 LVGL 行为）

* 轮播是**手写的跟手滚动 + 吸附 + 橡皮筋**（不是 LVGL 的 scroll）。
* ⚠️ **手写滚动的代价**：LVGL 不知道"发生了滚动"，它"滚动就不发点击"的机制失效 →
  v0.6.0 用户实测"列表滑动后误进了选项"。修法见 `watch_widgets.h` 的"拖动/点击判定"。
  **凡是自造的可点行，回调开头都要 `if (w_touch_was_drag()) return;`**。
* 功能列表页（v0.6.1 起）：**5 行一屏放下，不再滚动**，因此该页上滑能开控制中心。
  自检里有断言守着（"可滚 0 px"+"末行完整在屏内"），**改行高会让自检立刻报警**。
* 加新页面**不要塞进功能列表页**（它已 5 行占满 251/256px）—— 加第 6 行需要 269px 会溢出。
  v0.7.0 的做法是**新开一页**（工具页），理由写在 `watch_page_tools.c` 文件头。

### 4.4 计步算法（★ 参数是实测标定的）

* 定点算法 + 阈值在 `motion.c`，**步长是固定值**（走路 50cm / 跑步 90cm，按用户要求）。
* 采样 50Hz；传感器配 ±8g + 62.5Hz ODR + LPF。
* 调参流程：设备 `rec start` → 走 50 步 → `rec stop` →
  `serial_cmd.py "rec get /spiffs/imu_0001.bin"` 导出 →
  `tools/step_tune.py` / `step_search.py` / `step_eval.py` 离线评估。
* 实测过一组：50 步 → 51 步（+2%）、静止 12 秒 0 误计。**跨步频/跑步/上下楼还没验**。

### 4.5 WiFi 与校时（★ 坑最多，两轮修复都在这里）

**调用路径**：WiFi 页 → `wifi_hooks_t` → `wifi_service` → ESP-IDF WiFi 驱动 + SNTP。

**调用者分类（★ v0.7.0 新增的关键约定）**：

| 入口 | 密码来源 | 认证失败时 |
|---|---|---|
| 界面点网络 / `wifi connect` | 用户刚输入 | **不清凭据**（用户想改密码时正好走这条路） |
| 开机自动重连 | NVS 存储 | **清凭据**（这份密码用户没重输过，失效就该问） |

靠 `hook_connect_ex(ssid, pass, from_stored)` 的第三个参数区分。
`from_stored` 由调用方给，**不能自己推断**（第一版靠"密码是不是从 NVS 回填的"推断，
而开机路径是把密码当参数传的 → 恒为 false → 那条路永远不自愈）。

**已修的四个 bug（都是真机实测出来的）**：

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 连不上时**界面不报错、反复重试、永远不重新问密码** | `hook_connect()` **无条件**置 `s_user_disconnect=true`，指望断开事件消费它；但**断开空闲站点根本不会产生事件** → 标志残留 → 真正认证失败被误判成"用户主动断开" | 加 `disconnect_event_expected()`；等完 2 秒窗口**强制清掉** |
| 2 | 排查时发现：**密码打错也会被写进 NVS**，把能用的顶掉 | 在"配置刚写进驱动"时就 `creds_save()` | 改成**两段式**：`STA_CONNECTED`（关联 + 4 次握手过了 = 密码对）才落盘 |
| 3 | **开机自动重连永远不自愈** | 见上表 `from_stored` 的说明 | 加显式参数 |
| 4 | **扩多槽位会让"一次失败清光全部网络"** | `creds_erase()` 用的是 `nvs_erase_all` | 拆成三种粒度：按 SSID 删 / 按槽删 / 清全部（见下） |

**凭据存储**（v0.7.0 从单槽位扩成 5 槽位）：

| 键 | 含义 |
|---|---|
| `ssid` / `pass` | **旧键，保留**（迁移来源，首启自动拷进槽 1，`slot_cnt` 兼作迁移标志） |
| `ssid1..ssid5` / `pass1..pass5` | 新槽位 |
| `slot_cnt` (u8) / `last_ok` (u8) | 槽位计数 / 上次连上的槽（开机优先试它） |

三个删除粒度（**别混用**）：
`creds_erase_ssid(ssid)` 只删一个网（认证失败自愈、`hook_forget`）｜
`creds_erase_all_slots()` 删全部但保留计数（用户主动"重置 WiFi"）｜
`creds_save()` 同名更新 → 占空槽 → 满则覆盖非 `last_ok` 的槽。

**其它必须知道的**：
* `reason` 码要会读：**2 = AUTH_EXPIRE**、15 = 四次握手超时（密码错典型）、
  201 = 找不到 AP、203 = 关联失败、211 = 加密方式不兼容。
  `reason_is_auth()` 决定"要不要清凭据"——**201（没信号）不清**，否则出趟门回来密码就没了。
* 连 WPA2/WPA3 过渡模式（`authmode=7`）的 AP：已设好 `pmf_cfg.capable=true/required=false`、
  `sae_pwe_h2e=BOTH`、`threshold.authmode=OPEN`（**不要再"优化"这几项**，注释里写了为什么）。
* **开机自动连接默认关闭**（v0.7.0 按用户要求改成设置项 `wifi_auto`，默认 0）。
  理由：以前开机就拿存着的凭据去连，AP 不在时会一直卡"连接中"，既不报错也没法退出。
  想恢复旧行为就把 `wifi_auto` 置 1。
* 串口排查很方便：`wifi status` / `wifi scan` / `wifi connect <SSID> [密码]` /
  `wifi disconnect` / `wifi forget` / `wifi reset` / `wifi sync`。
  连接日志会打印**密码字节码**（查"末尾多了个不可见字符"用，历史上真踩过）。

### 4.6 息屏与唤醒（★ v0.6.1 才真正做到"第一下不误触"）

* 息屏 = **只关背光**（CPU、LVGL、IMU 采样照跑）。真正的低功耗在 v0.7.1。
* "熄灭后第一下触摸只负责亮屏、不穿透到界面"的实现：
  `w_screen_notify_activity()` 发现"刚才屏是灭的" → 置 `s_swallow_touch` →
  `bsp.c` 的触摸回调这一次上报 `LV_INDEV_STATE_RELEASED` → 抬手时清标志。
  ⚠️ **不能**用 `lv_indev_enable(false)` 事后禁用：LVGL 在**调用读回调之前**就检查了
  enable 状态，来不及。

### 4.7 多任务铁律（★ 血泪）

| 任务 | 干什么 | 栈（实测余量，v0.7.0） |
|---|---|---|
| `taskLVGL` | LVGL 主循环 + 界面回调 | 6144（余 3296） |
| `data_hub` | 周期采样设备状态 | **4096**（余 2048） |
| `motion` | IMU 采样 + 计步 | 4096（余 2048） |
| `settings_ev` | 订阅"设置变了" → 刷界面 | 3072（余 **1032**，**最紧的非系统任务**） |
| `console_repl` | 串口命令行 | 6144（余 3808） |
| `weather` | HTTP 拉取 + JSON（**只有抓取时才存在**） | 6144 |
| `wifi` / `tiT` | IDF 内部 | — |

**规则**：
1. **碰 `lv_*` 必须持锁**（`ui_port_lock/UINT32_MAX`），并且**不许在持锁时做阻塞操作**
   （NVS 写、网络、长延时）。
2. 跨任务共享的简单状态（标志、计数）用 `ui_port_critical_enter/exit()` 保护。
3. **回调里给出去的数据必须是副本**，不能给内部活指针（`data_hub` 的快照）。
4. **跑在别的任务里的服务不要碰 LVGL** —— 要更新界面就置个标志、让页面的 `lv_timer`
   轮询（WiFi 页、时钟页、天气页都是这个模式）。
5. 卡死了先跑 `taskmem`（看栈）+ `bt`（看所有任务调用栈）。

### 4.8 通用 toast 提示条（v0.7.0 新增）

* 挂 **`lv_layer_top()`**，不占模态栈、高于挂在 screen 上的模态。
* ⚠️ **建完容器后必须清掉自己的 `CLICKABLE`/`CLICK_FOCUSABLE`**。
  项目里曾流传"`lv_layer_top()` 一旦可点击就会吞掉整屏触摸"——**那句归因是错的**：
  `lv_hal_disp.c:225-230` 里 LVGL 自己就清了 top_layer 的 CLICKABLE；
  真正吞触摸的是**建在它上面的默认尺寸子容器**（`lv_obj_create(NULL)` 默认满屏 + 可点击）。
* **对象常驻、永不删除**（单例 + 显式状态机 `IDLE/SHOWING/HOLDING/HIDING`）。
  这是刻意的：参考工程的提示条"每次新建对象、离场 `ready_cb` 里删"，
  于是**滑出那 200ms 内再来一条提示会丢**。
* 闹钟/倒计时提醒层可见时 **toast 直接丢弃**（不排队）——别去挡提醒层的"停止"按钮。
* API：`watch_toast_show(text)` / `watch_toast_show_fmt(fmt,...)`，**调用者要持 UI 锁**。

### 4.9 服务组件怎么拿 app 层的东西（★ weak 符号）

`weather_service.c` 要读"时区和经纬度存哪"，但那是 app 层才知道的事；
而 `app` 已经依赖 `weather` → **会成环**，直接报 `undefined reference`。

**做法**：服务里给 **weak 默认实现**，app 层提供同名**强符号**在链接时覆盖：

```c
/* weather_service.c —— 弱默认（上海） */
__attribute__((weak)) int32_t weather_tz_unit(void) { return 32; }
__attribute__((weak)) bool weather_get_coords(int32_t *lat, int32_t *lon) { ... }
/* components/app/weather_port.c —— 强符号，读 settings */
int32_t weather_tz_unit(void) { return settings_get(SETTINGS_TIMEZONE, ...); }
```

两头都自洽：单编 `weather` 组件能过，整机用 app 的版本。
以后再有"服务需要 app 提供配置"的场景，照这个模式。

### 4.10 天气（v0.7.0 新增）

* 数据源：`http://api.open-meteo.com/v1/forecast`（**明文 http**，省掉证书包），
  取 `daily=weathercode,temperature_2m_max,temperature_2m_min&forecast_days=7`。
* **开机不联网**，先渲染 NVS 缓存；联网是用户点【获取天气】才发生。
* 缓存键：`wx_d0_mmdd..wx_d6_mmdd` / `_code` / `_max` / `_min` + `wx_fetched` + `wx_count`。
  **过期判定用 `wx_fetched`**，不用 "MM/DD" 字符串比较（那个跨月会算错）。
* **四个数组长度必须一致才采信**，否则丢弃本次结果 ——
  参考工程按 time 的长度循环，缺的字段取到 0，而 0 在 WMO 里是"晴"，
  于是缺数据的日子**静默显示成大晴天**。
* 图标是**界面层用图元自绘的**（7 类：晴/多云/阴/雾/雨/雪/雷），不引任何位图。
* 经纬度用**整数微度**（1e-5 度，上海 = 3123000 / 12147000），因为界面层设置钩子签名是 `int`。
* 界面层的微度⇄文本换算和 `weather_service.c` 里各有一份（**改一处要想着另一处**）。

## 六、PC 模拟器与冒烟自检（**改 UI 强烈建议用**）

**位置**：`lvgl_sim/`（在仓库外！见 §10 的"仓库边界"）

```powershell
cd lvgl_sim
mingw32-make -j8                            # 编译（几秒）
.\lvgl_sim.exe                              # 手动点着玩（能看界面、能点）
$env:SIM_SELFTEST='1'; .\lvgl_sim.exe       # 跑自检：**退出码 = 失败项数**（0 = 全过）
```

* 模拟器用**同一份界面源码**（`watch_ui` / `watch_ui_pages` / `fonts`，Makefile 里列了 38 个

  数对象/定时器（`sim_obj_count` / `sim_timer_count`）、模拟触摸、截图（`sim_shot`）。
* **⚠️ 模拟器和设备不是同一份 LVGL**：模拟器用 `lvgl_sim/third_party/lvgl`（**8.3**），
  设备用 `components/lvgl`（**8.4**）。已知差异：
  `lv_calendar_header_dropdown_set_year_list()` 是 8.4 才有的 →
  **日历的年份下拉在模拟器上会显示 1901（属预期），设备上是 2026**。
  源码里用 `LVGL_VERSION_MINOR` 守卫，两边都能编。
* **它抓到过的真 bug**（都是改这一版时抓到的）：
  WiFi 页定时器 use-after-free（去掉修复直接段错误）、息屏穿透失效、
  功能列表内容溢出、游戏对象泄漏、toast 药丸被压成竖条、计算器键盘整块不渲染、
  位移动画被布局覆盖。
* ⚠️ **写桩实现要和实机语义一致**：模拟器的 `sim_screen_activity()` 曾经是**空函数**，
  于是"息屏→触摸→亮屏"这条路根本走不到，那个 bug 也就测不出来（§8 教训 23）。
  同理天气桩给了**真实的 7 天数据**，否则"有数据"那条渲染路径走不到。
* 截图可直接进文档（注意模拟器出的 PNG 是 stored-deflate，约 197KB，
  要用 Pillow 重新编码 + 64 色调色板压到几 KB，仓库里 10 张图合计约 35KB）。

## 七、开发工作流

### 7.1 固定流程（已形成肌肉记忆）

```
① 想清楚要改什么（涉及架构 → 先写实施文档，见 doc/智能手表-B批实施文档.md 的写法）
② 改代码（一次只做一个主题）
③ 编过：.\build.ps1 build         → 0 error（警告也要看，第三方 deprecation 除外）
④ 模拟器自检：SIM_SELFTEST=1      → 退出码 0（**必须**）
⑤ 涉及中文 → 跑 §4.2 的三条校验 + 必要时重新生成字库
⑥ 看一眼模拟器截图（豆腐块/挤压/错位只有画面能发现）
⑦ 实机：烧录 → 按"验收清单"逐条让使用者确认（手感/颜色/观感只能人验）
⑧ 写 doc/version/vX.Y.Z.md（最后一节必须是「本版本改动简单说明」）+ 更新版本号三处
```

**版本号三处**（缺一不可）：
1. `components/app/app.c` 的 `APP_VERSION_STR`
2. `components/watch_ui_pages/pages/watch_page_settings.c` 的 `WATCH_FIRMWARE_VERSION`
3. `doc/version/README.md` 的版本列表

### 7.2 配置类改动的三个坑

1. **改 `sdkconfig.defaults` 不 clean 不生效** —— 而且是"部分生效"，最难查。
2. 改完要去**生成的 `sdkconfig`** 里确认真生效了（例如 `grep WPA3_SAE sdkconfig`）。
3. **编译器优化等级会暴露老代码问题**：v0.6.1 从 `-Og` 提到 `-O2` 后立刻 3 处 `-Werror`
   （`strncpy` 不补 `\0` 等）—— **都是真问题**。所以本工程现在是 `-O2`，警告不要随手关。

### 7.3 绝对不要做的事

| 不要 | 原因 |
|---|---|
| **不要用 shell（`Set-Content`/重定向）回写源码文件** | 本工程被这样毁过两次：PowerShell 5.1 把 UTF-8 写成 ANSI；`-NoNewline` 把整个文件压成一行 |
| 不要在 `watch_ui` 里 include IDF 头文件 | 见 §0/§3.1 |
| 不要在持 LVGL 锁时做阻塞操作（NVS/网络/长延时） | 会卡住整个 UI |
| 不要在事件回调里删**祖先**对象 | 读已释放内存（§8 教训 20） |
| 不要在**同一棵对象树**上排两个 `lv_async_call` 删除 | 顺序不保证，会崩 |
| 不要"想当然"用 LVGL API | 多条坑都出在这（`lv_btnmatrix_set_map` 只存指针、行分隔符必须是单独的 `"\n"` 元素、画布调色板在缓冲区头 16 字节、模态内容区高度不确定…）；**先翻源码** |
| 不要用 `nvs_erase_all` 清"一个网络" | 会连别的一起删（§4.5） |

## 九、常见任务怎么做

| 任务 | 步骤 |
|---|---|
| **加一个设置项** | ① `settings.h` 的枚举**加在末尾**（`SETTINGS_BIT` 掩码按枚举值算）② `settings.c` 的 `s_desc[]` 加一行（NVS 键名 / 默认值 / 范围 / 中文说明）③ 界面要按名字访问就 `watch_pages.h` 加 `W_SETTING_XXX` + `app.c` 加一行映射 ④ 页面里 `watch_ui_setting_get/set` |
| **加一个页面** | ① `watch_ui_pages/pages/` 新建 `watch_page_xxx.c` ② 实现 `watch_page_t`（build/refresh/delete）③ 注册进 `watch_pages_all()`（**数组顺序 = 轮播顺序**）④ **三处构建文件都要加**：`watch_ui_pages/CMakeLists.txt` 的 SRCS、`lvgl_sim/Makefile` 的源文件列表 |
| **加一个子页面（模态）** | `w_modal_open(...)`；**最大深度 4**；关闭用 `w_modal_close()`。⚠️ 两个高度坑：**内容区可用高度只有 222**（`280 − 2×12 − TITLE_H(34)`），而且 body 自身高度不确定 → **控件高度必须写死**，别用百分比/flex_grow |
| **加一个硬件驱动** | ① `board.h` 加引脚/地址 ② `bsp.c` 或新组件里初始化 ③ 需要给 UI 用 → 走 §3.3 的四步钩子 |
| **加中文文案** | 写进 `watch_strings.h` → `gen_font.ps1 -Force` → 三条校验（§4.2） |
| **加第二款游戏** | 写一个文件实现 `w_game_t` + 在 `k_games[]` 注册一行（宿主层已通用：暂停/结算/防息屏/闹钟暂停）；要存最高分就加一个 `W_SETTING_*` + app.c 一行映射 |
| **调计步参数** | §4.4 的三件套流程 |
| **改 UI 观感** | 在模拟器里改（几秒见效），改完跑自检 + **看截图**，再烧实机确认手感 |
| **加一条串口命令** | `app_console.c` 的 `s_cmds[]` 加一行；中文输出要登记字库 |

  **实机侧（烧录、触摸手感、颜色观感、最终确认）只能人做** —— 所以实机验收清单要写细。
* **提交习惯**：一个版本一次提交，提交信息 `x.y.z`（如 `0.7.0`）。
  ⚠️ 当前工作区**有大量未提交改动**（v0.7.0 整批），接手前建议先提交一次。
* **文档习惯**：每个版本必须有 `doc/version/vX.Y.Z.md`，最后一节是「本版本改动简单说明」。
* **不确定就不要写成结论**：报告里把"已证实的"和"最可能的解释"分开写。
