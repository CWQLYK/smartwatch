## 〇、一分钟结论

**先在这里找答案，再回我们这边落地。**
它回答的是"**这件事在这个芯片+这块屏上到底能不能做、大致怎么做**"；
我们这边要回答的是"**在我们这套分层和约束下怎么做得干净**"。

**抄三样**：思路 / 结构 / 参数（时序、缓冲区、超时、阈值）。
**绝不抄三样**：引脚定义 / 工程组织方式 / LVGL 配置方式（因为这三样两边完全不同，见 §一）。

## 一、先搞清楚差异：**照抄就错的六件事**

### 1.1 硬件根本不是同一块板（**最容易致命**）

| 功能 | 参考工程 | **我们（Waveshare ESP32-S3-Touch-LCD-1.69 V2.1）** |
|---|---|---|
| LCD SCLK / MOSI / DC / CS / RST | 12 / 13 / 14 / 10 / 11 | **看 `components/board/board.h`，别抄它的** |
| 背光 | GPIO9 | **GPIO15**（LEDC） |
| 触摸 I2C SDA / SCL / INT / RST | 3 / 4 / 2 / — | **见 board.h**（INT=GPIO14、RST=GPIO13） |
| 触摸芯片 | CST816**S** | CST816**T**（同族，寄存器/中断细节可能有别） |
| RTC | **RX8130CE** | **PCF85063ATL**（地址 0x51，寄存器完全不同） |
| 存储 | **MicroSD（SDMMC 1-bit + FATFS）** | **没有 SD 卡**（用 flash 里的 SPIFFS） |
| 音频 | **I2S + MAX98357 功放** | **只有单音蜂鸣器 GPIO42**（做不了音乐） |
| 按键 | **GPIO6/7/8 三个物理按键** | **没有按键**（全靠触摸） |
| 外设电源使能 | GPIO5（低有效） | 无此概念 |
| 充电检测 | GPIO39 | 无 |
| 显示 SPI 时钟 | **80MHz** | **40MHz** |
| IMU | 无（它不测步数） | **QMI8658C**（我们的计步靠它） |

> 👉 **凡涉及"哪个脚、哪个器件、有没有这个外设"的，一律以我们自己的 `board.h` / `bsp.c` / 原理图为准。**
> 参考工程在这方面的价值是：告诉你**这颗芯片能不能做**、**用什么外设类**，不是告诉你接哪。

### 1.2 LVGL 配置方式不同（**第二容易踩**）

| | 参考工程 | 我们 |
|---|---|---|
| 配置载体 | `main/lv_conf.h`（它自己在 sdkconfig.defaults 第 1 行就注明了） | **没有 `lv_conf.h`**！走 Kconfig：`sdkconfig.defaults` 里的 `CONFIG_LV_*` |
| 版本 | **8.3.11** | **8.4.0** |

> 👉 从它那儿抄 `#define LV_USE_XXX 1` **不会生效**。要改成我们的 `CONFIG_LV_USE_XXX=y`
> （映射关系在 LVGL 组件的 `lv_conf_kconfig.h` 里）。
> 我们已经从它那儿"翻译"过一批配置了（v0.6.1 的 A8：`LV_USE_PERF_MONITOR` 关掉、FreeRTOS 观测三件套等）。

### 1.3 工程组织不同

它是 **`main/` 一个大目录**（+ 少量组件）；我们是 **22 个自研组件的分层架构**。
👉 **学它的模块内部实现，不要学它的目录结构** —— 我们的分层是有约束的（`watch_ui` 不许碰 IDF 头文件等），照搬会破坏架构。

### 1.4 语言不同

它是 **C++**（大量 `.cpp`，还有 Arduino 兼容层 `main/compat/`）；我们是**纯 C**。
👉 抄算法/流程没问题；抄代码要"翻译"：类 → 结构体+函数、`Preferences` → 我们的 `settings`、
`String` → `char[]` + `snprintf`。

### 1.5 它的框架是手写的

它不用 `esp_lvgl_port`，而是**自己写 LVGL 移植**（`main/ui/ui_core.c`）。
👉 这其实是**优点**：它把"LVGL 底下到底在干什么"摊开给你看了（见 §四）。

### 1.6 版本与历史包袱

* IDF 5.5.**5** vs 我们 5.5.**4**；LVGL 8.3.11 vs 8.4.0 → 个别 API 有差异，**以我们编译通过为准**。
* 它是从 Arduino 分支移植来的，保留了 `slow_start_exit_flag` 这类全局变量和 compat 层 —— **学思路，别学风格**。

## 四、三个"现成答案"的完整范例（**照这个精度去读**）

### 范例 A：`wait_cb` —— 我们缺的那一块，它有完整实现

**背景**：LVGL 8.4 的 partial 双缓冲在发下一段 DMA 之前会调 `wait_cb`；
**如果没设，LVGL 就忙等空转**（`lv_refr.c` 里的 `while (disp->rendering_in_progress) {}`），白烧 CPU。

**它的做法**（`main/ui/ui_core.c`）：

```c
static SemaphoreHandle_t s_flush_sem = NULL;   /* DMA 完成信号 */

/* ① DMA 完成中断里：通知 LVGL + 给信号量 */
static void lvgl_flush_done_cb(void *user_ctx)
{
    BaseType_t hp_task_woken = pdFALSE;
    lv_disp_flush_ready(&disp_drv);
    if (s_flush_sem) xSemaphoreGiveFromISR(s_flush_sem, &hp_task_woken);
    if (hp_task_woken == pdTRUE) portYIELD_FROM_ISR();
}

/* ② wait_cb 里阻塞等待（而不是空转） */
static void my_disp_wait_cb(lv_disp_drv_t *drv)
{
    if (s_flush_sem) xSemaphoreTake(s_flush_sem, portMAX_DELAY);
}

/* ③ flush_cb 只发起异步 DMA，立即返回 */
static void my_disp_flush(lv_disp_drv_t *drv, const lv_area_t *area, lv_color_t *color_p)
{
    lcd_draw_bitmap_async(area->x1, area->y1, area->x2 + 1, area->y2 + 1, color_p);
}

/* ④ 注册 */
disp_drv.flush_cb = my_disp_flush;
disp_drv.wait_cb  = my_disp_wait_cb;
lcd_set_flush_done_cb(lvgl_flush_done_cb, NULL);
```

**怎么用到我们这儿**：我们的刷屏由 `esp_lvgl_port` 代管，所以要看**它内部有没有设 `wait_cb`**；
没有的话就是"给 `esp_lvgl_port` 打补丁或换成我们自己的移植"——这是一个**独立的小批任务**（优化清单 4.1）。

### 范例 B：`bt <任务名>` —— 我们有缺口，它有一整段

**背景**：我们的 `bt` 只能打所有任务（`esp_backtrace_print_all_tasks`），**不能指定任务**，
所以"某个任务卡住了"时输出很吵。

**它的做法**（`main/app/console.c:196-242`，完整代码见该文件，要点）：

```c
TaskHandle_t h = xTaskGetHandle(name);            /* 按名字拿句柄 */
if (h == xTaskGetCurrentTaskHandle()) {
    esp_backtrace_get_start(&fr.pc, &fr.sp, &fr.next_pc);   /* 自己：实时上下文 */
    esp_backtrace_print_from_frame(50, &fr, false);
} else {
    vTaskSuspendAll();                            /* 冻结调度，保证 TCB 一致 */
    vTaskGetSnapshot(h, &snap);
    xTaskResumeAll();
    XtExcFrame *f = (XtExcFrame *)snap.pxTopOfStack;   /* Xtensa：异常帧在任务栈顶 */
    fr.pc = f->pc; fr.sp = f->a1; fr.next_pc = f->a0;
    esp_backtrace_print_from_frame(50, &fr, false);
}
```

**怎么用到我们这儿**：把 `cmd_bt()` 扩成 `bt [任务名]`，逻辑照这段抄（**它已经处理了"自己/别人"两种情况和调度冻结**），
风格换成我们的中文输出 + `help` 串。改完**在模拟器里不适用**（模拟器没有 FreeRTOS 任务），只能实机验：`bt main`、`bt taskLVGL`。

### 范例 C：启动亮度渐变 —— 我们照它的思路做过一次

它的 `main/app/boot_anim.cpp`：把目标亮度分 **N 步**、每步 `vTaskDelay(5ms)` 线性升上去，
**并且每步都检查一个"退出标志"**（按键松开可以提前结束）。

我们的对应实现（`components/app/app.c` 的 `backlight_fade_in()`）：
改成"界面就绪后再淡入"（避免露出半成品界面），用 `esp_timer` 周期回调而不是独立任务，
并**去掉了"触摸打断"**（只有 300ms，不值得为它加一套状态——这是一个**有意识的取舍**，写在注释里）。

> 👉 这个范例说明标对的正确姿势：**学它的做法，然后按我们的约束做取舍，并把取舍写进注释**。

## 七、注意事项（工程 + 法律）

1. **许可证**：参考工程是开源项目，**抄代码前先确认它的许可证**并在我们的 `README.md`
   "第三方与致谢"表里加一行（我们已有的例子：LVGL、esp_lvgl_port、Chromium 小恐龙、恐龙玩法参考）。
   不确定时：**只借鉴思路与参数，不复制代码文本**。
2. **版本漂移**：它是 IDF 5.5.5 / LVGL 8.3.11，我们是 5.5.4 / 8.4.0。API 有出入时**以我们编译通过为准**。
3. **别被它的结构带走**：它的 `main/` 大目录 + C++ + 全局变量是历史包袱（从 Arduino 分支移植来的）。
   我们的 22 组件分层是有意为之，**不要为了"跟参考工程一致"去破坏它**。
4. **它的行为不是验收标准**：它跑 80MHz、用 PSRAM 大缓冲、有 SD 卡 —— 我们的验收标准是
   **编译 0 错误 + 模拟器自检 0 失败 + 实机人验**，以及我们自己的性能/内存预算。
5. **它是"参考"不是"依赖"**：不能让它出现在编译路径里（它只是素材目录）；
   最终代码必须自包含，别人 clone 我们的仓库就能编。
