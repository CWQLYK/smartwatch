## 一、现状：现在的"息屏"到底关了什么（逐项实测，带出处）

`power_screen_off()` 目前**只做一件事**：`bsp_backlight_set(0)`（`power.c:84-92`），
它自己的日志就写着"息屏（只关背光，CPU 照跑）"。所以息屏期间：

| # | 部件 | 息屏后的状态 | 频率 / 数值 | 出处 |
|---|---|---|---|---|
| 1 | 背光（LEDC duty 0） | **已关**（省了大头） | — | `bsp.c:71-81` |
| 2 | LCD 面板 | **仍在扫描显示**（GRAM 静态功耗） | 面板照常工作 | `bsp.c:130` 只调过一次 `disp_on_off(true)` |
| 3 | LVGL 刷新 | **照跑** | **100Hz**（`CONFIG_LV_DISP_DEF_REFR_PERIOD=10`） | `sdkconfig:2347` |
| 4 | 触摸 I2C 读取 | **照读**（每 10ms 一次 I2C 事务） | **100Hz** | `sdkconfig:2348` + `bsp.c:151-157` |
| 5 | IMU 采样 | 照跑 | 50Hz | `motion.c:29`、`:86` |
| 6 | data_hub 采样 | 照跑 | 1Hz（电量 30s） | `data_hub.c:33` |
| 7 | 电源轮询定时器 | 照跑 | 50Hz（`POWER_POLL_MS=50`） | `power.c:38`、`:260` |
| 8 | 时钟服务定时器 | 照跑 | 空闲 1Hz / 响铃时 100ms 自适应 | `watch_clock.c:78-87`、`:133` |
| 9 | WiFi | **连上就一直连着**（无闲置断开） | — | 见 §九（本档不做） |
| 10 | CPU | **恒定 240MHz**，无 DFS、无 tickless | `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y` | `sdkconfig` |
| 11 | PM / 睡眠 | **全工程 `esp_pm_*` / `esp_sleep_*` 零调用** | — | 本轮 grep 复核 |

**结论**：息屏后真正还在花电的是 **面板（2）+ 100Hz 的 LVGL 与触摸轮询（3、4）**，
这三条正是本档要处理的；CPU 频率与睡眠（10、11）是第二档的事。

## 二、把"低功耗"拆成三档（这样每一档的风险和收益都清楚）

| 档 | 内容 | 收益来源 | 风险 | 本档 |
|---|---|---|---|---|
| **第一档** | 面板 DISPOFF + LVGL 刷新放慢到 100ms + 触摸 I2C 门控 + 空闲定时器放宽 | 面板静态功耗 + 去掉 100Hz 的 SPI 推帧与 I2C 事务 + 减少任务唤醒 | **低**（全部非阻塞、可独立回滚） | ✅ **已实现并实机验证**（§4.2 末尾有实测结果） |
| **1.5 档** | 面板 **SLPIN**（更深睡眠，ST7789 的 sleep-in） | 面板控制器进入 sleep，比 DISPOFF 更低 | 中（驱动内部有 100ms 阻塞 → 需状态机） | ⭕ 可选，§四.5 |
| **第二档** | `CONFIG_PM_ENABLE` + DFS（空闲降频）+ light sleep（触摸 INT / RTC INT 唤醒） | CPU 240→80MHz、空闲时 CPU 停摆 —— **这一档才是毫安级的大头** | **高**（tickless、I2C/SPI 的 PM 锁、唤醒源配置、外设状态） | ❌ 单独一批（§九） |

> 深睡（`esp_deep_sleep`）**不建议**用于"息屏 30 秒"：它等于整机重启（`app_main` 重跑），
> 而本项目冷启动到可用约 **2.3 秒**（交接文档 §1.3）。深睡只适合"用户主动关机/长时间不用"。

## 三、已核实的关键事实（这几条决定了方案怎么写）

### 3.1 ✅ 关屏 API：`esp_lcd_panel_disp_on_off()` —— 非阻塞，可以随便调

- 声明：`esp_lcd_panel_ops.h:122`；实现只是发一条命令（`esp_lcd_panel_st7789.c:304-317`，
  `DISPON=0x29` / `DISPOFF=0x28`），**没有 delay**。
- 项目里**已经在用**：`bsp.c:130` 初始化时调过 `esp_lcd_panel_disp_on_off(s_lcd_panel, true)`。
- ⇒ 可以安全地从 esp_timer 回调（`power.c` 的 `poll_cb`）里调用。

### 3.2 ✅ 更深的 `esp_lcd_panel_disp_sleep()` —— 支持，但**内部阻塞 100ms**

```c
/* esp_lcd_panel_st7789.c:319-334（IDF v5.5.4，vendored 之外的官方组件） */
static esp_err_t panel_st7789_sleep(esp_lcd_panel_t *panel, bool sleep)
{
    int command = sleep ? LCD_CMD_SLPIN : LCD_CMD_SLPOUT;   /* 0x10 / 0x11 */
    esp_lcd_panel_io_tx_param(io, command, NULL, 0);
    vTaskDelay(pdMS_TO_TICKS(100));      /* ★ 无条件阻塞 100ms —— 谁调谁等 */
    return ESP_OK;
}
```
且驱动已把它挂上：`st7789->base.disp_sleep = panel_st7789_sleep;`（`:133`）。

> ⚠️ **所以它绝不能从 `power.c` 的 `poll_cb`（esp_timer 任务）里调** ——
> esp_timer 回调必须快进快出，阻塞它会连带推迟 `power_poll` 自身和 `bl_fade`（30ms 周期的背光淡入）。
> 见 §四.5 的非阻塞做法。

### 3.3 ✅ 降刷新的官方口子：`_lv_disp_get_refr_timer()` —— 但**只能"放慢"，不能"暂停"**

- 声明在**公开头** `lv_disp.h:171`，文档原话：
  "*Get a pointer to the screen refresher timer to **modify its parameters with `lv_timer_...` functions***"。
- 配 `lv_timer_set_period()`（`lv_timer.h:134`）。

**★ 实施中发现的关键约束（本版因此把"暂停"改成了"放慢到 100ms"）**：

`lv_timer_handler()` 的返回值是"距下一个**未暂停**定时器还有多久"：

```c
/* lv_timer.c */
uint32_t time_till_next = LV_NO_TIMER_READY;   /* :121 */
    if(!next->paused) { ...取最小 delay... }    /* :124 */
return time_till_next;                          /* :145 */
```
而 `esp_lvgl_port` 的任务**直接拿这个返回值当自己的睡眠时间**
（`esp_lvgl_port.c:198-206`，上限 `task_max_sleep_ms` = **500ms**）。

⇒ 一旦把 refresh timer **暂停**，息屏时屏幕上只剩 `watch_clock` 的 1 秒定时器，
LVGL 任务会**每 500ms 才醒一次**，后果（都是真问题）：

1. **闹钟响铃迟到**：`alert_pump()`（"每 500ms 响 300ms"）跑在 LVGL 定时器上 → 最长迟 500ms 才开始响，节奏还被量化成 500ms；
2. **倒计时到点迟到**：到点判定在 `clock_timer_cb()` 里 → 最长迟 500ms；
3. **亮屏重画迟到**：任务睡着时没人处理 invalidate → 最长 500ms 才出画面。

⇒ **正确做法：`lv_timer_set_period(refr, 100)`**。延迟 ≤100ms（无感），
刷新相关唤醒从 100Hz 降到 10Hz（省掉那 90 次/秒的空转检查）。

> 另注：`esp_lvgl_port` 的 `lvgl_port_task_wake()` 在 **LVGL8 上是空实现**
> （直接 `return ESP_ERR_NOT_SUPPORTED`），所以"暂停后用 API 把任务叫醒"这条路在本工程不可用。

### 3.4 ❌ `lv_indev_get_read_timer()` 在这个 LVGL 里是**坏的，禁止使用**

```c
/* lv_indev.c —— 签名类型写错，而且函数体返回的是 display 的字段 */
lv_timer_t * lv_indev_get_read_timer(lv_disp_t * indev)   /* ← 应该是 lv_indev_t* */
{
    return indev->refr_timer;      /* ← refr_timer 属于 lv_disp_t，不是 indev 的 read_timer */
}
```
传一个 `lv_indev_t*` 进去，它会按 `lv_disp_t` 的布局去取 `refr_timer` —— **拿到的是错指针**。
而 `struct _lv_indev_t` 也**不在** `lv_indev.h` 里（公开头只声明了函数），所以想手写 `indev->read_timer` 还得 include 私有头。

> **⇒ 决策：本档不用"降触摸轮询频率"这条路线，改用 §四.3 的 INT 门控**（更安全、收益相同）。

### 3.5 ✅ 为什么 INT 门控是安全的（CST816T 的 INT 引脚）

- 触摸芯片 CST816T 是**独立器件**，挂在共享 I2C 上（0x15），**不受 LCD 面板 DISPOFF/SLPIN 影响**；
- 它有 **INT 引脚（GPIO14，低有效）**：`board.h:44`；`bsp.c:220` 已把它配成中断脚（只是没注册 ISR）；
- 项目**已经在依赖它**：`power.c:129-132` 的 `touch_pressed()` 就是 `gpio_get_level(BOARD_TOUCH_GPIO_INT) == 0`；
- 读一个 GPIO 电平**几乎零成本**（寄存器读），而 I2C 事务要拉总线 + 100ms 超时保护 + 400kHz 时序。

### 3.6 ★ 三条必须遵守的息屏/亮屏铁律（都已逐行验证）

| # | 铁律 | 依据 |
|---|---|---|
| 1 | **只能"放慢" display refresh timer —— 不能暂停，更不能冻结 `lv_timer_handler()`** | ① 闹钟/倒计时/提醒层的推进**全在 LVGL 定时器上**（`watch_clock.c:133` → `alert_pump()`）；② 而 `esp_lvgl_port` 的任务拿 `lv_timer_handler()` 的返回值当睡眠时间 → 暂停 refresh timer 会让它睡满 500ms，到点提醒、亮屏重画全都迟到（详见 §3.3） |
| 2 | **亮屏必须三件套**：面板 DISPON + 恢复刷新 + **整屏重画** | `alert_start()` 会在闹钟到点时主动 `w_screen_wake()`（`watch_clock.c:359`）——不 invalidate 会出现"闹钟响了但屏上是旧画面" |
| 3 | **不能从 `power.c` 的轮询里"先亮屏再等触摸"** | 唤醒必须仍然经过 `bsp.c` 的触摸读回调，因为"吞掉唤醒那一下"的标志是在那里设的（`bsp.c:168-186` → `w_screen_should_swallow_touch()`）。若在别处先亮屏，读回调再进来时 `was_on` 已是 true → **不吞 → 误触手指下面的控件**（v0.6.1 修过的老 bug 会复发） |

### 3.7 现有可用的量化工具（验收要用）

- 串口 **`stats`**：各任务 CPU 占用（采两次，间隔 1 秒）→ 可以客观对比"息屏空闲时 `taskLVGL` 的 CPU%"改动前后；
- 串口 **`taskmem`**：各任务栈余量 → 确认新增代码没吃穿栈（`taskLVGL` 目前余 3296、`data_hub` 余 2048）；
- 串口 **`power status`**：看息屏/亮度状态；
- 模拟器 **`SIM_SELFTEST=1`**：逻辑回归（退出码 0）。

## 四、逐项设计

### 4.1 BSP 新增接口（`components/bsp/`）

```c
/** @brief 面板显示开/关（ST7789 DISPON 0x29 / DISPOFF 0x28）
 *  @note  只是"关显示输出"，不是面板睡眠；**非阻塞**（一条命令），可在任意任务/定时器回调里调。
 *  @note  不碰背光、不碰 LVGL 刷新 —— 那两件事由 power.c 负责编排。 */
esp_err_t bsp_lcd_display(bool on);
```
实现一行：`return esp_lcd_panel_disp_on_off(s_lcd_panel, on);`

**可选（1.5 档，见 §四.5）**：同文件再加 `esp_err_t bsp_lcd_sleep(bool sleep);`，
但在头文件注释里**必须写明它会阻塞约 100ms**（驱动内部 delay），并注明"禁止从 esp_timer 回调调用"。

### 4.2 `power.c` 的息屏 / 亮屏序列（本档核心）

**息屏**（由现有的 `poll_cb` 超时触发，运行在 esp_timer 任务 —— 所以这里**只能**用非阻塞调用）：

```
power_screen_off():
  ① bsp_backlight_set(0)                     ← 保留（原有行为）
  ② bsp_lcd_display(false)                   ← 新增：面板停显示输出
  ③ 把 LVGL 刷新放慢到 100ms（非阻塞拿锁，拿不到就下次再试）：
       if (bsp_display_lock(0)) {
           lv_timer_t *t = _lv_disp_get_refr_timer(bsp_display_get());
           if (t) lv_timer_set_period(t, 100);      ← ★ 不是 pause！见 §3.3
           bsp_display_unlock();
       }
  ④ poll_retime(true)                        ← 电源轮询 50ms → 200ms
  ⑤ s_screen_on = false; 记日志
```

**亮屏**（三件套；调用点有三处：触摸唤醒 `hook_activity()`、闹钟 `hook_wake()`、串口 `power on`）：

```
power_screen_on():
  ① bsp_lcd_display(true)                    ← 先让面板能显示
  ② 恢复刷新速率 + 整屏重画（同样非阻塞拿锁）：
       if (bsp_display_lock(0)) {
           lv_timer_t *t = _lv_disp_get_refr_timer(bsp_display_get());
           if (t) lv_timer_set_period(t, LV_DISP_DEF_REFR_PERIOD);   /* 回 10ms */
           lv_obj_invalidate(lv_scr_act());     ← 强制整屏重画
           lv_obj_invalidate(watch_ui_screen());← 轮播 screen（模态与提醒层挂在它上面）
           lv_obj_invalidate(lv_layer_top());   ← toast 挂在 top layer 上，别漏
           bsp_display_unlock();
       }
  ③ bsp_backlight_set(bright)                ← 恢复到设置里的亮度（≥5）
  ④ poll_retime(false)                       ← 轮询恢复 50ms
  ⑤ s_wake_at = now                          ← 沿用现有"吃掉唤醒那一下"的屏蔽期
```

**关于拿不到锁**：`hook_activity()` 跑在 LVGL 任务里（触摸读回调），锁必然拿得到；
`poll_cb` 跑在 esp_timer 任务里，可能拿不到 → 那就置 `s_refr_pending`，
在 `poll_cb` 顶部**补做**（补做时若那次是"亮屏"，把整屏重画也一起补上）。
**不要**为了拿锁而阻塞 esp_timer 任务。

### 4.3 触摸 I2C 门控（`bsp.c` 的 `touch_read_cb`）—— 本档第二个收益点

**现状**：LVGL 每 `LV_INDEV_DEF_READ_PERIOD`（**10ms**）调一次 `touch_read_cb`，
每次**无条件**做一次 I2C 事务（`esp_lcd_touch_read_data()`，`bsp.c:157`）→ **息屏时也是 100 次/秒**。

**做法**：在回调最前面加一道"息屏 + 没人碰"的快速返回，完全不碰 I2C：

```c
static void touch_read_cb(lv_indev_drv_t *drv, lv_indev_data_t *data)
{
    esp_lcd_touch_handle_t tp = (esp_lcd_touch_handle_t)drv->user_data;

    /*
     * ★ v0.7.1 省电门控：息屏且 INT 为高（没人碰）→ 直接报"松开"，**不做 I2C 事务**。
     *
     *  为什么安全：
     *   1. CST816T 是独立器件，INT(GPIO14, 低有效) 在手指按下时拉低 —— 本项目
     *      已经在依赖它（power.c:129-132 的 touch_pressed()）；
     *   2. 读一个 GPIO 是寄存器级操作，比一次 I2C 事务便宜几个数量级；
     *   3. **亮屏时这道门不生效**，触摸手感完全不受影响；
     *   4. 有人碰时照旧走完整流程 → w_screen_notify_activity() → 亮屏 + 吞掉那一下
     *      （铁律 #3：唤醒必须走这里，所以这道门不能反过来把唤醒挡掉）。
     */
    if (!w_screen_is_on() && gpio_get_level(BOARD_TOUCH_GPIO_INT) != 0) {
        data->state = LV_INDEV_STATE_RELEASED;
        return;
    }

    esp_lcd_touch_read_data(tp);
    ... 其余保持原样
}
```

**收益**：息屏空闲时 **I2C 事务从 100 次/秒降到 0**（只剩 100Hz 的 GPIO 读 + LVGL 定时器唤醒）。
**代价**：无（亮屏行为逐字节不变）。
**副作用需实机确认**：若某块板的 CST816T 在空闲时 INT 不是稳定高电平，会出现"息屏时误认为有人碰"
→ 那只是多做了几次 I2C 读，**不会误触**（因为坐标要真的按下才有效）；最坏情况是省电收益变小。

> **为什么不改用"降低触摸轮询频率"**：见 §3.4 —— `lv_indev_get_read_timer()` 是坏的，
> 而 `struct _lv_indev_t` 不在公开头里。INT 门控达到同样效果且不碰 LVGL 私有结构。

### 4.4 空闲定时器放宽（小项，但都是"每秒白醒很多次"）

| # | 位置 | 现状 | 改法 | 依据/风险 |
|---|---|---|---|---|
| 1 | `power.c` 的 `poll_cb`（`POWER_POLL_MS=50`） | 息屏时仍 20Hz 轮询，而它在息屏状态下几乎什么都不做 | 息屏时把周期放到 **200ms**，亮屏时回到 50ms（`esp_timer_start_periodic` 用新周期重启） | 只影响"屏蔽期结束/兜底活动检测"的精度；休眠期不需要 50ms 精度 |
| 2 | `watch_game.c` 的帧定时器（`GAME_FRAME_MS=33`） | `READY/PAUSE/OVER` 时**仍然 30Hz 空转**（回调里只做两次 `lv_tick_get()`） | 非 `GS_PLAY` 时把周期改成 200~500ms，进 `GS_PLAY` 再改回 33ms | 照 `watch_clock.c:78-87` 已有的自适应周期写法；暂停面板上的按钮是事件驱动，不依赖帧定时器 |

> ⚠️ 第 2 项是**优化清单 §5.14 已记录**的项，属"顺手修"；但因为它是"息屏/空闲时不必要唤醒"，
> 与低功耗主题直接相关，所以放进本档。

### 4.5 【可选，1.5 档】面板 SLPIN —— 更深，但需要一个非阻塞时序

**为什么值得做**：DISPOFF 只是"关显示输出"，面板控制器（含 charge pump/振荡器）仍在工作；
**SLPIN（0x10）才是把面板送进睡眠**。对"息屏后长时间待机"的场景，这是 DISPOFF 之外的第二笔面板功耗。

**为什么不能直接调**：驱动内部 `vTaskDelay(100ms)`（§3.2）。而息屏由 `poll_cb`（esp_timer 任务）触发。

**做法（非阻塞状态机，~20 行，仍在 `power.c` 内）**：
```
息屏：poll_cb 置 s_panel_want = SLEEP
      → 由一个 20ms 的 lv_timer（跑在 LVGL 任务里，允许阻塞）执行：
          bsp_lcd_display(false)            /* 先关显示输出 */
          bsp_lcd_sleep(true)               /* 内部等 100ms，跑在 LVGL 任务里可接受 */

唤醒：power_screen_on() 置 s_panel_want = WAKE
      → 同一个 lv_timer：
          bsp_lcd_sleep(false)              /* SLPOUT，内部等 100ms */
          bsp_lcd_display(true)             /* SLPOUT 之后才能 DISPON */
          恢复刷新 + 整屏重画
```
**为什么唤醒要串行化**：ST7789 的时序要求 **SLPOUT 之后才能发后续命令**
（面板在上电初始化里也是先 SLPOUT 再配置，见 `esp_lcd_panel_st7789.c:187`）。
所以"SLPOUT → DISPON → 重画"必须是这个顺序，代价是**亮屏多约 100ms 延迟**。

**必须实机确认的三点**：
1. 亮屏延迟 100ms 是否可接受（背光可以**先亮**、画面 100ms 后出现？还是等 SLPOUT 完再亮背光以免看到黑屏闪烁）；
2. SLPIN 后 CST816T 的 INT 是否仍然可靠（它俩是独立器件，理论上无关，但要实测）；
3. 反复 SLPIN/SLPOUT 20 次不出花屏（面板时序边界）。

**回滚**：不建那个 `lv_timer` 即回到第一档。

## 七、风险、边界与回滚

| # | 风险 | 说明 | 缓解 / 回滚 |
|---|---|---|---|
| 1 | 亮屏后画面不刷新（黑屏/旧画面） | 忘了 `lv_obj_invalidate()`，或恢复刷新时没拿到锁 | 铁律 #2 三件套 + 自检断言 #3；实机清单第 1 条 |
| 2 | 闹钟/倒计时在息屏时"哑掉" | 误把整个 `lv_timer_handler` 停了 | 自检断言 #4 专门守这条 |
| 3 | 唤醒误触（老 bug 复发） | 在别处先亮屏，破坏了"吞掉那一下"的前提 | 铁律 #3：唤醒只经 `bsp.c` 触摸回调；自检断言 #2 |
| 4 | DISPOFF 后画面残影/闪一下 | ST7789 边界行为 | 实机看；回滚 = 去掉 `bsp_lcd_display()` 两个调用 |
| 5 | 息屏时 `bsp_display_lock(0)` 拿不到锁 | esp_timer 任务不阻塞 | 用"想要的状态"标志，在 `poll_cb` 里补做（§4.2） |
| 6 | INT 门控误判（板子差异） | 只是多几次 I2C 读，不误触 | 实机确认；回滚 = 删掉那 4 行 |
| 7 | §4.4 放宽电源轮询导致唤醒屏蔽期变长 | `W_IGNORE_TOUCH_MS=350` 的结束判定精度从 50ms 变 200ms | 可只在**息屏**时放宽；实机体会 |

**回滚总原则**：本档每一个改动都能**单独删掉**且不留状态（无新增 NVS 项、无新增任务）。
最坏情况：`git revert` 单个提交。

## 九、本档**不做**的，以及为什么（避免范围蔓延）

| 项 | 为什么不做 / 何时做 |
|---|---|
| **IMU 降频（息屏 50→10~25Hz）** | 会破坏计步：带通系数 `k_bp[2][5]` 与 4 个 EMA alpha**全部按 50Hz 硬编码**（`qmi8658c.c:5,45-47,54-64`），`above_cnt>=3` 还是**按样本计数**（`:495`）；作者自己在 `motion.c:253-254` 写了"采样率必须和 `sample_rate_hz` 对得上，否则带通截止频率会偏，计步会忽多忽少"，而**该约束没实现**。属**重新标定级**工程。→ 单开一版；更好的方向是用 QMI8658C 的**运动中断**（INT2=GPIO38 目前空闲）做"静止停采、动起来再采"。 |
| **WiFi 空闲自动断开** | ① 字面的"校时后立刻断"会**打坏天气**（连上就自动 SNTP → 断网 → 用户再点【获取天气】没网）；② `wifi_service` **内部没有任何周期 tick**，两个超时都是"有人调 `hook_get_status()` 时才惰性求值"，而那只在 WiFi 页打开时发生 → 朴素空闲超时**在该生效时永不触发**；③ 自动断开必须走 `s_user_disconnect = disconnect_event_expected()` 标志，否则会被当成"连接失败"，且若 `s_conn_used_saved` 仍为真**还会删掉用户保存的密码**（`wifi_service.c:776-825`）。→ 需要单独设计（引用计数 + 真正的 tick）。 |
| **第二档：`CONFIG_PM_ENABLE` + DFS + light sleep** | **收益最大、风险也最高**：需要 tickless idle、给 SPI/I2C 加 PM 锁、配置唤醒源（触摸 INT=GPIO14 / RTC INT=GPIO39 目前都没用作唤醒），且 light sleep 期间外设状态要逐项确认。→ **建议在本档做完实机续航对比之后再单独立项**（那时才知道还差多少）。 |
| **深睡** | = 整机重启（冷启动约 2.3 秒），只适合"主动关机/长时间不用"。 |
| 其他（上滑入口、UAF、布局、天气 epoch 等） | 与本档无关，已在 `doc/智能手表-v0.7.1实施文档.md` 里单独列出，**等你许可再排期**。 |
