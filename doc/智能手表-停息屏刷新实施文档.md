# 智能手表 —— "息屏彻底停刷新 + 闹钟/触摸脱离 LVGL 循环" 实施文档

> 关联：[低功耗总纲](智能手表-低功耗实施文档.md) §4.5（1.5 档面板深睡，已实施）、§4.6（第二档，阶段 1 DFS 已实施）

## 一、目标 / 收益 / 代价（先把话说清楚）

**目标**：息屏时 LVGL 任务**完全不运行**（现在只是"放慢"，仍是每秒醒 10 次）；同时让**闹钟、倒计时、触摸唤醒不再依赖 LVGL 的循环节奏**。

| | 内容 |
|---|---|
| **收益 1（正确性）** | 闹钟/倒计时的准点性不再受"LVGL 任务睡多久"牵制。**现状：最坏会晚约 500ms**（见 §二的分析），改造后由硬件定时器驱动，误差在毫秒级 |
| **收益 2（省电）** | 息屏时 LVGL 任务从"每秒醒 10 次 + 每秒推一次没人看的画面"变成**完全不醒**。可用 `stats` 客观验证（息屏静置时 `taskLVGL` 的 CPU 占用应从 ~9% 降到接近 0） |
| **收益 3（为 light sleep 铺路）** | 唤醒源从"LVGL 定时器"变成"**触摸中断 + 闹钟定时器**"。这是第二档阶段 2 能安全落地的前提 —— 否则一开 light sleep，触摸和闹钟都会失灵或延迟 |
| **代价 / 风险** | 涉及 `power.c` / `bsp.c` / `watch_ui/watch_clock.c` / 新增触摸中断 → **分 3 步实施，每步可独立验证、可单独回滚** |
| **⚠️ 诚实的收益预期** | **单看电流，这一项收益不大（预计 1mA 量级以内）**：息屏时 CPU 本来就在降频空转，真正的大头是 light sleep（把 CPU 停掉）。**这一项的主要价值是"结构正确 + 让 light sleep 能安全落地"**，不是它自己省的那点电 |

## 二、★ 为什么不能"只把刷新停掉"（依赖链分析，本文档的核心）

现状：画面刷新的定时器**身兼三职**，所以它不能想停就停。

| 它现在承担的职责 | 说明 |
|---|---|
| ① 画面刷新 | 亮屏时有用；**息屏时本来也没人看**（这部分确实是浪费） |
| ② LVGL 任务的"心跳" | `lv_timer_handler()` 跑完会返回"下一个定时器还有多久到期"，LVGL 移植层拿它当睡眠时间（**上限 500ms**）。刷新定时器是周期最短的那个（息屏 100ms），所以**是它在维持整个循环的节奏** |
| ③ 触摸的读取节奏 | 触摸**不是**中断驱动的，而是由 LVGL 的输入设备定时器（`LV_INDEV_DEF_READ_PERIOD`=10ms）周期调用的回调去读的（`bsp.c:177` 有明确注释）。**循环一停 = 没人读触摸 = 屏幕再也叫不醒** |

**并且还有一个反直觉的事实**（这次核查代码才发现，值得记下来）：

> 闹钟/倒计时**不是**挂在刷新定时器上，而是挂在**它自己的 LVGL 定时器**上
> （`watch_ui/watch_clock.c:81` 的 `clock_timer_cb`，空闲周期 1000ms）。
> 但 LVGL 定时器同样要由 `lv_timer_handler()` 来跑，而移植层任务**最多睡 500ms** ——
> 所以**闹钟的实际精度上限是约 500ms**（不是 100ms、也不是 1 秒）。
> 现在的 100ms 刷新定时器只是**"顺带"**把循环叫醒得勤一些，让闹钟看起来只晚 ≤100ms。

⇒ **结论**：只停刷新，闹钟会从"晚 ≤100ms"退化到"晚 ≤500ms" ✗。
必须先把**闹钟搬到硬件定时器（esp_timer）**、把**触摸改成中断**，最后才能停刷新 ✔。

## 三、改造后的职责划分（对照表）

| 职责 | 现在 | 改造后 |
|---|---|---|
| 每秒时间推进 | `data_hub` 发 `EVT_TIME_TICK`，UI 侧处理 | 不变（`data_hub` 已有独立任务） |
| **闹钟/倒计时判定 + 到点响铃** | **LVGL 定时器**（`clock_timer_cb` 1s/100ms 自适应） | **独立 `esp_timer`（1s）+ 独立任务**，不再依赖 LVGL |
| 弹提醒层 / 刷新时钟数字 | LVGL 定时器里直接调 `s_ui_refresh()` / `watch_alert_poll()` | 改为"**请求绘制**"：唤醒 LVGL 任务，由它绘制 |
| **触摸检测** | LVGL 输入定时器每 10ms 轮询（含 INT 门控） | **触摸 INT 的 GPIO 中断**（下降沿）→ 唤醒请求；坐标仍在 LVGL 醒来后读 |
| **画面刷新** | 息屏放慢到 100ms | **息屏暂停**；亮屏恢复 10ms |
| **LVGL 任务** | 一直运行 | 息屏且无待画内容 → **挂起**；需要画 → **恢复** |
| 屏幕面板 | DISPOFF + SLPIN（已有） | 不变 |

## 四、详细设计

### 4.1 时间与提醒服务（新增 `time_svc`，逻辑从 `watch_clock.c` 搬移）

- **1 秒周期 `esp_timer`**（硬件定时器，不依赖任何任务的调度节奏）。
- 回调里**只做三件事**（都不允许阻塞）：
  1. 判定"闹钟/倒计时是否到点"（复用现成的 `watch_clock_tick()` 逻辑，**搬移不重写**）；
  2. 到点 → 启动蜂鸣器（现有 `buzzer` 组件）+ 请求亮屏（现有 `power_screen_on()`，非阻塞）；
  3. 置"需要弹提醒层"标志 + **唤醒 LVGL 任务**。
- ⚠️ **铁律**：`esp_timer` 回调里**不能阻塞、不能碰 LVGL 对象**（LVGL 不是线程安全的）→ 所有绘制都交给 LVGL 任务。
- 倒计时精度：1 秒足够（界面显示的就是秒）；秒表在运行时由 LVGL 侧自己按需刷新（那时屏幕必是亮的）。

### 4.2 触摸改为中断驱动（这是"能停刷新"的前提）

- 触摸 INT（低有效，`BOARD_TOUCH_GPIO_INT`）配 `gpio_isr_handler`（**下降沿**）。
- ISR 里**只置标志 + 通知**（`xTaskNotifyGive`）：**不做 I2C、不碰 LVGL、不打印日志**。
- **去抖**：30~50ms 内重复中断只算一次（用时间戳判断，不阻塞）。
- 醒屏路径复用现有实现：中断 → `power_screen_on()`（非阻塞，已实现）→ 恢复 LVGL 任务与刷新 → 面板 `SLPOUT` → `DISPON` → **同步整屏重画** → 开背光（顺序已有）。
- 坐标读取仍在 LVGL 任务里（唤醒后照旧读），避免在 ISR 里做 I2C；"第一次触摸只用于唤醒、不误触控件"的屏蔽期逻辑已有 ✔。

### 4.3 LVGL 任务按需运行（挂起 / 恢复）

- 句柄：`xTaskGetHandle("taskLVGL")`（移植层的任务名，实测就叫这个）。
- **★ 挂起前的安全规则（上次死锁事故的教训，必须写进代码注释）**：
  **先成功获取 LVGL 锁**（`bsp_display_lock`）—— 这一步同时**证明该任务此刻不持有锁**；拿到锁后再挂起它，最后放锁。
  **绝不允许"没拿到锁就挂起"**：那样可能把它停在持锁状态下，全系统凡是要用 LVGL 的地方都会永久阻塞。
- 恢复时机（任一即有）：触摸唤醒、闹钟/倒计时到点要弹层、页面切换/设置变化导致重画、串口命令要求亮屏。
- **兜底**：发出"唤醒请求"后 200ms 检查 LVGL 任务是否真的在跑（`eTaskGetState`），没跑则重试一次 + 打 ERROR 日志（避免"请求丢了、屏幕再也不亮"这种最坏情况）。

### 4.4 刷新定时器：息屏暂停

- 息屏：`lv_timer_pause(_lv_disp_get_refr_timer(disp))`；亮屏：`lv_timer_resume(...)`（接口已有，现用 `lv_timer_set_period`）。
- 亮屏**不依赖**它：唤醒路径本来就是"**同步整屏重画**"（`lv_refr_now`，1.5 档已实现）✔。

### 4.5 两条唤醒时序（完整序列）

**触摸唤醒**
```
触摸芯片 INT 拉低 → GPIO 中断（只置标志）
  → 去抖 40ms → power_screen_on()（非阻塞：刷新恢复、轮询恢复、屏蔽期开启）
  → 恢复 LVGL 任务 → 面板 SLPOUT（~100ms）→ DISPON
  → 同步整屏重画 → 开背光
```

**闹钟 / 倒计时唤醒**
```
esp_timer 1s 到点 → 判定到点 → 蜂鸣器开始响 + power_screen_on()
  → 唤醒 LVGL 任务 → 弹提醒层 → 同步整屏重画 → 开背光
```

**息屏入睡**
```
power_screen_off()（浅睡：背光 0、DISPOFF、暂停刷新、轮询放慢）
  → 面板深睡 SLPIN（已有状态机）
  → 确认无待画内容 → 挂起 LVGL 任务
```

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| **挂起 LVGL 任务造成死锁**（历史事故类型） | 挂起前必须先拿到 LVGL 锁（证明它没持锁）；写进注释 + 代码评审要点 |
| 暂停刷新后某些状态不再更新 | 息屏时本来就不可见；唤醒路径做**整屏重画**，不依赖增量刷新 ✔ |
| 触摸中断抖动 / 误触发 | ISR 只置标志；40ms 去抖；坐标读取照旧在任务里做 |
| 闹钟到点但 LVGL 没被唤醒 | 200ms 兜底检查 + 重试 + ERROR 日志 |
| `esp_timer` 回调阻塞（会拖垮整个定时器任务） | 回调内只做标志/通知/蜂鸣器启动；**严禁** I2C、绘制、`vTaskDelay` |
| 连续触摸/长按 | 第一次触摸只用于唤醒（屏蔽期逻辑已有）；长按沿用现有处理 |
| 与 DFS / 后续 light sleep 的交互 | 蜂鸣器响、屏幕亮时按既有规则持锁（`NO_LIGHT_SLEEP`）不被睡；触摸 INT 将成为 light sleep 的唤醒源 |

## 六、验证方案（要求客观可量化，不靠"感觉"）

| # | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | **闹钟准点性** | 日志打印"到点时刻 vs 实际触发时刻"的差值，改造前后对比 | 改造前允许 ≤500ms 抖动；**改造后应稳定在几毫秒级** |

| 3 | **唤醒延迟没有变差** | 沿用现有日志：`面板唤醒 SLPOUT+重画（耗时 X ms）` | 与改造前同量级（约 125ms） |
| 4 | **息屏电流** | 万用表串电池回路；运行开关 `power refrstop on\|off` 做 A/B | 记录实测差值（预期个位数 mA 以内，如实汇报） |

| 6 | 三道门 | 编译 0 error / 模拟器自检 0 失败 / 字库三连 | 全绿 |

## 七、分步实施（每步单独验证、单独回滚）

| 步 | 内容 | 验证 | 回滚 |
|---|---|---|---|
| **1** | 闹钟/倒计时判定与响铃搬到独立 `esp_timer` + 任务（功能不变，**先不动触摸和刷新**） | 验证项 1（准点性） | 删定时器即回到现状 |
| **2** | 触摸改为 INT 中断驱动（**保留原轮询作为开关 fallback**） | 验证项 3、5（唤醒/稳定性） | 开关切回轮询 |
| **3** | 息屏暂停刷新 + LVGL 任务按需挂起 | 验证项 2、4（`stats`/电流） | 开关切回"放慢到 100ms" |

- 每步都加**运行时开关**（默认先"关"，实测通过后再默认"开"），保证任何一步出问题都能一条命令退回。
- 三步都通过后，才考虑与第二档阶段 2（light sleep）合并。

## 八、明确**不做**的事

| 项 | 原因 |
|---|---|
| IMU 采样降频 | 会破坏按 50Hz 标定的计步算法（需重新标定，属独立工程） |
| light sleep 本体 | 属第二档阶段 2；本项做完后它才有安全落地的前提（唤醒源清晰、无周期刷新打扰） |
| 面板 SLPIN | 已完成（v0.7.3） |
| 让 LVGL 完全不初始化 | 亮屏后仍需绘制，且 `lv_refr_now` 是唤醒路径的关键步骤 |
