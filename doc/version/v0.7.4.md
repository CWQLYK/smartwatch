## 一、一句话总结

**本版让 CPU 不再"永远跑在 240MHz"：空闲时自动降到 40MHz，有活干自动升回来（DFS）。**

它只改了三个地方：
1. `sdkconfig.defaults` 开 `CONFIG_PM_ENABLE` + `CONFIG_PM_DFS_INIT_AUTO`；
2. **把背光和蜂鸣器的 LEDC 时钟源从"自动"改成"晶振"** —— 否则 DFS 一降频，**背光亮度会漂、蜂鸣器音调会跑**
   （查证：LEDC 驱动**不加任何 PM 锁**，是这一档里唯一"自己不管自己"的外设）；
3. 加 `pm` 命令（看当前频率/PM 锁列表）+ **`pm dfs on|off` 运行时开关**（既是测量手段，也是回滚开关）。

**实测结果**：息屏 **51 → 30mA**，亮屏静置 **80 → 60mA**（与 v0.7.3 的面板深睡合计）。

**★ 本版最值钱的产出其实不是代码，而是"动手前查出的两颗雷"**（见 §三）——
其中一颗**如果直接照搬常规做法开 light sleep，会让手表在电池供电下第一次睡眠就断电**。

## 三、★★ 动手前查出的两颗雷（本版最有价值的部分）

### 雷 1：开 light sleep 会让**电池供电直接断电**（所以本版只开 DFS）

常规做法是"顺手把 tickless 也开了"，但查 Kconfig 发现：

```
# esp_hw_support/Kconfig
select PM_SLP_DISABLE_GPIO if FREERTOS_USE_TICKLESS_IDLE      ← 强制打开，关不掉
```

而它的实现是（`esp_hw_support/sleep_gpio.c:223`）：

```c
#if CONFIG_ESP_SLEEP_GPIO_RESET_WORKAROUND || CONFIG_PM_SLP_DISABLE_GPIO
    // Configure to isolate (disable the Input/Output/Pullup/Pulldown function of the pin)
    // all GPIO pins in sleep state
    esp_sleep_config_gpio_isolate();
```

**即：light sleep 期间所有 GPIO 都被隔离（连输出功能一起关掉）。**
而本板的**电源自锁脚 `SYS_EN`(GPIO41) 正是靠"输出高电平"维持整机供电的**
（见 v0.7.2 §3.5：它驱动 T2 → 拉低 Q5 栅极 → Q5 保持导通）。

> ⇒ 不先用 `gpio_hold_en(GPIO41)` 把它钉住，**电池供电会在第一次 light sleep 时掉电**。
> ⇒ 而插着 USB 时 VBUS 直接供电，**这个坑在桌面上永远复现不出来**（和 v0.7.2 那颗雷同源）。

**所以本版的决定是：DFS 与 light sleep 拆成两个阶段**——DFS 不触发 GPIO 隔离，先做、先测；
light sleep 等把 hold 和几把锁都加好再做（清单见 §五）。

### 雷 2：LEDC 驱动**不加任何 PM 锁**（唯一"自己不管自己"的外设）

对依赖的外设做了一次全量排查：

| 依赖 | 自带 PM 锁？ | 结论 |
|---|---|---|
| SPI / esp_lcd / spi_flash / I2C / GPIO | ✅ 有 | 传输期间自动保护，不用我们管 |
| **LEDC（背光 + 蜂鸣器）** | ❌ **没有** | **DFS 一降频，PWM 频率就变 → 亮度漂、音调跑** ⇒ 必须换晶振时钟源 |
| esp_timer / ADC | ❌ 没有 | 但它们只在"任务正在跑"时才工作，而 DFS 只在 idle 时切换频率 → 安全 |

**顺带一个好消息**：`CONFIG_USJ_NO_AUTO_LS_ON_CONNECTION` —— IDF 在**检测到 USB 主机连接时会自己持有一把
`NO_LIGHT_SLEEP` 锁，主机一拔就释放**（`usb_serial_jtag_connection_monitor.c`）。
这正好是我们要的行为：**插 USB 调试时 light sleep 自动不生效（控制台不会被睡眠搞断），电池供电时才生效** ✔

### 4.3 ★ 实测功耗（**使用者用万用表串在电池回路测得**）

| 状态 | v0.7.1（旧） | **v0.7.3 + v0.7.4（现在）** | 变化 |
|---|---|---|---|
| **操作中**（点击/滑动/页面切换） | — | **≈130 mA** | 新增基线（交互时 CPU 满载 + 刷新 + 背光） |
| **亮屏静置** | 80 mA | **≈60 mA** | **−20 mA（−25%）** |
| **息屏** | 51 mA | **≈30 mA** | **−21 mA（−41%）** |

**诚实说明（测量口径）**：
- 这次**没有单独 A/B 测 DFS**（即 `pm dfs off` 与 `on` 各测一次），所以上面的降幅是
  **v0.7.3 的面板深睡（SLPIN）+ v0.7.4 的 DFS** 两项的**合计**效果，未拆分；
- "操作中 130mA" 说明：**屏幕 + 交互时的 CPU/刷新**才是当前最大的耗电项，
  所以**下一档（light sleep）的真正目标是"不操作时"的那 60/30mA**。

> 若以后想把两项拆开，方法仍在：`pm dfs off` / `pm deepsleep off` 排列组合，同电量下各测一次即可。

## 八、本版本改动简单说明

**这一版做的事：让 CPU 不再"永远全速跑"，空闲时自动降频省电。**

以前 CPU 一直锁在 240MHz，哪怕手表什么都没干。现在空闲时它会自动降到 40MHz，
你一操作它立刻升回 240MHz（这叫 DFS，动态调频）。**用起来完全一样，感觉不出来。**

**效果（你用万用表量出来的）**：

| 状态 | 以前 | 现在 |
|---|---|---|
| 操作手表时 | — | 约 130 mA |
| 亮着屏不动 | 80 mA | **60 mA** |
| 息屏 | 51 mA | **30 mA** |

**息屏从 51mA 降到 30mA，差不多省了四成。**

顺带说清楚两件事：

1. **这次省下来的电，是上一版（屏幕深睡）和这一版（CPU 降频）一起的功劳** ——
   你没有单独测"只开降频"和"只开深睡"，所以我也不硬说是谁的贡献。
   想分开看的话，命令还在：`pm dfs off`、`power deepsleep off`，各自关掉再量一次就行。
2. **"操作时 130mA"这个数很重要**：说明**屏幕和操作本身**才是最大的耗电项。
   所以下一步要省的是"不操作时"的那 60/30mA。

**另外，这一版真正值钱的其实是"没做的事"**：我本来可以顺手把一个更狠的省电功能
（light sleep，让 CPU 彻底睡过去）一起打开，但动手前查代码发现 ——
**那么做会让手表在电池供电下第一次睡觉就直接断电**（睡眠时芯片会把所有引脚"隔离"，
而这块板子恰恰靠一个引脚的高电平维持供电；插着 USB 时这个坑完全看不出来）。
所以我把它拆成了下一阶段，并把全部风险点列成了清单。

**下一步建议做的**：**light sleep（阶段 2）** —— 目标是把你现在息屏的 **30mA 再往下压到 10~15mA**。
清单已经准备好了，风险点也都定位清楚了。
