## 一、一句话总结

**把"息屏"从"只关背光（CPU/LVGL/IMU 全照跑）"改成真正的低功耗状态**：
面板停显示输出（DISPOFF）、LVGL 刷新从 100Hz 放慢到 10Hz、息屏空闲时完全不碰触摸 I2C、
电源轮询从 20Hz 放慢到 5Hz；游戏在非游戏状态下的帧定时器也从 30Hz 放到 3.3Hz。

**实施中发现并避开了一个会打坏闹钟的坑**（见 §三.1）：原本打算"暂停刷新定时器"，
但那会让 `lv_timer_handler()` 返回 ~1s，而 `esp_lvgl_port` 的任务拿它当睡眠时间（上限 500ms）
→ 闹钟响铃/倒计时到点/亮屏重画全会迟到最多半秒。改成"放慢到 100ms"后延迟 ≤100ms（无感），
同时仍省掉 90% 的刷新相关唤醒。

## 三、实施中的关键决策与"意外收获"

### 3.1 ★ 刷新只能"放慢"，不能"暂停"（差点打坏闹钟）

**原设计**（写进实施文档的第一版）：息屏时 `lv_timer_pause(_lv_disp_get_refr_timer(disp))`。
**实施中核对调度语义时发现它有害**：

```c
/* components/lvgl/src/misc/lv_timer.c */
uint32_t time_till_next = LV_NO_TIMER_READY;      /* :121 */
    if(!next->paused) { ...取最小 delay... }       /* :124  ← 暂停的定时器被跳过 */
return time_till_next;                             /* :145  ← 返回"距下一个未暂停定时器还有多久" */
```
而 `esp_lvgl_port` 的任务**直接拿这个返回值当自己的睡眠时间**（`esp_lvgl_port.c:198-206`，
上限 `task_max_sleep_ms = 500ms`）。

⇒ 一旦暂停 refresh timer，息屏时屏幕上只剩 `watch_clock` 的 1 秒定时器 → LVGL 任务
**每 500ms 才醒一次** → 三个真实后果：

| # | 后果 |
|---|---|
| 1 | **闹钟响铃迟到**：`alert_pump()`（"每 500ms 响 300ms"）跑在 LVGL 定时器上 → 最长迟 500ms 才开始响，节奏还被量化 |
| 2 | **倒计时到点迟到**：到点判定在 `clock_timer_cb()` 里 → 最长迟 500ms |
| 3 | **亮屏重画迟到**：任务睡着时没人处理 invalidate → 最长 500ms 才出画面 |

**最终做法**：`lv_timer_set_period(refr, 100)`。延迟 ≤100ms（无感），刷新相关唤醒仍从 100Hz 降到 10Hz。
**这条已写进 `power.c` 的注释并标注"别改回去"**，实机也验证了（见 §四的闹钟一项）。

> 顺带确认：`esp_lvgl_port` 的 `lvgl_port_task_wake()` 在 **LVGL8 上是空实现**
> （直接 `return ESP_ERR_NOT_SUPPORTED`），所以"暂停后用 API 把任务叫醒"这条路在本工程不可用。

### 3.2 用"期望状态 + 补做"处理拿不到锁的情况

`power_screen_off()` 是从 **esp_timer 任务**（`poll_cb`）里触发的，而改 LVGL 定时器必须先拿 LVGL 锁。
esp_timer 回调**绝对不能阻塞等锁**，所以：

```
refr_slow_request(slow) → 记下 s_refr_slow → refr_apply()
   └─ bsp_display_lock(0) 失败 → 置 s_refr_pending
poll_cb 顶部：if (s_refr_pending) { refr_apply(); 若是"亮屏"那次没拿上锁 → 补整屏重画 }
```

### 3.3 学到的两条"工具事实"（都不是猜的）

1. **`lv_indev_get_read_timer()` 在这个 LVGL 里是坏的**：签名写成 `lv_disp_t*`，函数体返回
   `indev->refr_timer`（那是 display 的字段，不是 indev 的 `read_timer`）→ **用它必然拿到错指针**；
   而 `struct _lv_indev_t` 又不在公开头里。所以**放弃了"降低触摸轮询频率"这条常规路线**，
   改用 INT 门控（收益相同、不碰私有结构）。
2. **打开串口会让芯片复位**（老坑，交接文档 §1.4）→ **测"息屏时的 CPU"必须一条命令里连着发**：
   `serial_cmd.py COM24 "power off" "stats" ...`。单独敲一条 `stats` 测到的是"刚开机、亮屏"的状态
   （复位后屏幕又亮了）。这一条在本版实测时踩过一次并已纠正。

### 3.4 中文流水线真的拦住了一次

新增的串口文案里有一个「**慢**」字，`tools/check_all_literals.py` **立刻报红**
（`✗ 有 1 个字符不在字库里：慢 U+6162`）。按流水线重跑 `gen_font.ps1 -Force`
（扫描 58 个文件 → 758 个字符）→ 字库覆盖从 851 升到 **853 码点**，三连恢复全绿。
**所以本版提交里包含重新生成的字库文件**，这是预期内的。

## 五、明确**没做**的事（范围控制）

| 项 | 原因 |
|---|---|
| **IMU 降频**（息屏 50Hz → 10~25Hz） | 会破坏计步：带通系数 `k_bp[2][5]` 与 4 个 EMA alpha **全部按 50Hz 硬编码**（`qmi8658c.c:5,45-47,54-64`），`above_cnt>=3` 还是**按样本计数**（`:495`）；作者自己在 `motion.c:253-254` 写了"采样率必须和 `sample_rate_hz` 对得上，否则带通截止频率会偏，计步会忽多忽少"，而**该约束没有实现**。属**重新标定级**工程。**建议单开一版**，并优先考虑用 QMI8658C 的运动中断（INT2=GPIO38 目前空闲）而不是单纯降频。 |
| **WiFi 空闲自动断开** | ① 字面的"校时后立刻断"会**打坏天气**（连上就自动 SNTP → 断网 → 再点【获取天气】没网）；② `wifi_service` **内部没有任何周期 tick**，两个超时都是"有人调 `hook_get_status()` 时才惰性求值"，而那只在 WiFi 页打开时发生 → 朴素空闲超时**在该生效时永不触发**；③ 自动断开必须走 `s_user_disconnect = disconnect_event_expected()` 标志，否则会被判定成"连接失败"，且若 `s_conn_used_saved` 仍为真**还会删掉用户保存的密码**（`wifi_service.c:776-825`）。→ 需单独设计（引用计数 + 真正的 tick）。 |
| **面板 SLPIN（1.5 档）** | 比 DISPOFF 更深，但 IDF 的 ST7789 驱动在 `esp_lcd_panel_disp_sleep()` 内部**无条件 `vTaskDelay(100ms)`**，谁调谁阻塞 → 需要写成非阻塞状态机，且唤醒会多约 100ms 延迟。**等本档续航数据出来再决定**（用户已定）。 |
| **第二档：`CONFIG_PM_ENABLE` + DFS + light sleep** | 收益最大、风险也最高（tickless idle、给 SPI/I2C 加 PM 锁、配置触摸 INT/RTC INT 为唤醒源）。**建议单独立项**。 |
| **深睡** | = 整机重启（冷启动约 2.3 秒），只适合"主动关机/长时间不用"。 |
| 上滑入口修复 / `hint_ok_cb` UAF / 天气 epoch / 布局更正 / `check_all_literals` 扫描目录 | **都已逐行核实、写在 `doc/智能手表-v0.7.1实施文档.md` 里**，但按用户要求本版**只做省电**，这些留待下一版。其中"上滑打开控制中心在实机上不可达"已在模拟器上实测确认（见该文档 §3.1）。 |

## 八、本版本改动简单说明

**这一版没有加任何新功能，只做一件事：让"息屏"真的省电。**

以前的息屏只是**把背光关掉**——屏幕面板还在扫描、LVGL 还在每秒刷 100 次、
触摸芯片还在每秒被读 100 次、电源也不停在轮询。也就是说屏幕黑了，但里面的东西一样没少干。

现在息屏时四件事一起做：

1. **面板真的停显示**（发 ST7789 的 DISPOFF 命令），不再白扫；
2. **界面刷新从每秒 100 次降到 10 次**（不是完全停 —— 完全停会让报时、倒计时、
   闹钟"到点该响"的判断变慢最多半秒，这个坑在实施时发现并避开了）；
3. **息屏时不再白读触摸芯片**（先看中断脚：没人碰就一次 I2C 都不发）；
4. **电源轮询从每秒 20 次降到 5 次**。

顺带把游戏在"开始/暂停/结算"界面上的空转也降下来了（原来暂停着也每秒跑 30 次）。

**对你的实际影响**：息屏后的耗电应该明显下降，而**用起来完全一样**——
触摸照样一点就亮、第一下不会误触、闹钟到点照样亮屏响铃、亮起来画面照样是对的（这四条都实测过了）。

**还没做的**：更深的省电（让面板进睡眠、让 CPU 降频/轻睡）留到下一档 ——
因为那些会带来"唤醒变慢"或更高的风险，我想先看到这一档的实际省电数据再决定值不值得做。
