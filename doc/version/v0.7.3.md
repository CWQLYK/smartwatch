## 一、一句话总结

**v0.7.1 的"息屏"只做到了 `DISPOFF`（关显示输出）——面板内部的振荡器、charge pump、
源栅驱动其实还在跑。本版把它们也停掉（`SLPIN`），并给这个功能配了一个运行时开关。**

关键取舍已经写进设计：

- **代价**：进睡眠要发 `SLPIN`、唤醒要发 `SLPOUT`，而 IDF 的 ST7789 驱动**对两者都无条件阻塞 100ms**
  （`esp_lcd_panel_st7789.c:331`，已核源码）⇒ 唤醒比原来慢约 125ms；
- **因此**："何时息屏/亮屏"的触发方（esp_timer 回调、触摸回调）**只置一个"期望状态"**，
  真正阻塞的面板命令交给一个独立小任务 `pwr_sm`；
- **更关键的一条**：面板睡眠期间 **GRAM 内容不可信** ⇒ 唤醒必须**整屏重画**，
  而且**要重画完再开背光**（否则用户会看到"黑屏/白闪一下才回画面"）。

**因为收益预计只有 1~2mA、而代价是用户能感知的 125ms**，本版刻意做了运行时开关：
`power deepsleep off` 一条命令即可退回 v0.7.1 行为（同时也是回滚手段）。

## 三、关键决策与实现要点

### 3.1 为什么必须单独开一个任务

`esp_lcd_panel_disp_sleep()` 内部**无条件阻塞约 100ms**（SLPIN/SLPOUT 都一样）。
而"何时息屏"是 `poll_cb`（**esp_timer 任务**）决定的 —— esp_timer 回调里绝不能阻塞 100ms，
否则电源轮询、看门狗检查这些同样跑在 esp_timer 任务上的东西会一起被拖住。

⇒ 触发方（esp_timer 回调 / 触摸回调 / 串口）**只置期望状态**（非阻塞），
`pwr_sm` 负责真正阻塞的面板命令。

### 3.2 ★ 优先级取 3（低于 LVGL 的 4）—— 与最初方案不同，这是实施中改的

触摸唤醒是在 **LVGL 任务**里调 `power_screen_on()` 的，而那一刻 LVGL 任务**正持有 LVGL 锁**
（`lvgl_port_task` 是在持锁状态下跑 `lv_timer_handler()` 的）。

- 若状态机优先级**更高**：它会在对方持锁时抢跑去抢锁 → `lv_refr_now()` 只能靠重试等锁；
- 取**更低**：等 LVGL 处理完当前帧、**释放锁之后**才执行唤醒序列 → 同步重画一次就能拿到锁，
  也顺带避免 `SLPIN` 的 100ms 卡住界面刷新。

**实测确认**：唤醒日志里没有出现"没拿到 LVGL 锁"的兜底文案 ⇒ 一次就拿到了 ✔

### 3.3 ★ 唤醒必须"重画完再开背光"

面板睡眠期间 **GRAM 写入无效、内容不可信** ⇒ 醒来若不重画就开背光，用户会看到
"黑屏/白闪一下就回画面"。所以顺序固定为：

```
SLPOUT（阻塞 ~100ms）→ DISPON → invalidate_all() → lv_refr_now() 同步重画 → 开背光
```

代价是多花一帧（实测约 25ms），换来"**背光亮起＝画面已就绪**"。

### 3.4 状态机栈给 6KB 的依据

`lv_refr_now()` 是**真正在绘制**（和 LVGL 任务干同一件事），而 LVGL 任务的栈就是 6KB
（`bsp.c` 里 `lvgl_port_cfg.task_stack = 6*1024`）⇒ 状态机不能比它小。
实机 `taskmem` 复核：`pwr_sm` 栈余 **3244 / 6144** 字节，与 `taskLVGL` 的 3232 几乎一致 ✔

### 4.3 ⚠️ 还差最后一步：A/B 电流测量（只有使用者能做）

```
（在 USB 上先把开关设好 —— 设置在这次电池会话里一直有效，因为拔线不会重启）
① 插 USB → power deepsleep off → 拔线 → 等自动息屏 → 读万用表 mA
② 插 USB → power deepsleep on  → 拔线 → 等自动息屏 → 读万用表 mA
③ 两者之差 = SLPIN 的真实收益（预计 1~2mA）
```

配套的**手感验收**（人眼/手指）：
1. 触摸唤醒能不能接受（多约 125ms）；
2. 唤醒时**有没有黑闪/白闪**；
3. 闹钟到点仍能正常亮屏；
4. 反复 20 次息屏/唤醒不花屏。

> **如果收益只有 1mA 而手感明显变差** → `power deepsleep off` 即可退回 v0.7.1 行为，零成本。

## 五、明确**没做**的事

| 项 | 原因 |
|---|---|
| **第二档（DFS + light sleep）** | 收益最大的一档（息屏 51mA 的大头是 CPU 240MHz 双核常开 + PSRAM），但风险也最高：tickless idle、给 SPI/I2C 加 PM 锁、配置触摸 INT/RTC INT 为唤醒源。**建议单独立项**——本版已经把"深度电源状态 + 运行时开关 + 可量化 A/B 测量"这套基础设施搭好，第二档可直接复用。 |
| **更激进的深睡策略**（如"息屏 N 秒后才深睡"） | 本版按批准采用**方案 A：息屏立即深睡**。若实测觉得 125ms 手感不能接受，再切"延迟 N 秒"（改动很小：加一个定时器）。 |
| IMU 降频 / WiFi 空闲断开 | 会分别破坏计步标定与天气功能（见 v0.7.1 文档 §五）。 |
| PSRAM 配置实验 | `CONFIG_SPIRAM=y`（8MB OCT @80MHz）是潜在静态功耗来源；若确认没用到可试关，但要 clean 重编 + 全量回归，属独立实验。 |
| 长按 PWR 关机 | 属新功能（自锁生效后关机的唯一途径），待排期。 |

## 八、本版本改动简单说明

**这一版只做一件小事：让息屏时屏幕"睡得更死"一点，并且给你一个开关决定要不要留它。**

上一版（v0.7.1）的"息屏"做到了 **DISPOFF**——关闭显示输出。但面板**内部**的振荡器、
电荷泵、驱动电路其实还在工作，还在耗电。这一版再多发一条命令（`SLPIN`），
把这些也停掉，也就是真正的"面板睡眠"。

代价是**唤醒会慢大约 125 毫秒**（其中 100ms 是芯片驱动的固定等待，另外约 25ms 是
"把整屏重新画好之后再开背光"——不这么做你会看到屏幕先黑/白闪一下才出现画面）。
预计省电 **1~2mA**。

因为**收益不大、代价是能感觉到的 125ms**，这一版特意加了开关，让你自己判断值不值：

```
power deepsleep off    # 关掉（退回上一版行为，唤醒恢复原来的快）
power deepsleep on     # 打开（默认）
power status           # 能看到：功能开关 / 当前是否已睡 / 上次唤醒耗时
```

测法：在 USB 上把开关设好 → 拔线 → 等它自动息屏 → 用万用表读息屏电流；
开关 on/off 各测一次，**两个数的差就是它的真实收益**。
如果只有 1mA 左右、而你又觉得唤醒变慢了，那就关掉它 —— 一行命令的事。

**下一步建议做的**：真正的大头是**第二档**（CPU 降频 / 轻睡眠）。
息屏还剩 51mA，主要都花在"CPU 一直跑在 240MHz 双核"上。这一版把台子搭好了，
第二档可以直接在这上面做 —— 那一档有望把 51mA 压到 15~25mA。
