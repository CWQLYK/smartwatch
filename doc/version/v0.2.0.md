## 一、这一版的核心动作：从单体到分层

v0.1.0 的问题是**260 行 `main.c` 打天下**。这一版把它拆成
**14 个自建组件、5 个层次**：

```
main.c（30 行）→ app（装配 + 命令行）
                    ├─ watch_ui_pages ─ watch_ui ─ ui_port ─┐
                    ├─ data_hub ─ rtc_pcf85063 / battery    │
                    └─ settings / event_bus / buzzer        │
                                        bsp ─ board ◀────────┘
```

### 三条关键设计决策（后面几版都靠它们省事）

#### 1. 共享 I2C 总线的所有权收进 `board` 组件

板上触摸(0x15) / IMU(0x6B) / RTC(0x51) **共用一条 I2C**。
v0.1.0 里 BSP 持有总线，导致 RTC 驱动要读寄存器就得反向依赖 BSP —— 依赖方向错了。

现在 `board` 是总线的**所有者**，`bsp` 和 `rtc_pcf85063` 都是**使用方**，平级。

#### 2. `data_hub` 作为"设备状态唯一真相"

1Hz 采时间、30s 采电量，带锁快照 + 变更回调：

```
rtc / battery ──周期采样──▶ data_hub ──┬─▶ 事件总线（给非 UI 订阅者）
                                       └─▶ 变更回调（给 UI）
```

好处：
- **界面不阻塞**（ADC 采样要 ~10ms，I2C 会抖动；让 UI 主动读就会卡）
- **一致性**（表盘同时显示时间/电量，分开读会读到不同时刻的值）
- 以后 BLE 上报、AI 语音查数据订阅同一个源

#### 3. `watch_ui` / `watch_ui_pages` 零 ESP-IDF 依赖

靠 `ui_port` 端口层（加锁/显示/主循环）+ PC 垫片（`esp_err/log/check` 的假实现），
**同一份界面源码**既能跑实机也能跑 PC 模拟器。

> 这条在 v0.3.0 加计步时立刻回本了：新增 IMU 数据后**界面代码一行没改**
> 就显示出了真实步数。

## 二、新增组件（14 个）

| 组件 | 职责 | 关键接口 |
|---|---|---|
| `board` | **全项目唯一**知道 GPIO 号和 I2C 地址的地方；持有共享 I2C 总线 | `board_init()`、`board_i2c_read_reg()` |
| `bsp` | LCD / 触摸 / 背光 / LVGL 移植层 | `bsp_init()`、`bsp_display_lock()` |
| `rtc_pcf85063` | PCF85063 驱动：BCD ↔ 日历 ↔ Unix 时间戳，掉电检测 | `rtc_pcf_init()`、`rtc_pcf_time_lost()` |
| `battery` | GPIO1 ADC + **曲线拟合校准** + 中值滤波 + 电压→电量曲线 | `battery_read()` |
| `buzzer` | GPIO42 LEDC 单音 + **非阻塞**音序器（esp_timer 状态机） | `buzzer_beep()` |
| `event_bus` | 发布/订阅，解耦生产者与消费者 | `event_bus_subscribe()` |
| `settings` | 9 项可持久化配置，**表驱动**，存 NVS | `settings_get/set()` |
| `data_hub` | 设备状态快照 + 变化通知 | `data_hub_snapshot()` |
| `ui_port` | 平台差异隔离（实机 / PC 两套实现） | `ui_port_lock()` |
| `fonts` | 生成的中文字库 + 字号查表 | `watch_font_cn(16)` |
| `watch_ui` | 主题令牌、公共控件、页面栈、手势 | `watch_ui_init()`、`watch_page_t` |
| `watch_ui_pages` | 4 个页面 + 中文文案总表 | `watch_pages_all()` |
| `app` | 装配层 + 串口命令行 | `app_start()` |

## 四、附带完成的东西

### 1. 中文字库流水线（`tools/gen_font.ps1`）

全量 CJK 字库有几十 MB，Flash 装不下，必须按需抽字。
脚本自动扫源码抽字 → 调 `lv_font_conv` 生成 14/16/20 三档。

加中文的流程：**写进 `watch_strings.h` → 跑脚本 → 完成**。

> ⚠️ 生成时必须加 `--no-compress`：LVGL 8.x 读不了压缩位图，
> 症状是"字形查得到、宽度正常，但屏幕上是豆腐块"。

### 2. 串口命令行（P1 唯一的校时入口）

RTC 没有备份电池（见第六节），每次上电都要校时，所以必须有这个口子。

| 命令 | 作用 |
|---|---|
| `set_time 2026-10-06 14:30:00` | 按墙上时间校时 |
| `time` / `battery` / `status` / `settings` | 查状态 |
| `brightness 60` | 调亮度（写 NVS） |

### 3. PC 模拟器共用界面代码

`lvgl_sim/` 直接引用固件的 `components/watch_ui*`，改界面几秒就能看效果，
不用烧板子。加了 `pc_shim/` 提供 `esp_err/log/check` 的假实现。

### 4. 校验工具

- `check_fonts.py` —— 找"ASCII 字体 + 中文文案"的豆腐块隐患

## 五、这一版踩的坑（8 个）

> 完整版见 `../../../../doc/代码架构说明.md` 第六章。这里是新增的。

| # | 坑 | 症状 | 解决 |
|---|---|---|---|
| 7 | **控制台必须走 USB-Serial-JTAG，不是 UART0** | 板子能跑但串口**全黑**，像死机；`idf.py monitor` 全黑 | 这块板 Type-C 直接接 ESP32-S3 原生 USB（Windows 认成 `USB JTAG/serial debug unit`），UART0 只引到扩展口没接出来。改 `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y` |
| 8 | 二级 console 开着会崩在启动阶段 | `console.common: set max history length to 0 failed` 后 `Guru Meditation`，无限重启 | 默认开的 `SECONDARY_USB_SERIAL_JTAG` 从没装驱动。改 `SECONDARY_NONE=y` |
| 9 | `rtc.h` / `rtc_init` 与 ESP-IDF 撞名 | 链接期 `multiple definition of 'rtc_init'`，first defined in `esp_hw_support/.../rtc_init.c` | ESP-IDF 已有 `soc/rtc.h`（废弃）和内部 `rtc_init()`。组件改名 `rtc_pcf85063`，函数加 `rtc_pcf_` 前缀。**教训：驱动组件名要带芯片型号** |
| 10 | 颜色宏不能取地址 | `error: lvalue required as unary '&' operand` 报一整片 | `W_COLOR_TEXT` 是函数式宏不是变量。控件工厂的颜色参数改成**值传递**，用 `W_COLOR_AUTO` 当哨兵 |
| 11 | CMake 不支持反斜杠续行 | `Parse error. Function missing ending ")". Instead found bad character with text "\"` | `idf_component_register()` 参数一行写完 |
| 12 | **中文字库漏字（最隐蔽）** | 编译运行都不报错，屏幕上某一个字是豆腐块 | 见下 |
| 13 | Win32 模拟器必须先 `lv_init()` | 不报错、不崩溃、**窗口也不出来**，进程挂着 | `lv_win32_init()` 内部要调 `lv_disp_drv_register()`，卡在等窗口就绪事件上。另外它的后两个参数是**分辨率**不是缩放倍数 |
| 14 | GUI 子系统程序的 printf 看不到 | 日志全丢 | MinGW 链接的 GUI 程序 stdout 不接控制台且全缓冲。用 `> log.txt 2>&1`，并在 `main()` 开头 `setvbuf(..., _IONBF, 0)` |

### 坑 12 详述：中文字库漏字

**三个实例**：

| 漏的字 | 原因 |
|---|---|
| 年、月 | 写在 `watch_page_home.c` 的格式串 `"%d年%d月%d日"` 里，而生成脚本只扫 `watch_strings.h` |
| `·`(U+00B7) | 字库只含 **ASCII + 源码里的 CJK**，U+00B7 两边都不沾 |

**当时的解决办法**（v0.3.0 又加了根治手段）：
1. 生成脚本扫描范围扩到 `watch_ui` / `watch_ui_pages` / `app` 下所有 `.c`/`.h`
2. 日期这类格式化用字，统一写成 `W_STR_DATE_FMT` 放进 `watch_strings.h`
3. 非汉字字符（分隔符、单位）**优先用 ASCII**

## 六、实测确认的硬件事实（很重要）

| 疑点 | 实测结论 |
|---|---|
| **RTC 有没有备份电池** | **没有**。断电后 OSF 停振标志置位，时间丢失，必须重新校时。原理图只接了 32.768kHz 晶振 |
| 板载 Flash 多大 | **16MB**（官方示例写的 4MB 是错的） |
| I2C 上三个器件 | 触摸 0x15 / IMU 0x6B / RTC 0x51 **全部在**，400kHz 正常 |
| PSRAM | 8MB Octal，80MHz，`SPI SRAM memory test OK` |
| PCF85063 芯片温度 | **读不到**（0x0B/0x0C 恒为 0x80/0x80）。驱动返回 `ESP_ERR_NOT_SUPPORTED`，不误导上层 |
| 电池 ADC | 4113 mV / 94%，曲线拟合校准生效 |
| COM24 是什么 | **ESP32-S3 原生 USB-Serial-JTAG**，不是 UART 桥（这条直接引出了坑 7） |

> **RTC 无备份电池**这条影响很大：它让 P2 的 BLE 校时从"锦上添花"变成**必需功能**。
