## 三、游戏是怎么搭起来的（分层）

### 3.1 为什么游戏**不能**做成轮播页

轮播页是"同一个 screen 里并排的三个槽位"，而**每次换页都会把三个槽位整个
`lv_obj_del_async` 掉重建**（`watch_pages.c` 的 `slot_build`/`slot_destroy`）。
游戏状态挂在页面上的话，手指一滑整局就没了。

所以游戏层和模态子页（`watch_modal.c`）、到点提醒层（`watch_alert.c`）一样，
是**轮播 screen 上的兄弟容器**：

```
screen
├── 轮播视口 s_vp（3 个页面槽）
├── 模态子页栈（设置 / 时钟 / WiFi / 游戏列表 …）
├── 到点提醒层（闹钟要盖住一切）
└── ★ 游戏层（打开时 move_foreground 置顶）
```

**顺带白拿一个好处**：它天然挡住所有滑动和手势。
LVGL 命中测试取最上层可点击对象，游戏层满屏且 `CLICKABLE`，
手指事件根本到不了轮播视口；手势层（`watch_gesture`）挂在更下层的页面根上，
也收不到事件。所以"玩游戏时不能左右滑切页 / 上滑开控制中心"
**一行手势代码都不用改**。

### 3.2 宿主 vs 本体（加第二个游戏要动哪里）

| 层 | 文件 | 职责 |
|---|---|---|
| **宿主**（可复用外壳） | `watch_ui/watch_game.c` | 全屏层、33ms 帧定时器、触摸转发、开始/暂停/结束面板、最高分读写、防息屏、闹钟自动暂停 |
| **游戏本体** | `watch_ui_pages/games/dino_game.c` | 物理、碰撞、障碍生成、画到画布 |
| 精灵数据 | `watch_ui_pages/games/dino_sprites.c` | 脚本生成的位图（不手改） |
| 游戏列表 | `watch_ui_pages/pages/watch_page_games.c` | 列表 + 注册表 |

游戏本体只实现 `w_game_t` 里那几个回调（init/reset/step/render/input/score/over/dirty_top/destroy）。

**加一款新游戏 = 写一个文件 + 在 `k_games[]` 里加一行**（要存最高分再多一个设置项键名）。
外壳、暂停菜单、结算面板、防息屏、闹钟联动全是白送的。

### 3.3 画布：为什么是 2bpp 索引图 + 只刷脏带

**硬约束**：LCD 走 SPI 40MHz，16bpp 下有效带宽约 5MB/s。
整屏 240x280 = 134KB，刷一次要 **27ms** —— 只剩 37FPS，没有余量。

做法：

| 项 | 做法 |
|---|---|
| 画布 | `lv_canvas` + `LV_IMG_CF_INDEXED_2BIT`（4 色：底色 / 前景 / 地面云 / 强调），**240x280 = 16.8KB**（+16 字节调色板） |
| 每帧绘制 | 直接拿位图指针按位写（`watch_gfx.c`）：`memset` 清 16.8KB + 约 1 万次像素写 ≈ **0.8ms**。不走 `lv_canvas_set_px()`（每像素都要重算描述符，6.7 万次调用纯开销） |
| 每帧刷新 | 只 `lv_obj_invalidate_area()` **下面那条会动的带子**（`dirty_top()` 返回所有活动精灵里最高的顶边）。HUD 在带子之上，只有分数变了才重画 |
| 帧率 | 33ms（30FPS），物理按**实测 dt** 积分 |

### 3.4 精灵从哪来

`tools/gen_dino_sprites.py`（新工具）从参考工程的 `sprite01.png` 里抠图：

* 源图是**Chrome 原版离线精灵表的 2 倍图**（2441x130，8 位调色板 PNG）
* **隔点取样折半**得到 1x —— 不能缩放，一缩放像素画立刻出毛边
* 输出 13 个精灵共 **6888 字节**的 2bpp 位图（恐龙 5 帧、仙人掌 4 种、翼龙 2 帧、云、1200x10 地面条）

工具里写了三个必须知道的坑（都踩过）：

1. **不能用 alpha 判形状**：精灵是画在**不透明白色卡片**上的，alpha 全是 255，
   按"不透明"取形状会取到整张白卡片。必须按**亮度**取墨色
   （云是浅灰 luma≈218，阈值要单独放宽到 230，否则整朵云消失）。
2. **包围盒里可能混进别的墨团**：站立恐龙脚下压着地面的小石子和横线，
   它们和恐龙不相连但落在同一个矩形里 —— 只按矩形裁的话，恐龙脚边会飘两颗黑点
   （放大才看得出来）。所以裁剪必须按"种子点所在那一团"取。
3. **裁剪框越界要当错误报出来**：第一版翼龙的框算出了 `y=-4`，
   而 Python 的负索引会**静默绕到图片末尾**读数据，生成一堆垃圾点阵且不报错。
   现在有越界断言。

**版权**：精灵图来自 Chromium 的离线小恐龙（BSD-3-Clause），
生成物头部写明了来源。自己戴的表不商用没问题，对外发布要保留这段声明。

⚠️ 参考工程在 `相关资料/`，**不在 git 仓库里**。所以**生成物 `.c` 提交进仓库**，
构建永远不依赖那个目录；脚本找不到源图时明确报错，不会生成空表。

## 四、🔴 用户实测报的问题：列表滑动后误进了选项（本次修复）

### 4.1 症状（用户原话）

> "在列表上下滑动的过程中，滑动后会误触到其中一个选项，
>  例如我从上往下滑动时手指是触到时钟，滑动后就进入到了时钟页面。"

也就是说：**列表确实滑动了，但抬手时又把手指停住的那一行当成点击**，直接进了子页。

### 4.2 根因（对着 LVGL 源码看的，不是猜的）

`lv_indev.c` 的 `indev_proc_release()`：

```c
lv_event_send(indev_obj_act, LV_EVENT_RELEASED, indev_act);
if(scroll_obj == NULL) {                 // ← 判据在这里
    lv_event_send(..., LV_EVENT_SHORT_CLICKED, ...);
    lv_event_send(..., LV_EVENT_CLICKED, ...);
}
```

LVGL 判"这次按下有没有变成滚动"（`scroll_obj`），是滚动就不发点击 ——
**但轮播页的纵向滚动是本项目手写的**（`watch_pages.c` 的 `scroll_page_by`，
理由是"页面根一旦可滚动，上滑开控制中心就失效"，见那里的长注释）。

于是：在 LVGL 眼里 `scroll_obj` **永远是 NULL**，
它那套"滚动就不发点击"的机制对我们**完全不生效** ——
滚动照做、CLICKED 照发。

**为什么只有功能列表页中招**：其余列表（设置/开发人员/游戏列表/WiFi）
都在**模态子页**里，模态是**原生滚动**（`watch_modal.c` 里
`lv_obj_set_scroll_dir(page, LV_DIR_VER)` + SCROLLABLE），
LVGL 自己就把 `scroll_obj` 设上了、点击本来就会被它拦掉。
只有轮播页（功能列表）用的是手写滚动。

### 4.3 修法：手势层自己记"这次触摸变成了拖动"

1. `watch_pages.c` 的拖动处理里，记录**过程中出现过的最大位移**，
   超过 10px（LVGL 自己的默认滚动阈值 `LV_INDEV_DEF_SCROLL_LIMIT`）
   就调 `w_touch_mark_drag()`。
2. `w_menu_row_create()` 建出来的行自带**点击守卫**：
   收到 CLICKED 时先查这个标记，是拖动就丢掉（业务回调挂在 user_data 里，
   守卫替它转发）。
3. `w_btn_create()` 也加上同一个守卫 —— 万一以后在轮播页上放按钮，
   不会重新踩一遍这个坑。

**两个必须注意的点**（否则修不干净）：

* **要用"过程中出现过的最大位移"，不能用"抬手时相对起点的位移"**：
  用户往下拖 60px 滑列表、再往回拖到起点附近才松手的话，
  后者算出来是 0，照样被当成点击。
* **标记必须在抬手之后「异步」清除**：
  LVGL 的事件顺序是 `RELEASED → SHORT_CLICKED → CLICKED`，
  在 `RELEASED` 里直接清的话，紧接着那个 CLICKED 读到的就是"没拖动过"，
  守卫白加。所以用 `lv_async_call()` 推迟到同一次 `lv_timer_handler` 的后面清。
  不清也不行 —— 残留的标记会把**下一次正常点击吞掉**。

### 4.4 回归自检（模拟器里把用户的动作原样做一遍）

用户报的这个场景无法用静态检查发现，所以加了 4 条断言
（走的是**和真手指完全相同**的处理函数 `drag_begin/drag_move/drag_end`，
不是另抄一份逻辑 —— 模拟器没法真的注入触摸事件，只能把处理函数体暴露出来）：

```
功能列表结构  子对象 2，列表行 5  OK
点一下「时钟」 模态深度=1  OK（正常进页）
拖动后抬手    列表滚到 60（原 0） OK，标记=已置位，模态深度=0  OK（滚了列表但没误进页面）
标记已自动清除 是  OK（下次点击不受影响）
再点一次     模态深度=1  OK（恢复正常）
```

第 3 条是核心：**往上划 60px（列表真的从 0 滚到 60）+ 抬手时补一个
LVGL 真实会发的 CLICKED → 那一行必须毫无反应**。

## 五、🔴 自检抓出来的另一个真问题：障碍**数学上跳不过去**

这一版最值得写下来的东西。

### 5.1 症状

模拟器里的"机器玩家"（固定随机种子 + 每帧手动推进 + 一条固定起跳规则）
在 **3 秒**就撞死了，速度才 110px/s。

### 5.2 根因：跳跃弧线和障碍宽度之间有一条约束链

能不能跳过一个障碍，取决于：

```
脚底高于障碍的时长  ≥  障碍从"碰到恐龙"到"离开恐龙"的时长

左边 = 2*sqrt(v0² - 2gh)/g      （抛物线高于 h 的那一段）
右边 = (障碍宽 + 恐龙碰撞盒宽) / 速度
```

第一版参数 `v0=520, g=2000`：高于 46px 的仙人掌只有 **0.32s**；
而单株大仙人掌通过恐龙身位要 **0.5s**。
**右边比左边大 —— 物理上不可能跳过去**，跟操作没关系。

**为什么人肉试玩查不出来**：实机上只会觉得"这游戏好难 / 我手残"，
根本不会想到是参数关系错了。是自检里的机器玩家把它逼出来的。

### 5.3 修法（两层，缺一不可）

**第一层：把参数调到有意义的余量**

| 参数 | 旧 | 新 | 说明 |
|---|---|---|---|
| 重力 g | 2000 | **1250** | 滞空从 0.52s 拉到 0.85s |
| 初速 v0 | 520 | **530** | 最高点 112px |
| 起始速度 | 110 | **190** | 太慢则"通过身位"要很久，宽障碍必死 |
| 封顶速度 | 260 | **320** | |
| 松手截断 | 0.40 | **0.80** | 旧值点一下只能跳 16px，**连小仙人掌都过不去** |
| 障碍间隔 | 1.0~2.3s | **1.45~2.55s** | 必须大于滞空 0.85s + 落地反应时间 |

**第二层：生成障碍时按当前速度反推宽度上限**（把"余量"变成硬保证）

```c
allowed = 0.75 * air_time_above(仙人掌高) * 当前速度 - 恐龙碰撞盒宽;
max_copies = clamp(allowed / 单株宽, 1, 3);
```

于是：**低速只会出单株/两株，高速才可能出三株** ——
难度随速度自然长起来，而且**永远不可能生成一个跳不过去的组合**。
这条不变式是可断言的：一旦越界就累加 `s_unfair_spawns`，
自检断言它必须是 0。

### 5.4 修完的结果

```
机器玩家      4000 帧（132 秒）得分 4290，最高速度 320  OK（没死）
速度爬到封顶  320 / 320  OK
跳不过去的障碍 0 次  OK（每个障碍都在跳跃能力内）
```

机器玩家的打法**完全照人类来**：障碍进入"速度 x 0.28"就起跳、
按住 12 帧（约 0.4s）再松手（人跳的时候也是按住的）。
它没有任何"预知未来"的作弊手段 —— 它能活下来，就说明这套参数人类也能活。

## 六、这一版踩的坑（新增 13 个）

### 6.1 🔴 用 PowerShell 回写源码，把整个文件压成了一行

* **干了什么**：用 `(Get-Content) -replace ... | Set-Content -NoNewline` 改一个常量。
  `Set-Content` 收到的是**字符串数组**，`-NoNewline` 让它把数组直接拼起来 ——
  换行全没了，`sim_main.c` 变成 1 行 53KB。
* **为什么危险**：文件**能编译**（C 不在乎空白），肉眼也看不出问题，
  直到某天看 diff 或者改一行才发现整个文件"全变了"。
* **怎么救的**：写了个带词法分析的 `reflow.py` 重新分行 ——
  只在**字符串 / 字符字面量 / 注释之外**插换行（否则会把 `printf("a;b")` 里的分号当语句结尾），
  预处理指令按已知形态切（`#include <...>` 遇到 `>` 结束）。
  救回来了，但格式不如手写的整齐。
* **规矩**：**永远不要用 shell 管道/`Set-Content` 改源码文件**。
  要改就用编辑工具，或者写 Python 脚本用 `encoding='utf-8', newline='\n'`。
  （v0.5.0 已经因为 PowerShell 5.1 的 ANSI 编码毁过一个 `.c` 文件，这是第二次。）

### 6.2 `lv_obj_set_size()` 之后调色板被抹掉不会报错

`lv_canvas` 的 2bpp 缓冲区**头 16 字节是调色板**（4 项 x `lv_color32_t`）。
`w_gfx_clear()` 如果从缓冲区第 0 字节开始 `memset`，会把调色板一起填掉 ——
**不报错、不崩溃，整幅画变成全黑**。
所以 `watch_gfx.c` 里"跳过 16 字节"只算一次（`w_gfx_init`），别处一律用 `g->px`。

### 6.3 `lv_canvas_set_palette()` 必须在 `set_buffer()` **之后**调

调色板是写进那块缓冲区的，顺序反了就白设。

### 6.4 `watch_ui_goto(n)` **一次只翻一页**

源码里写了"跨多页请多调几次"，我传 3 却只翻了一页。
后果极具迷惑性：`watch_ui_current()`（读 `s_cur`，切页时立刻变）说"functions"，
而**槽位里的页对象还是首页**（要等吸附动画跑完 `rebuild_window()` 才换）——
于是量出来"可滚 0 px"，我差点去查一个根本不存在的布局 bug。
→ 自检里改用一页一页翻 + 断言真的到了目标页，并加了整树诊断 `sim_dump_tree()`。

### 6.5 `ui_port_run(N)` 不是"跑 N 毫秒"

它的实现是"**调一次** `lv_timer_handler()` 然后 `Sleep(N)`"。
所以 `ui_port_run(300)` 只产生**一次** LVGL 心跳，中间 300ms 是睡过去的。
而轮播切页要等吸附动画跑完 —— 动画要的是"多次心跳推进时间"。
实测卡在 **233/240（97%）**，槽位里还是上一页。
→ 加了 `sim_run_ms(ms)`：按 10ms 切成很多次心跳。**这才是"等 N 毫秒"的正确写法。**

### 6.6 自检基线取错了地方（假泄漏）

我把"对象数/定时器数/防息屏引用"的基线取在**游戏已经开着**的代码块里，
退出后再比一次 —— 当然"少了一堆对象"，自检报了个假泄漏。基线必须在**开之前**取。

### 6.7 数对象要**在同一页**数

轮播三个槽位放的是"当前页 + 左右邻居"，而各页面的子对象数差别很大
（首页 10、健康页 4、功能列表 2）。在首页取基线、在功能列表页复测，
差 2 个对象纯属页面构成不同 —— 又被误报成泄漏。
→ 复测前先 `sim_goto_page(0)` 回到同一页。

### 6.8 `lv_obj_scroll_by_bounded(0, dy)` 的 dy 是"手指位移"语义

`dy < 0`（手指上划）才看得到下面的内容；传正值会被夹在顶部，纹丝不动。
我在自检里传了正值 → 报"没滚动"。
（顺带：这个函数的调试口返回的应该是**剩余距离**而不是"总范围"——
`current_page_scroll_range()` 算的是 top+bottom，滚到底了它还是 60 而不是 0。）

### 6.9 `const` 结构体不能在定义之后再"补"成员

我第一版在 `dino_game` 结构体初始化里把 `.score`/`.over` 留成 NULL，
下面写了句注释"下面补"，然后定义了两个函数 —— 但那两个函数**根本没接进去**。
后果：宿主跳过结束判定，**游戏永远不会结束**。
`const` 对象一旦定义就没法再改，函数必须定义在结构体**之前**。

### 6.10 ESP_LOG 的格式串写错（`%.0fx%d` 把 x 当成了转换符）

想让日志输出"23x46"，写成了 `"速度为 %.0f 时 %.0fx%d 的障碍…"` ——
那个 `x` 是字面量，但旁边正好有 `%.0f`，于是参数类型对不上，
编译器只给警告（不是错误），日志里打出一堆垃圾数字。

### 6.11 每帧扫描整幅画布统计像素

`dino_debug_ink_pixels()` 第一版写在 `render()` 里，每帧扫 6.7 万像素。
自检用的东西绝不能进每帧路径 —— 改成按需调用。

### 6.12 字库生成器默认**跳过**已存在的产物

`gen_font.ps1` 不带 `-Force` 时会打印"14px 已存在，跳过"然后**什么都不做**，
但扫描阶段照样打印"得到 662 个汉字"，看起来像成功了。
症状：新加的中文全是豆腐块。**改完中文必须 `-Force`。**

### 6.13 🔴 手写滚动 → LVGL 不知道"发生了滚动" → 抬手照样发点击

* **症状**：功能列表上下滑动之后，抬手把手指停住的那一行当成点击，直接进了子页
  （用户实测报的，完整分析见第四节）。
* **根因**：LVGL 在 `indev_proc_release()` 里用 `scroll_obj == NULL` 判"这次算不算点击"。
  而本项目轮播页的纵向滚动是**手写**的（为了保住"上滑开控制中心"），
  LVGL 的 `scroll_obj` 一直是 NULL —— **它那套防误触机制对这条路径完全不生效**。
* **教训（比这个 bug 本身重要）**：
  **凡是绕开框架自己实现的机制，都要把框架顺带提供的那部分能力一并补上。**
  这里绕开的是"滚动"，顺带丢掉的是"滚动时不发点击"；
  同一笔账里还欠着"惯性"和"回弹"（框架白送的，目前都没做）。
* **修法与回归自检**见第四节。

## 九、⚠️ 已知局限

1. **功能列表变成可滚动的副作用**：页面内容溢出后，纵向拖动优先给"滚页面"，
   所以**在这一页上滑不再能打开控制中心**（其余 3 页不受影响）。
   这是滚动方案的必然代价。
2. **手写滚动没有惯性和回弹**：轮播页的滚动是本项目自己实现的
   （理由同上一条），所以松手后不会"滑一段再停"，也不会有拉到头的回弹效果。
   框架原生滚动是白送的这两样。以后要补，得自己写速度预测 + 缓动。
3. **第 5 行「游戏」要滑一下才看得到**（用户明确选择了 5 行 + 滑动，而不是压缩行高）。
4. **没有音效**（用户明确不要）。真要加，跳跃/得分/撞击三个短音
   加起来不到 20 行 —— 但**蜂鸣器是单音喇叭**，做不出原版音效。
5. **没有下蹲、没有难度选择、没有昼夜切换**（都是用户明确砍掉的）。
6. **翼龙不会造成威胁**：它按用户要求"改成不用躲"，
   所以现在只是"会扇翅膀的高空装饰"，没有碰撞盒。
7. **一局最多 99999 分**（HUD 是 5 位补零）。
8. **游戏只有一款**。列表页已经按"多款游戏"设计好（`k_games[]` 加一行即可），
   但第二款游戏本身还没做。
9. 精灵图**依赖 `相关资料/` 里那个参考工程**才能重新生成；
   生成物已入库，所以正常构建不受影响，但换机器重新生成精灵时需要把那个目录一起带上。

## 十、本版本改动简单说明

> （给不看代码的人）

**这一版加了个游戏。**

在"功能列表"里往下滑一下，最下面多了一行**「游戏」**。点进去是游戏列表，
现在里面有一款**「小恐龙」**（就是断网时谷歌浏览器里那只恐龙）。
点它就开始玩：

* **点屏幕任意处 = 跳**。想跳高一点就**按住不放**，点一下就松只能小跳。
* 天上飞的翼龙不会撞到你，只是好看。
* 左上角有个**暂停**按钮，可以继续、重新开始或者退出。
* 撞到仙人掌就结束，会显示这一局多少分、历史最高多少分。
  **最高分会存下来，关机也不会丢。**
* 玩游戏的时候**屏幕不会自动熄灭**；如果闹钟或倒计时到点了，
  游戏会**自动暂停**并弹出提醒，处理完再点继续。

分数越跑越快：一开始障碍来得慢，分数高了之后仙人掌会成排出现、速度也更快。
（这些难度参数是拿"机器玩家"在电脑上试出来的：它用和人一样的打法连续跑了
两分多钟都没死，所以这个难度人是能玩的。）

**另外修了一个问题**：在"功能列表"里上下滑动的时候，以前松开手指会**误进**
手指停住的那一行（比如滑动时手指停在「时钟」上，一松手就进了时钟页）。
现在滑动之后松手不会再误进，只有真正的"点一下"才会进。
