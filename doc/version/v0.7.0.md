## 三、实施中的偏离与"意外收获"

### 3.1 计算器：**先写测试向量再做界面**，当场抓出两个真 bug

引擎（`calc_engine.c`）是纯函数，所以先把 34 条向量写完再写界面。
结果第一次跑就红了 21 条，全是"算出天文数字"：

1. **漏了 `#include <stdlib.h>`** → `strtod` 被隐式声明成返回 `int`，
   **double 的位模式被截断**。编译只有一条 warning，运行结果全是 1e+14 那种数。
2. `%` 的 token 索引没前进 + 前导运算符取错栈 → `100-10%` 算成 99.9。

> 如果先做界面、靠"手点几下看对不对"，这两个 bug 会以
> "算出来的数看着不对"的形式藏很久，而且很难定位。

**决策**：`%` 按**商用计算器语义**（`100-10%` = 90、`50%` = 0.5），
不是参考工程那种"一律除以 100"（它算出 99.9）。

### 3.2 toast：纠正了一条流传在项目里的错误结论

`watch_overlay.c` 的文件头写着"`lv_layer_top()` 一旦可点击就会吞掉整屏触摸"，
所以过去一直避开 layer_top。翻源码发现**归因错了**：

```
lv_hal_disp.c:225-230
    lv_obj_clear_flag(disp->top_layer, LV_OBJ_FLAG_CLICKABLE);   ← LVGL 自己清了
```

真正吞触摸的是**建在它上面的默认尺寸子容器**（`lv_obj_create(NULL)`
默认满屏 + 可点击）。所以 toast 用 layer_top 是对的，代价只是
**建完立刻清自己容器的 CLICKABLE**。这条更正写进了 `watch_toast.h`。

### 3.3 toast 的一个设计决定：**对象常驻、永不删除**

参考工程的提示条是"每次显示新建对象、离场动画 `ready_cb` 里删对象"，
它因此在**离场那 200ms 窗口**里有个真 bug：这段内再来一条提示，
文字改了但定时器空转、也没反向滑入动画，**而已在跑的离场动画照样删容器**
→ 新提示一闪即逝、状态归零。

我们改成单例常驻 + 显式状态机（`IDLE/SHOWING/HOLDING/HIDING`），
滑出中途重入就**反向滑回**。这样从结构上没有删除、没有 UAF、
没有"清理只挂 `ready_cb` 不可靠"这一类问题。自检里专门有一条断言守着。

### 3.4 截图抓到 3 个"断言全过但画面是错的"问题

这三个都是**状态类断言抓不到**的，只能看图：

| 现象 | 根因 |
|---|---|
| toast 药丸被压成 **15px 宽的竖条** | `LV_SIZE_CONTENT` 父容器 + `LV_PCT(100)` 子标签 → 尺寸计算退化 |
| toast 位移动画永远停在 `y=-35` | 用 `lv_obj_set_y()` 会被**布局重算覆盖** → 改用 `translate_y`（样式属性，不参与布局） |
| 计算器键盘整块**不渲染** | 模态内容区高度是 `LV_SIZE_CONTENT`，里面用 `LV_PCT(100)`/`flex_grow` 算成 0 高 → 改显式像素高度 |

### 3.5 计算器键盘：两处 LVGL 隐式约定（都踩了）

1. **`lv_btnmatrix` 的行分隔符是单独的 `"\n"` 元素**
   （`lv_btnmatrix.c:130` 靠 `strcmp(map_row[i], "\n") == 0` 判断行结束）。
   我按"每 3 个一格、空串结尾"写 → 整张表被当成**一行 18 键**，
   屏幕上文字连成一排、18 根竖条。
2. `set_btn_width()` 每次调用都会**重跑整张 map**（参考工程有个 20 次循环，
   纯浪费）—— 我们直接不调。

另外键下标算成 `(ROWS-2)*COLS+2 = 17`，而**17 正好是 `+` 键**
→ 按 `+` 变成退格。自检当场报出来了。

### 3.6 日历：年份下拉显示 1901（根因很隐蔽）

LVGL 默认年份表是**降序**的 `"2023\n2022\n...\n1901"`（顶年只到 2023），
而头部同步算法是 `sel = 列表首项 - showed_year`：

```
2023 - 2026 = -3  →  赋给 uint16_t 下溢  →  被钳到末项 = 1901
```

**8.4 才提供 `lv_calendar_header_dropdown_set_year_list()`**，
所以设备端（8.4）换成自有的"2030→1990"表就正常了；
**模拟器那份是 8.3、连实现都没有**，PC 上复现不了 —— 这一条只能实机看。

> 中途我还被一张**过期截图**误导过一次（那次自检失败没重新生成图）。
> 教训：看图前先确认文件时间戳。

### 3.7 2048：动画当数据，不建 LVGL 动画对象

参考工程用 16 个格子的 `lv_anim` 做移动/合并，退出时要靠父容器被删才回收。
我们**把动画当数据**：每格存 `{from_r, from_c}`，`step()` 插值、`render()` 一次画完。
于是"重开一局 / 退出"就是 `memset` 一块结构体 —— **零清理、零悬空回调**。

数字也是画布上自绘的（3×5 点阵字模），因为画布是 2bpp 四色、没有字体。
实测 2~32768 在 44px 格子里都清晰。

### 3.8 WiFi 多槽位：先修地雷，再扩槽

动手前先修了 `creds_erase()` 的 `nvs_erase_all` ——
扩成 5 槽之后，**任何一次认证失败会把家里/公司/热点全删掉**。
现在分三个粒度：

| 函数 | 用在哪 | 粒度 |
|---|---|---|
| `creds_erase_ssid(ssid)` | 认证失败自愈、`hook_forget` | **只删那一个网** |
| `creds_erase_all_slots()` | 用户主动"重置 WiFi" | 删全部槽，但**保留** `slot_cnt`/`last_ok` |
| `creds_save()` | 连接成功落盘 | 同名更新 / 占空槽 / 满则覆盖非 `last_ok` 的槽 |

**向后兼容**：旧键 `ssid`/`pass` 保留，首启（`slot_cnt` 不存在时）自动迁进槽 1。
`last_ok` 记"上次连上的槽"，开机优先试它而不是死板按槽号顺序。

### 3.9 天气：比参考工程好的四处

| 参考工程 | 问题 | 我们 |
|---|---|---|
| 缓存过期用 `"MM/DD"` **字符串比较** | **跨月出错**（3 月初拿 2 月数据） | 存 `fetched_epoch` |
| 图标是 10 张 100×100 RGB565 = **200KB** | flash 占用巨大 | **图元自绘**（7 类，零资源） |
| `is_day` 恒传 1 | 夜间图标**从未被使用** | 图元组合，天然可分昼夜 |
| 无加载/失败反馈 | 用户不知道为什么失败 | 状态里有 `fetching`/`failed` |

**架构**：`components/weather/`（HTTP + cJSON + NVS，可 include IDF）→
`w_platform_weather()` 钩子 → 界面页（**不碰 IDF**）。
经纬度用**整数微度**（1e-5 度），因为界面层设置钩子签名是 `int`。

### 3.10 两个 LVGL 8.3/8.4 差异（模拟器与设备不是同一份 LVGL）

设备用**我们 vendored 的 8.4**，PC 模拟器用**它自带的 8.3**。
本批撞到两处：

1. `lv_calendar_header_dropdown_set_year_list()` —— 8.4 新增，8.3 连实现都没有
2. 头文件在 `src/extra/widgets/calendar/` 子目录里，**两边都没有这条 include 路径**
   → 改成**就地原型声明**（不改 vendored 构建脚本，免得被上游更新覆盖）

### 3.11 `weather` 组件不能依赖 `app`（链接期才暴露）

`weather_service.c` 要读"时区和经纬度存哪"，但那是 app 层才知道的事；
而 `app` 已经依赖 `weather` → 会成环，直接报
`undefined reference to weather_get_coords`。

**解决**：`weather_service.c` 给 **weak 默认实现**（上海），
app 层的 `weather_port.c` 提供同名**强符号**在链接时覆盖。
两头都自洽：单编 weather 组件能过，整机用 app 的版本。

## 八、本版本改动简单说明

**这一版把"一块手表该有的本地功能"补齐了，并加了联网的天气。**

具体做了七件事：

1. **通用提示条（toast）** —— 以前各功能的反馈方式五花八门（有的只打串口日志、
   有的什么都不显示），现在统一成"屏幕顶部滑出一条，1.5 秒自动消失"。
   先做它是因为后面每个功能都要用它做反馈。

2. **计算器** —— 新加了「工具」页（轮播第 5 页），计算器就在里面。
   支持加减乘除和百分号，`100-10%` 按商用计算器算成 **90**。
   求值逻辑做成独立的纯函数模块，配了 34 条测试向量。

3. **日历** —— 也是工具页进去。中文星期名、今天高亮、能切年月。

4. **2048** —— 游戏列表里第二款。四个方向滑动合并相同数字。
   为了不出内存问题，动画是"用数据算"而不是"建动画对象"。

5. **WiFi 能记住 5 个网络** —— 以前只存一个（换网络就得重输密码）。
   现在家里/公司/热点都能记住，点已保存的网络直接连、不用再输密码。
   顺带修了一个隐患：以前"某一次密码错"会把保存的网络**全部清掉**，现在只清那一个。

6. **天气** —— 工具页进去，显示 7 天预报（晴/多云/阴/雾/雨/雪/雷，图标是画的、不占空间）。
   数据来自 Open-Meteo（免费、不用 API key）。**要在 WiFi 页先连上网**，
   再回天气页点【获取天气】。城市坐标可以自己改（默认上海）。
   查询结果会存下来，下次打开直接显示，不用重新联网。

7. **按你的要求：开机不再自动连 WiFi** —— 以前开机就自己拿存着的密码去连，
   如果那个热点不在，界面会一直卡在"连接中"，既不报错也没法退出。
   现在联网变成**你的动作**（进 WiFi 页点一下才连）。
   如果你确实想让它开机自动连，去**设置页**把"开机自动连WiFi"打开即可。

另外顺手修了三条小债：串口 `wifi forget` 命令以前写在帮助里但没实现（现在实现了）、
开机自动重连不再"连不上也不管"（会按需清掉失效的密码）、
以及给 2048 加了最高分存档。

*本文档对应固件 v0.7.0*
