## 一、🔴 修 Bug：滑动完全没反应

### 现象

实机上手指滑动屏幕，**什么反应都没有**。但屏幕显示、触摸点击都正常。

### 根因（翻 LVGL 源码定位）

v0.2.0 用的是 LVGL 官方的 `LV_EVENT_GESTURE` + `lv_indev_get_gesture_dir()`，
配合 `LV_OBJ_FLAG_GESTURE_BUBBLE` 让事件冒泡到页面根。代码看着很正规，但：

```c
/* components/lvgl/src/core/lv_indev.c */
907:    if(indev_obj_act) {
908:        lv_event_send(indev_obj_act, LV_EVENT_PRESSING, indev_act);
913:        _lv_indev_scroll_handler(proc);      /* ← 先把这次拖动"吃掉"当滚动 */
915:        indev_gesture(proc);
1118: void indev_gesture(_lv_indev_proc_t * proc)
1121:     if(proc->types.pointer.scroll_obj) return;   /* ← 第一行就 return */
```

而 `lv_obj_create()` 造出来的对象**默认带 `LV_OBJ_FLAG_SCROLLABLE`**
（`lv_obj.c:441`）。于是：手指按在哪张卡片上，那张卡片就变成 `scroll_obj`，
拖动被当成"滚动这张卡片"，**`LV_EVENT_GESTURE` 一次都不会触发**。

### 第一版修法：自己算方向

完全不依赖 LVGL 的手势系统：

```
PRESSED  -> 记下起点
PRESSING -> 算累计位移；超过阈值就判定方向并执行（每次触摸只执行一次）
RELEASED -> 复位
```

唯一依赖是 `PRESSING` 能冒泡到页面根，靠给子树打 `LV_OBJ_FLAG_EVENT_BUBBLE` 保证。

## 二、🔴 二次返工：跟手滑动（用户要求加视觉反馈）

第一版修法只是"松手才切页"，没有跟手的视觉反馈。加跟手时又踩了两个坑，
**而且推翻了我自己的两个判断**：

### 坑 A：我以为"LVGL 8 没有分页吸附"——错了

`lv_obj_set_scroll_snap_x()` **在 8.4 里确实存在**（`lv_obj_scroll.h:76`），
而且松手后的"速度预测 + 吸附动画"是白送的（`lv_indev_scroll.c:165-172`）。

按这个思路改成"可滚动 viewport + 三槽窗口 + `SCROLL_SNAP_START`"，
理论上能白拿跟手位移 + 惯性 + 吸附，代码还更短。

### 坑 B：但滚动吸附方案**实测滑不动**，且原因非常隐蔽

模拟器实测数据：

```
三个槽放在 -240 / 0 / +240
lv_obj_get_scroll_right(vp) = 240          看起来行程够
lv_obj_scroll_by(vp, -40, 0, LV_ANIM_OFF)        -> scroll_x 0 -> 0   （纹丝不动）
lv_obj_scroll_by_bounded(vp, -40, 0, LV_ANIM_OFF) -> 也是 0
```

连最底层的 `lv_obj_scroll_by()` 都推不动。说明 LVGL 的滚动坐标
**不是我们以为的"内容坐标系"**：`scroll_right` 会把内容外框的左边缘减掉
（`lv_obj_scroll.c` 的 `lv_obj_get_scroll_right`），实际可达位置和槽位坐标对不上。

**错得很隐蔽**——`scroll_right`、槽位坐标、`scroll_x` 数值看着都合理，就是不动。
我为此在模拟器里加了运行时探针（直接调各个滚动 API 看哪个真的动得了）才定位。

### 最终方案：**手动定位**（确定性优先）

放弃 LVGL 的滚动系统，改为自己控制坐标：

```
scr                        screen 240x280（唯一的 screen）
└── vp                     裁剪容器 240x280（**不滚动**，纯裁剪）
    ├── slot[0]   x = off - 240    前一页
    ├── slot[1]   x = off          当前页
    └── slot[2]   x = off + 240    后一页
```

- `off` = 内容横向偏移，拖手指时直接 `lv_obj_set_x()` 跟手
- 松手：位移超过 **1/4 屏（60px）** 判定翻页，否则弹回
- 翻页后重建三槽窗口并把 `off` 归零 —— 内容平移一页和归零正好抵消，**无跳变**
- 收尾用 `lv_anim` + `lv_anim_path_ease_out`，180ms
- 越界按 1/4 速度走，做出橡皮筋手感

**取舍**：失去 LVGL 白送的"轻甩翻页"（速度预测）。
理由：**能确定地动起来 > 手感略好但不知道为什么不灵**。

## 三、结构变化：页面从 screen 改成普通对象

因为要"相邻页并排放在同一个容器里"，而 **LVGL 的 screen 挂不进容器**：

```c
/* lv_obj_tree.c:132 */
if(obj->parent == NULL) {
    LV_LOG_WARN("Can't set the parent of a screen");
    return;                      /* 直接拒绝 */
}
```

而且 8.4 没有 `lv_obj_remove_from_parent()`，也没有"先摘再挂"的偏方。

| 项 | 变化 |
|---|---|
| `watch_page_t::create` | `(void)` → **`(lv_obj_t *parent)`** |
| `w_screen_create()` | 删除，改成 **`w_page_create(parent)`** |
| 4 个页面 | 各改 2 行 |
| 控制中心（`watch_overlay`） | **不受影响**，仍是独立 screen（模态覆盖层，不跟手） |

## 四、新增 P1 功能

| # | 功能 | 实现 |
|---|---|---|
| 5 | **多页面切换** | 跟手轮播，4 页循环（表盘→设置→健康→运动） |
| 6 | **计步器** | 新组件 `imu`（QMI8658C 驱动）+ `motion`（50Hz 采样 + 计步算法） |
| 7 | **卡路里 / 距离** | 计步算法内一并算（按身高算步长、按体重算热量） |
| 8 | **设置页** | 亮度滑块 + 自动息屏/抬腕亮屏/步数目标/身高/体重 + 只读信息 |
| 9 | **亮度调节** | 设置页滑块 + 控制中心滑块，写 NVS |

### 设置页交互约定

可点行统一用**"点一下切到下一个值"**，不做二级页面也不做加减按钮：

- 自动息屏：15 → 30 → 60 → 120 → 常亮 → 15 …
- 抬腕亮屏：开 ⇄ 关
- 步数目标 / 身高 / 体重：按档位循环

每项只要一个 `lv_obj_add_event_cb`，用户也不用学怎么操作。

## 五、新增组件（2 个）

| 组件 | 职责 |
|---|---|
| `imu` | QMI8658C 六轴驱动 + **全定点**计步算法 |
| `motion` | 50Hz 采样任务 → 跑计步 → 1Hz 推结果给 `data_hub` |

### 新增数据通路

```
QMI8658C --50Hz--> motion --1Hz--> data_hub --> 界面
```

**界面代码一行没改**就显示出了真实步数 —— 这是 v0.2.0 分层设计的回报。

### 计步算法要点（详见 [QMI8658C-计步方案.md](../QMI8658C-计步方案.md)）

- 带通 **0.5–3.5Hz**，2 级 RBJ biquad，Q15 系数
- **去重力 LPF 必须 τ=3s**（用 0.6s 会跟着步伐摆动，反而放大信号）
- **定点 EMA 必须四舍五入**（负数直接 `>>` 向 −∞ 取整会引入 1.5mg/s 漂移）
- **σ 不能用 E[x²]−E[x]²**（Q10 下灾难性相消，σ 会乱跳）
- 防抖：`max(250ms, 35% × 自适应步周期)`
- 误计抑制三层：带通 → 波峰因数门 → **步间隔变异系数门 CV ≤ 0.26**

## 六、其它改动

### 1. 新增设置钩子 `watch_ui_set_setting_hooks()`

设置页要读写设置项，但 `watch_ui_pages` **不能 include ESP-IDF 头文件**
（否则 PC 模拟器编不过）。所以按"名字寻址"的钩子把两边接起来：

```
界面层：watch_ui_setting_get("timeout", 30)
app 层：接到 settings_get_or_default() / settings_set()
模拟器：不接 -> 用默认值，界面照跑（改动不落盘而已）
```

### 2. `event_bus` 有了第一个真实消费者

`app.c` 里订阅 `EVT_SETTINGS_CHANGED` → 自动刷界面。
以后 BLE 改设置、串口改设置都会自动生效。
（在此之前 `event_bus` 只是搭好了没人用。）

### 3. 新增"自动字体"机制（防豆腐块的正解）

```c
w_label_create_auto(parent, text, ascii_font, cjk_size, color);
w_label_set_text_auto(label, text);        /* 换文案时也自动切字体 */
```

内容含中文时自动切中文字库，纯 ASCII 时用 Montserrat（数字更好看）。

**为什么需要它**：豆腐块这个坑本项目**一共踩了三次**
（日期格式串、设置页值列、`·` 分隔符）。
根因都是"标签设了 ASCII 字体但内容是中文"，而且**编译运行都不报错**。
与其每次人肉判断，不如让工厂函数按内容自动选。

### 4. 新增 3 个校验工具

| 工具 | 作用 |
|---|---|
| `check_glyphs.py` | 解析字库 **cmap**（不是注释！）检查覆盖 |
| `check_all_literals.py` | 扫所有字符串字面量，找漏进字库的字 |
| `check_fonts.py` | 找出"ASCII 字体 + 中文文案"的组合 |

> ⚠️ `check_glyphs.py` 早期版本读的是 `.c` 文件里的 `/* U+XXXX */` 注释，
> **被误导过**：注释列的是字形位图，而 LVGL 真正查表用的是
> `cmaps[]` + `unicode_list[]`（SPARSE_TINY，存的是相对 `range_start` 的偏移）。
> 两者不是一回事。现在改成按结构解析。

### 5. 字库瘦身

生成脚本改成**只扫字符串字面量**（不再扫注释），两个好处：

- 字符数 **839 → 406**
- 顺带解决了 Windows 命令行参数过长导致 `npx` 报
  `The command line is too long`（上限 8191 字符，每个字占约 8 字符）

**效果**：字库源码 2.1MB → 1.2MB，固件 1.02MB → **902KB**。

### 6. LVGL 瘦身（为仓库准备）

删掉 `demos/`、`examples/`、`cmsis-pack`、`korean.ttf`，共 **75MB**
（都是不参与编译的示例资源）。

⚠️ **同时改了 `env_support/cmake/esp.cmake`**：原来它无条件把
`examples/` 和 `demos/` 加进 `INCLUDE_DIRS`，目录删掉后 CMake 会报
`Include directory ... is not a directory`。改成"存在才加"。

> **以后从上游更新 LVGL 需要重新打这个补丁。**

### 7. 新增串口命令

`motion`（计步状态）、`motion_watch <秒>`（连续遥测，调参用）、`steps_reset`

### 8. 仓库准备

新增 `.gitignore`：忽略 `build/`、`sdkconfig`、`**/*.o`、`**/*.exe`、
`.vscode/settings.json`。

## 八、验证结果

| 项 | 结果 |
|---|---|
| 跟手轮播 | ✅ 模拟器自检 **6/6 通过**（页号正确循环、偏移正确归零） |
| 实机 IMU | ✅ 50Hz 采样正常，静止 12 秒 **0 误计**，信号稳定收敛到 0 |
| 实机步数显示 | ✅ 表盘显示 "0"（不是 "--"），说明 `data_hub` 已收到 IMU 就绪 |
| 字库覆盖 | ✅ 316 个字面量字符全部覆盖，0 个豆腐块 |
| 固件体积 | **902 KB**（`0xe1440`），app 分区剩 **78%** |
| 编译 | 0 error / 0 warning（除第三方组件自带的 deprecated 警告） |

### 修掉的一个真实 Bug（收尾时发现）

`motion` 只在**步数变化**时才推给 `data_hub`（省得每秒白刷界面）。
但没人走路时步数永远是 0 → 永远不推送 → `data_hub` 里
`steps.available` 一直是 false → **界面永远显示 "--"**。

修法：`motion_init()` 里先推一次"IMU 已就绪、当前 0 步"。

## 九、⚠️ 已知局限（未验证 / 未完成）

1. **计步精度未实测**。算法参数是用**合成腕部运动模型**扫出来的，
   没有用真实腕部数据标定过。公开评测（Koffman 2024 复现 7 种开源算法）里
   最好的纯算法平均绝对误差约 8.6%，纯阈值法普遍**系统性少计**。
   必须上板实测调参（用 `motion_watch` 命令看遥测）。

2. **走走停停会少计**：节律门要求攒够 3 个间隔才落账，
   每段走路**开头约 3 步被丢掉**（算法取舍，降低 `commit_after` 可缓解但误计风险上升）。

3. **跑步（165 步/分）未通过**合成测试（高频谐波被 3.5Hz 上沿衰减）。
   真实跑步冲击幅度远大于走路，大概率没这么糟，但**必须实测**；
   若确实漏计，把带通高端提到 5Hz 并降 `crest_min_x100`。

4. **自动息屏、抬腕亮屏只存了开关，没接实际动作**。
   需要新增一个 `power` 组件监听触摸/IMU 角度。设置项和 UI 都已就绪。

5. **跟手滑动的手感未经真人验证**。
   本机环境的鼠标/键盘注入不生效（`SendInput`、`mouse_event`、`keybd_event`
   都试过，连拖动时 `GetAsyncKeyState(VK_LBUTTON)` 都读不到按下），
   所以只能靠**模拟器自检 + 代码走查**验证逻辑。
   实操调整位置：`components/watch_ui/watch_pages.c` 的 `COMMIT_THRESHOLD_PX`
   （默认 `W_SCREEN_W / 4` = 60px）
   - 太钝（要拖很远才翻页）→ 调小
   - 太灵敏（容易误翻）→ 调大

6. **计步未做持久化**（按需求"先做基础的"）：重启归零，跨天不自动清零。
   跨天清零需要读 RTC 日期，接口已就绪但未接。

7. **未验证**：极慢走(<70 步/分)、上楼、手插口袋、拄拐。

## 十、本版本改动简单说明

> **修好了滑动，并补齐 P1 功能 5~9：多页面切换、计步器、卡路里/距离、设置页、亮度调节。**
>
> **滑动**换掉了 LVGL 的手势系统（它被滚动系统吃掉，静默失效），
> 改成自己判定方向 + 手动定位的三槽轮播，做到跟手位移。
> 中间试过 LVGL 的滚动吸附方案，但实测 `lv_obj_scroll_by()` 静默无效、
> 原因隐蔽，最终选择**手动定位**——确定性优先。代价是没有"轻甩翻页"。
>
> **新增两个组件**：`imu`（QMI8658C 驱动 + 定点计步算法）、
> `motion`（50Hz 采样服务）。新数据通路 `IMU→motion→data_hub→界面`
> 让界面**一行没改**就显示出真实步数。
>
> **页面结构**从 screen 改成普通对象（screen 挂不进容器），
> 4 个页面各改 2 行；控制中心不受影响。
>
> **根治豆腐块**：新增"自动字体"机制（按内容自动选中文字库），
> 配 3 个校验脚本；字库生成改成只扫字符串字面量，固件 **1.02MB → 902KB**。
>
> **LVGL 瘦身 75MB**（删示例资源）为入库做准备，
> 顺带改了 `esp.cmake`（include 改条件判断，**上游更新需重打补丁**）。
>
> ⚠️ **计步精度尚未用真实数据标定**，需要上板实测调参（见第九节第 1 条）。
