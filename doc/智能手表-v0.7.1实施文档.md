### 3.1 ★ 上滑打开控制中心：**入口不存在**（本轮实测）

**实测证据**（模拟器跑的就是设备那套 38 个界面源文件，见 `lvgl_sim/Makefile:218-255`）：

| 步骤 | 注入 | 结果 |
|---|---|---|
| 阳性对照 | 左滑 | ✅ 时间 → 运动（画面改变） |
| 阳性对照 | 右滑 | ✅ 运动 → 时间 |
| **待测** | **上滑（190 LVGL px，远超 30px 阈值）** | ❌ **零变化；前后截图 SHA256 逐字节相同** |

```
_probe_home_before.png   A00A532845C4969503844CD853DE849B28EB5FE370C42D7935129856B55D0538
_probe_home_after_up.png A00A532845C4969503844CD853DE849B28EB5FE370C42D7935129856B55D0538
```

**代码级根因链（全仓穷尽）**：

| # | 事实 | 出处 |
|---|---|---|
| 1 | `watch_overlay_show()` 全仓只有 2 个调用点 | `watch_pages.c:670`（`LV_KEY_UP`）、`:729`（`.open_overlay`） |

### 3.2 天气的"缓存过期判定"**从未实现**（交接文档 §10 #19 结案）

| 证据 | 位置 | 事实 |
|---|---|---|
| 写入 | `weather_service.c:357` | `tmp.fetched_epoch = esp_timer_get_time()/1000000` —— 这是**开机秒数**，不是 epoch（这就是日志里"抓取于 epoch 390"的来源） |
| 设计声明 | `weather_service.h:27`、`weather_service.c:21-24`、`v0.7.0.md:160` | 都写"存 `fetched_epoch`，按**抓取日 ≠ 今天**判过期" |
| 实际消费 | 全工程 grep | **只写、只存 NVS、只读回打日志、只拷进钩子快照**；`local_ymd_of()`（`:89`）**零调用者**；界面页完全不读 |

⇒ 不是"值不对但功能正常"，而是**过期判定根本没写**。而模拟器把它桩成固定值 `1791578100`
（`sim_main.c:313`），所以**自检永远测不出这条**（典型的"两边语义不一致"，§8 教训 23）。

**正确的数据源已经存在**：`SETTINGS_TIME_EPOCH`（NVS 键 `t_epoch`，"最后已知时间戳"）**已经在被正确维护**——
`data_hub.c:320`（从 RTC 写）、`:331`（`data_hub_set_epoch()` 写）。语义是"**本地墙上时间当作 epoch**"
（RTC 存的就是本地时间，`data_hub.c:5-13`）。

### 3.3 ★ 模态内容区的布局模型：**`lv_obj_align()` 在 flex 父容器里是空操作**

`watch_modal.c:75-84` 的 body 是 `LV_SIZE_CONTENT` + `LV_FLEX_FLOW_COLUMN` + `pad_row 6`。
而 `lv_obj_align()` = 设 `style_align` + `lv_obj_set_pos()`（`lv_obj_pos.c:339-343`），
但 `lv_obj_refr_pos()` 在 `lv_obj_is_layout_positioned(obj)` 为真时**提前返回**（`lv_obj_pos.c:628-630`），
而该判据只要**父容器有 layout** 就为真（`lv_obj_pos.c:276-286`）。

**⇒ 直接建在模态 body 上的子对象，所有 `lv_obj_align(..., TOP_LEFT, 0, y)` 都被忽略，真实布局是"6px 间隔顺序堆叠"。**

**像素测量证实**（量自模拟器自检截图，`shot_*.png` 是 stored-deflate PNG）：

| 截图 | 最低有内容的行 y | 若=绝对定位应为 | 若=flex 堆叠应为 | 实测符合 |
|---|---|---|---|---|
| `shot_weather_done.png` | **279**（贴到屏幕最后一行） | 268（留 12px 边距） | **280** | ✅ flex |
| `shot_calc_page.png` | 270 | —（无 align） | 272 | ✅ flex，且超出内容区 268 |
| `shot_calendar_page.png` | 260 | — | 263 | ✅ flex，268 以内 |

**后果**：
- **`watch_page_weather.c`**：作者的 `22+170+30 = 222` 是**按绝对定位算的**，真实是 `22+6+170+6+30 = 234`
  ——**忘了两个 6px 间隔**。按钮行底边落在 **y=279/280**（贴屏），比"精确占满 222"多 12px 并产生 12px 可滚范围。
  **好在没有内容被裁**（30px 按钮行 250→279 完整可见），所以是"注释与观感问题"，不是坏功能。
- **`watch_page_calc.c`**：226 vs 222，**真超 4px**，且该页**主动关掉了滚动条**（`:402-408`）→ 看不见的溢出。
- **`watch_page_calendar.c`**：217 vs 222 **放得下**（实测 260 ≤ 268），只是注释里的 `~230` 用了错的 `TITLE_H(26)`。

### 3.4 息屏/亮屏的三条铁律（都已逐行验证）

| # | 铁律 | 依据 |
|---|---|---|
| 1 | **只能暂停 display refresh timer，绝不能冻结 `lv_timer_handler()`** | 提醒层/闹钟/倒计时全靠 LVGL 定时器：`watch_clock.c:133`（1s/100ms 自适应）→ `watch_alert_poll()` → `alert_pump()` |
| 2 | **亮屏必须三件套**：面板 DISPON + 恢复刷新 + **整屏重画** | `alert_start()` 会主动 `w_screen_wake()`（`watch_clock.c:359`）——闹钟响时屏幕必须真的看得见 |
| 3 | **往 `power.c` 的 `poll_cb` 里加代码要用非阻塞拿锁** | 它跑在 **esp_timer 任务**里；现有 `lv_indev_enable()`（`:159-162`）是失效残留（真正的机制是 `w_screen_should_swallow_touch()`，`bsp.c:182-190`），顺手清掉 |

**官方口子已确认**：`_lv_disp_get_refr_timer(lv_disp_t*)` 声明在公开头 `lv_disp.h:171`，
文档原话是"*Get a pointer to the screen refresher timer to **modify its parameters with `lv_timer_...` functions***"
—— 配 `lv_timer_pause/resume/set_period` 即可。关面板用 `esp_lcd_panel_disp_on_off()`（`bsp.c:130` 已在用）。

现语义：息屏 = **只** `bsp_backlight_set(0)`（LEDC duty 0，`bsp.c:71-81`）；面板仍在扫描、LVGL 仍 100Hz（10ms）。

### 3.6 需要更正的"铁律表述"（重要，会误导后面每一次改动）

交接文档 §0/§3.1 写的是"`watch_ui` 不许 include **任何** ESP-IDF 头文件（`esp_*.h`、`freertos/*`、`driver/*`）"。
**准确规则**（这才是能照着做的版本）：

> `watch_ui` / `watch_ui_pages` **只能用这三个 IDF 头**——`esp_err.h`、`esp_log.h`、`esp_check.h`，
> 因为 PC 端在 `lvgl_sim/pc_shim/` 给了它们的垫片（`-Ipc_shim`）。
> 一旦 include `freertos/*`、`driver/*`、`esp_timer.h`、`nvs.h` 等，**PC 模拟器立刻编不过**。
> 另外 `ui_port.h:19` 声称"界面层不会出现任何 ESP-IDF 头文件"也不准确——它自己就 include 了 `esp_err.h`。

### 3.7 模拟器与设备的行为差异（文档只写了一条，实际有 5 条）

### 3.8 模拟器输入注入的可用方法（本轮摸清，对自动化测试有直接价值）

- **`SendInput` / `SetForegroundWindow` 在本机不可用**：前台窗口是别的程序（实测是 Word），
  Windows 的**前台锁**让后台进程抢不到焦点 → 注入全部落空。这正是 `tools/test_keys.py` 文件头
  "本机环境的自动化鼠标注入不生效"的**真正原因**（它归因成"注入不生效"）。
- **可用方案：`PostMessage` + 客户端像素坐标**。依据是 win32drv **读消息的 `lParam`**：
  `win32drv.c:795`（`g_mouse_value = lParam`）→ `:681-688`（`MulDiv(x, 96, WIN32DRV_MONITOR_ZOOM * g_dpi)`，
  zoom=2 即除以 2）。按键同理（`:806-811` → `:714-715`）。**不需要前台焦点、不动用户鼠标。**
- 另注：`tools/test_swipe.py:117` 用 `ShowWindow(hwnd, 5)`（SW_SHOW），**恢复不了最小化窗口**
  → 第二次调用会报"窗口尺寸异常"（`0x0 @ (-32000,-32000)`）；应改 `SW_RESTORE(9)`。

⇒ **建议（独立小改，可与本版一起做）**：把 `tools/test_swipe.py` 的注入方式换成 `PostMessage`，
并把 `ShowWindow` 换成 `SW_RESTORE`。这样项目的交互自动化在这台机器上才真正可用。

### 4.1 【建议第一位】修「上滑打开控制中心」入口

**做法**：在 `watch_ui_init()` 里，`s_scr`/`s_vp` 建立之后，把**轮播 screen** 交给手势层：

```c
/* watch_pages.c，紧接 s_vp 的事件注册之后 */
watch_gesture_attach(s_scr);      /* 让上滑能在轮播页上被收到 */
```

**为什么接 `s_scr` 而不是 `s_vp`**：
- `watch_gesture_attach()` 内部会 `lv_obj_clear_flag(scr, SCROLLABLE)` 并清 `scr` 自己的 `EVENT_BUBBLE`
  —— `s_scr` 在 `:759-760` **本来就已经是这两种状态**，语义吻合、不产生新约束；
- 接在 `s_vp` 上会让手势层和轮播自己的处理器挂在同一对象上，两个 `PRESSING` 回调抢同一个拖动，
  容易出现"一次滑动既切页又开控制中心"。

**必须同时想清的三件事**：
1. **横向不能打架**：手势层的横向分支已有 `horizontal_probe = watch_ui_carousel_active`
   （`watch_pages.c:735`），轮播页上会 `return`，交给轮播。✅ 已有护栏。
2. **纵向语义**：内容**溢出**的页面仍旧走 `drag_move()` 的滚动分支（`watch_pages.c:525-534` 先 return，
   而它是在 `s_vp` 上、**比 `s_scr` 更早**收到事件，且不会 post 动作）→ 不冲突；
   内容不溢出的页面才会落到 `s_scr` 的手势层 → 上滑开控制中心。**这正是注释里原本描述的意图。**
3. **模态子页**：模态根挂在 `s_scr` 下、但它们的子树**没有** `mark_subtree`
   （`watch_modal.c:35-89` 不调用它），所以模态里上滑不会误开控制中心 —— 这也符合直觉
   （模态有自己的滚动与返回键）。**这一条要在自检里断言住**，避免以后有人顺手给模态也打 bubble。

**回滚**：删掉这一行即可，无状态残留。

**验证**：
- 模拟器：上滑 → 断言 `watch_overlay_visible() == true`；下滑 → 断言 `false`；
  横向滑动仍能翻页（`watch_ui_current_index()` 变化）；
  模态打开时上滑 → 断言控制中心**不出现**。
- 实机：上滑能开、下滑能关、亮度滑块能拖。

### 4.2 【建议第二位】`hint_ok_cb` 同步删祖先 → 改异步

**问题链（已逐行核实）**：
- `watch_page_wifi.c:277-278` 把 `mask` 作为 `user_data` 交给确定按钮的回调；
- `hint_ok_cb`（`:224-231`）里 `lv_obj_del(panel)` —— `panel` 就是 `mask`，是事件 target `ok` 的**祖先**；
- `lv_obj_del` → `obj_del_core()` **同步**递归删子对象并 `lv_mem_free`（`lv_obj_tree.c:45-61`、`:351-416`）；
- 而 `_lv_event_mark_deleted()` **只在被删对象就是 target/current_target 时**才置 `e->deleted`
  （`lv_event.c:147-155`）→ 删祖先不置位；
- 回调返回后事件循环继续读 `e->current_target`：`lv_obj_get_event_dsc(e->current_target, i)`（`:469`）
  与 `e->current_target->parent`（`:472`）—— **`current_target` 已被释放**。

**做法**（与 `watch_modal.c:114-115` / `watch_keyboard.c:281` / `watch_game.c:303` 保持同一风格）：

```c
static void hint_ok_cb(lv_event_t *e)
{
    lv_obj_t *panel = (lv_obj_t *)lv_event_get_user_data(e);
    if (panel) {
        lv_obj_add_flag(panel, LV_OBJ_FLAG_HIDDEN);   /* 先藏，防闪一帧 */
        lv_obj_del_async(panel);                      /* 再异步删，别在事件派发里删祖先 */
    }
    w_modal_refresh();
}
```

**回滚**：改回 `lv_obj_del` 即可（但不要）。

**验证**：模拟器自检里覆盖"WiFi 页 → 连上 → 弹出耗电提示 → 点确定 → 不崩且对象/定时器数不变"。
⚠️ 现有自检**没有**这条路径（提示框只在"真连上"时出现，而模拟器是 fake wifi）。

### 4.3 【主线】息屏真关屏 + 降刷新

**新增 BSP 接口**（`bsp.h` + `bsp.c`）：

实现一行：`esp_lcd_panel_disp_on_off(s_lcd_panel, on)`（`bsp.c:130` 已在用同一 API）。

**`power.c` 的息屏序列**（新）：

```

  1. bsp_backlight_set(0)                    ← 保留（原有）
  2. bsp_lcd_display(false)                  ← 新增：面板进 sleep，省静态功耗
  3. 暂停 display refresh timer               ← 新增：不再往 SPI 推帧
       if (bsp_display_lock(0)) {             ← 非阻塞；拿不到就下次 50ms 再试
```

**亮屏序列**（新，三件套，缺一不可）：

```

  2. if (锁) { lv_timer_resume(_lv_disp_get_refr_timer(disp));
               lv_obj_invalidate(lv_scr_act());   ← 强制整屏重画

  3. bsp_backlight_set(bright)
  4. s_wake_at = now  （沿用现有的"吃掉唤醒那一下"机制）
```

**为什么"重画"必须做**：面板 DISPOFF 期间 LVGL 可能仍有脏区被丢弃/或被我们暂停了刷新，

**为什么不暂停整个 LVGL 任务**（重复强调，这是本版最容易犯的错）：
闹钟/倒计时/提醒层的**全部**推进都在 LVGL 定时器上（`watch_clock.c:133` → `alert_pump()`）。

- 新增的 `lv_*` 调用一律 `bsp_display_lock(0)` 非阻塞（`poll_cb` 跑在 esp_timer 任务里）。

**"放慢"还是"暂停"**：建议**暂停**（息屏时本来就没人看），但保留一个开关便于对比续航；
若实测发现恢复时首帧有闪，退化为 `lv_timer_set_period(refr, 200)`（5Hz）即可 —— 改动同样只有一行。

**回滚**：`bsp_lcd_display()` 的两个调用点删掉 + 去掉 pause/resume，即回到 v0.7.0 行为。

**验证**（自检 + 实机）：

### 4.4 天气 epoch + 过期判定

**第一步：给 `weather` 一个取"本地 epoch"的口子（照 §4.9 的 weak 符号模式）**

```c
/* weather_service.c —— 弱默认：拿不到就说"不知道" */
__attribute__((weak)) uint32_t weather_local_epoch(void) { return 0; }
```
```c
/* components/app/weather_port.c —— 强符号，覆盖上面的 */
uint32_t weather_local_epoch(void)
{
    int32_t v = 0;
    if (settings_get(SETTINGS_TIME_VALID, &v) != ESP_OK || v == 0) return 0;   /* 未校时 → 0 */
    if (settings_get(SETTINGS_TIME_EPOCH, &v) != ESP_OK) return 0;
    return (uint32_t)v;        /* 注意：这是"本地墙上时间"，不要再套时区换算 */
}
```

**第二步：写入真 epoch + 用 `local_ymd_of()` 判过期**

- `parse_and_store()` 里把 `tmp.fetched_epoch = esp_timer_get_time()/1000000;`
  改成 `tmp.fetched_epoch = weather_local_epoch();`（拿不到就是 0 = 未知）。
- 增加过期判定（"抓取日 ≠ 今天"），用**现成但零调用**的 `local_ymd_of()`（`weather_service.c:89`）：

```c
/* 取缓存时：抓取日与今天不同 → 视为过期（仍可显示，但 UI 要提示"该刷新了"） */
bool weather_cache_is_stale(void)
{
    const uint32_t now = weather_local_epoch();
    if (!now || !s_st.fetched_epoch) return true;          /* 时间未知 → 保守当过期 */
    int fy, fm, fd, ty, tm, td;
    local_ymd_of(s_st.fetched_epoch, &fy, &fm, &fd);
    local_ymd_of(now,                 &ty, &tm, &td);
    return (fy != ty) || (fm != tm) || (fd != td);
}
```

**关键陷阱（§4.1 的第二个坑）**：`SETTINGS_TIME_EPOCH` 已经是**本地**墙上时间
（`data_hub.c` 顶部约定 + `app.c:538` 写入时已加过时区），所以**不要再套 `SETTINGS_TIMEZONE`**，
否则会跨日算错。判过期用的"今天"也必须用同一口径算。

**第三步：界面表现**（不打坏现有体验）
- 缓存仍有数据 → **照旧显示 7 天**（v0.7.0 就是这么设计的：开机先渲染缓存），
  但状态行文案从"缓存数据，可点获取刷新"改为"**缓存已过期，点获取刷新**"（新增一条 `W_STR_*`，
  按 §4.8 流程登记 + 重生成字库）。
- 缓存与今天同日 → 保持现有文案不变。

**第四步：模拟器桩改成"会走的时间"**
- `sim_main.c:313` 的 `s_fake_wx.fetched_epoch = 1791578100u;` 改成**相对当前模拟器时间**的值
  （模拟器的时间来自 `sim_data.c` 的编译期时钟，并且每秒走），
  这样"同日/跨日"两种情况都能在自检里构造：
  - 同日：`fetched_epoch = now` → 断言文案为"缓存数据…"
  - 跨日：`fetched_epoch = now - 86400` → 断言文案为"缓存已过期…"

**回滚**：`weather_local_epoch()` 返回 0 时整条链退化为"永远当过期"，不会崩；彻底回滚就是恢复
`esp_timer_get_time()/1000000` 那一行。

## 六、自检要补的断言（对应 §2.1 D + F + H）

| # | 断言 | 做法要点 |
|---|---|---|
| 1 | **上滑能开控制中心 / 下滑能关** | `watch_ui_debug_touch_begin/move/end`（与真手指同一条路径，`watch_pages.h:270-276`）模拟纵向拖动 → 断言 `watch_overlay_visible()` 翻转；**这是本版最重要的一条新断言** |
| 2 | 横向滑动仍能翻页（回归） | 同一套 debug touch，断言 `watch_ui_current_index()` 变化 |
| 3 | **模态打开时上滑不误开控制中心** | 开设置页 → 上滑 → 断言 `watch_overlay_visible()==false` |
| 4 | 天气页几何 | 照功能列表页的写法（`sim_main.c:1344-1385`）：量**最后一个子对象的绝对 y2** 与屏高比较；并断言"可滚 0px"（若决定修布局） |
| 5 | 计算器页几何 | 同上 |
| 6 | 息屏唤醒链路 | 断言"息屏 → `w_screen_is_on()==false`；触摸 → 亮屏且那一下被吞掉（`w_screen_should_swallow_touch()`）；抬手后解除" |
| 7 | 天气过期判定的两种情形 | 用可构造的桩时间：同日 → 文案不变；跨日 → 文案变"已过期" |
| 8 | `hint_ok_cb` 路径 | 直接喂 fake wifi 到 CONNECTED、点确定，断言不崩 + 对象/定时器数不变 |
| 9 | **控制中心的对象/定时器计数** | 开→关后 `sim_obj_count()`/`sim_timer_count()` 复原（控制中心现在**零自检覆盖**） |

**断言纪律**（血的教训）：能抓住 bug 的断言才算断言；跨页比对象数会假阳性，
所以每次都要**先回到进入时的那一页**再比（`sim_main.c:1150-1154`、`:1769-1776` 是先例）。

## 十、本版**不做**的（明确划界）

| 项 | 为什么不做 |
|---|---|
| **IMU 降频** | 会破坏计步：滤波器系数 `k_bp[2][5]` 与 4 个 EMA alpha 全部**按 50Hz 硬编码**（`qmi8658c.c:5,45-47,54-64`），且 `above_cnt >= 3` 是**按样本计数**（`:495`）。作者自己在 `motion.c:253-254` 写明"采样率必须和 `sample_rate_hz` 对得上，否则带通截止频率会偏，计步会忽多忽少"，但**该约束没有实现**（`sample_rate_hz` 全工程只有定义/赋值/这句注释）。降频属于**重新标定级工程**（要重算系数并录新数据跑 `tools/step_*.py` 三件套）。**建议单开一版做**，并优先考虑 QMI8658C 的运动中断（INT2=GPIO38 目前空闲）而不是单纯降频。 |
| **WiFi 空闲自动断开** | ① 字面意义的"校时后立刻断"会**打坏 v0.7.0 的天气**（连上就自动 SNTP → 断网 → 用户再点【获取天气】没网）；② `wifi_service` **内部没有任何周期 tick**，两个超时都是"有人调 `hook_get_status()` 时才惰性求值"，而那只在 WiFi 页打开时发生（300ms）→ 朴素的空闲超时**在该生效的时候永远不会触发**；③ 自动断开必须走 `s_user_disconnect = disconnect_event_expected()` 那套标志（否则被当成"连接失败"，且若 `s_conn_used_saved` 仍为真还会**删掉用户保存的密码**，`wifi_service.c:776-825`）。**需要单独设计（引用计数 + 真正的 tick）**。 |
| 仓库根上提（把 `doc/` 与 `lvgl_sim/` 纳入版本管理） | 用户已定"先不动"，**记入风险表**：项目根不是 git 仓库，`doc/`、`lvgl_sim/`、`相关资料/` 均**无版本管理也无备份**；项目根 `doc/` 里有 6 份只此一份的文档（板载资源分析 / AI 语音方案 / Brookesia 解析 / 开源框架调研 / 代码架构说明 / 官方示例对照）。 |
| 「C 批」显示链路（SPI 超频实验、`wait_cb`） | 优化清单已归入 C 批，本版不碰。 |
| 页面转场动画 | 依赖轮播改造（3 槽、切页重建），风险高，建议单独一批。 |
