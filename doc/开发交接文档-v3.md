## 〇、先看这三件事（否则容易白干一天）

1. **`watch_ui` 组件绝对不能 include ESP-IDF 头文件** —— 因为 PC 模拟器也要编译它。
   需要平台能力（背光/NVS/时间/蜂鸣器/WiFi）一律走 `watch_platform.h` 的**钩子**。
   这是全项目最重要的一条架构约束，破坏了模拟器就废了（见 §3.3）。
2. **改 `sdkconfig.defaults` 之后必须 `clean` 重编**，否则不生效；改完要去**生成的 `sdkconfig`** 里确认真的改了（§7.2）。
3. **实机验证只能由人来点**（触摸手感、颜色、观感）。自动化能覆盖的部分已经做到：**PC 模拟器 + 三套自检**（§6）。
   **提交前必须让自检 0 失败**，它是这个项目唯一的安全网。

> `build.ps1` 的退出码是**可信的**（v0.6.1 修过：以前构建成功也返回 1）。

### 1.3 怎么判断"跑起来了"

串口（**USB-Serial-JTAG，不是 UART0**）应当看到类似：

```
I (xxx) APP: ===== 智能手表启动 =====
I (xxx) BSP: 屏幕初始化完成 240x280
I (xxx) WIFI: WiFi 服务就绪
I (xxx) MAIN: 心跳 #1｜空闲堆 xxxxxxx 字节｜最小空闲堆 xxxxxxx 字节
watch>                                   ← 命令行提示符
```

**屏幕表现**：上电先黑屏（故意的），界面装好后**背光淡入约 300ms**（v0.6.1 加的）。
若一直黑屏但串口有日志 → 背光/初始化顺序的问题；若串口无输出 → 线或端口选错（本板有两个 COM 口，认 USB-Serial-JTAG 那个）。

### 1.4 ⚠️ 一个必须知道的硬件行为

**打开串口会让芯片复位**（`rst:0x15 (USB_UART_CHIP_RESET)`）。
所以任何"打开串口 → 发命令"的脚本都要**先等 5 秒**再发，否则命令会丢在启动过程里。
`tools/serial_cmd.py` 已经处理了这件事（它不靠提示符同步，靠固定等待 + 全量回读）。

## 二、项目全貌

### 2.1 这是什么

一块**从零手写的触摸智能手表**：ESP32-S3 + 240×280 圆角屏，跑 ESP-IDF + LVGL 8.4。
界面全部自绘（不用 SquareLine），中文用自制子集字库。
最终目标见 §11：先做扎实的普通手表 → 联网 → **叠加 AI 语音**。

## 三、架构

### 3.1 分层与依赖方向（**最重要的规则**）

```
        ┌─────────────── app（启动装配、串口命令行）───────────────┐
        │                                                          │
   watch_ui_pages ──► watch_ui ──► (平台钩子) ◄── 各服务组件
   （具体页面/游戏）   （框架：页面宿主、模态、控件、手势、样式）    data_hub / settings /
        │                  │                                      wifi_service / motion /
        └──► watch_strings │                                      watch_clock / power /
                           └──► LVGL（lv_*）+ 自己的 watch_gfx     buzzer / imu_logger
                                     ▲
                            ui_port（LVGL 锁与任务；两份实现：设备/PC 模拟器）
```

**铁律（破坏任何一条都会付出代价）**：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **`watch_ui` 不许 include ESP-IDF 头文件**（`esp_*.h`、`freertos/*`、`driver/*`） | PC 模拟器要编译它；一旦引入 IDF，模拟器直接编不过 |
| 2 | **`watch_ui` 不许 include `watch_ui_pages`** | 依赖必须单向：页面依赖框架，反之不行（框架里不该知道"有哪些页面"） |
| 3 | 平台能力**只经 `watch_platform.h` 的钩子**进入 UI 层 | 设备侧由 `app.c` 装配真实实现；模拟器侧有桩实现 |
| 4 | LVGL 的调用必须**持有 `ui_port_lock()`**（`app_start` 里装配界面时也要） | LVGL 不是线程安全的；`esp_lvgl_port` 在设备侧提供锁 |
| 5 | 数据只有**一个来源**：`data_hub` | 以前各页面自己读传感器 → 数据不一致、重复采样 |

### 3.3 平台能力靠"钩子"注入（关键设计）

UI 层不认识硬件。它要什么能力，就在 `watch_platform.h` 里定一个钩子，由 `app.c` 装配：

```c
/* 设备侧（components/app/app.c）—— 接真实实现 */
w_platform_set_time_hooks(&s_time_hooks);       /* → RTC / watch_clock */
w_platform_set_buzzer_hooks(&s_buzzer_hooks);   /* → buzzer */
w_platform_set_rec_hooks(&s_rec_hooks);         /* → imu_logger */
w_platform_set_wifi_hooks(wifi_service_get_hooks());  /* → wifi_service */
watch_ui_set_brightness_hooks(brightness_get, brightness_set);  /* → power */
watch_ui_set_setting_hooks(setting_get, setting_set);          /* → settings */
```

**要加新能力时的顺序**：① 在 `watch_platform.h` 加钩子结构体与 setter → ② 模拟器 `ui_port_pc.c` 写**语义一致的桩**（见 §8 的教训 23）→ ③ `app.c` 装配真实实现 → ④ 页面里用。

## 四、几个容易搞错的子系统

### 4.1 时间语义（★ 踩过两个大坑）

* **RTC 没有备份电池** → 断电后时间无效，必须靠 WiFi SNTP 或手动校时页。
* 界面显示"未校准"是**故意的**：宁可说不知道，也不要显示一个错的时间。
* **时区**：RTC 存本地时间；SNTP 回来后按 `W_SETTING_TZ` 换算（`set_time utc ...` 用于直接写 UTC）。
* ⚠️ **`watch_clock.c` 的一处"注释与实现相反"是有意保留的**：
  闹钟"设到当前这一分钟"会**立刻响**（`s_al_fired_hhmm = -1`），而注释写着"等下一分钟"。
  既有自检**断言的就是"立刻响"**。这是一个**行为选择，不是 bug** —— 要改先确认用户想要哪种（见 §10）。

### 4.2 中文字库流水线（★ 最容易漏字）

LVGL 用子集字库（不是全字库），**没登记的字会显示成豆腐块**。

```
① 中文只写在 components/watch_ui_pages/include/watch_strings.h（集中登记）
   —— 只出现在 app 层日志/命令行里的字，写进 W_STR_FONT_EXTRA
② 跑生成脚本：powershell -ExecutionPolicy Bypass -File .\tools\gen_font.ps1 -Force
   （**必须带 -Force**，否则静默跳过）
③ 跑三条校验（**必须带 PYTHONUTF8=1**，否则 GBK 控制台打印 ✓ 会报错退出 1）：
   python tools\check_all_literals.py     # 所有字面量都在字库里？
   python tools\check_fonts.py            # ASCII 字体配中文文案的低级错误？
   python tools\check_glyphs.py --all     # 三套字库逐码点核对
```

现状：字面量 533 个非 ASCII 字符 / 字库覆盖 **791 个码点**（其中汉字 684），三套字号 14/16/20。

### 4.3 手势与翻页（★ 改之前必须懂 LVGL 行为）

* 轮播是**手写的跟手滚动 + 吸附 + 橡皮筋**（不是 LVGL 的 scroll）。
* ⚠️ **手写滚动的代价**：LVGL 不知道"发生了滚动"，它"滚动就不发点击"的机制失效 →
  v0.6.0 用户实测"列表滑动后误进了选项"。修法见 `watch_widgets.h` 的"拖动/点击判定"。
* 功能列表页（v0.6.1 起）：**5 行一屏放下，不再滚动**，因此该页上滑能开控制中心。
  自检里有断言守着（"可滚 0 px"+"末行完整在屏内"），改行高会让自检立刻报警。

### 4.4 计步算法（★ 参数是实测标定的）

* 定点算法 + 阈值在 `motion.c`，**步长是固定值**（走路 50cm / 跑步 90cm，按用户要求）。
* 调参流程：设备 `rec start` → 走 50 步 → `rec stop` → `serial_cmd.py "rec get /spiffs/imu_0001.bin"` 导出
  → `tools/step_tune.py` / `step_search.py` / `step_eval.py` 离线评估。
* 实测过一组：50 步 → 51 步（+2%）、静止 12 秒 0 误计。**跨步频/跑步/上下楼还没验**。

### 4.5 WiFi 与校时（★ 坑最多，v0.6.1 刚修完两处）

**调用路径**：WiFi 页 → `wifi_hooks_t` → `wifi_service` → ESP-IDF WiFi 驱动 + SNTP。

**v0.6.1 修的两个 bug（都是真机实测出来的）**：

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 连不上时**界面不报错、反复重试、永远不重新问密码** | `hook_connect()` **无条件**置 `s_user_disconnect=true`，指望紧随的断开事件消费它；但**断开空闲站点根本不会产生事件** → 标志残留 → 真正的认证失败被误判成"用户主动断开" | 加 `disconnect_event_expected()`（只在真连着/正在连时才置）；等完 2 秒窗口**强制清掉** |
| 2 | 排查时发现：**密码打错也会被写进 NVS**，把能用的顶掉 | 在"配置刚写进驱动"时就 `creds_save()`，没等连上 | 改成**两段式**：`hook_connect` 只暂存 → `STA_CONNECTED`（关联+4 次握手过了 = 密码对）才落盘；失败则丢弃 |

**其它必须知道的**：
* `reason` 码要会读：**2 = AUTH_EXPIRE**、15 = 四次握手超时（密码错典型）、
  201 = 找不到 AP、203 = 关联失败、211 = 加密方式不兼容。`reason_is_auth()` 决定"要不要清凭据"。
* 连 WPA2/WPA3 过渡模式（`authmode=7`）的 AP：已经设好 `pmf_cfg.capable=true/required=false`、
  `sae_pwe_h2e=BOTH`、`threshold.authmode=OPEN`（不要再"优化"这几项，注释里写了为什么）。
* **凭据自愈**：用**已保存的密码**连上却认证失败 → 自动清掉该凭据，下次直接问密码。
  ⚠️ 只在"用户点已保存网络"这条路上生效；**开机自动重连那条路不触发清理**（`s_conn_used_saved` 为 false）——
  已知小缺口，见 §10。
* 串口排查很方便：`wifi status` / `wifi scan` / `wifi connect <SSID> [密码]` / `wifi reset`。
  连接日志会打印**密码字节码**（查"末尾多了个不可见字符"用，历史上真踩过）。

### 4.6 息屏与唤醒（★ v0.6.1 才真正做到"第一下不误触"）

* 息屏 = **只关背光**（CPU 照跑）。真正的低功耗在 B 批。
* "熄灭后第一下触摸只负责亮屏、不穿透到界面"的实现：
  `w_screen_notify_activity()` 发现"刚才屏是灭的" → 置 `s_swallow_touch` →
  `bsp.c` 的触摸回调这一次上报 `LV_INDEV_STATE_RELEASED`（而不是 PRESSED）→ 抬手时清标志。
  ⚠️ **不能**用 `lv_indev_enable(false)` 事后禁用：LVGL 在**调用读回调之前**就检查了 enable 状态，来不及。

### 4.7 多任务铁律（★ 血泪）

| 任务 | 干什么 | 栈（实测余量） |
|---|---|---|
| `taskLVGL` | LVGL 主循环 + 界面回调 | 6144（余 3328） |
| `data_hub` | 周期采样设备状态 | **4096**（余 2048） |
| `motion` | IMU 采样 + 计步 | 4096（余 2056） |
| `wifi` / `tiT` | IDF 内部 | — |
| `settings_ev` | 订阅"设置变了" → 刷界面 | 3072（余 1024，**最紧的非系统任务**） |
| `console_repl` | 串口命令行 | 6144（余 4800） |

**规则**：
1. **碰 `lv_*` 必须持锁**（`ui_port_lock/UINT32_MAX`），并且**不许在持锁时做阻塞操作**（NVS 写、网络）。
2. 跨任务共享的简单状态（标志、计数）用 `ui_port_critical_enter/exit()` 保护（v0.6.1 给 `watch_clock` 加的）。
3. **回调里给出去的数据必须是副本**，不能给内部活指针（`data_hub` 的快照）。
4. 卡死了先跑 `taskmem`（看栈）+ `bt`（看所有任务调用栈）。

## 七、开发工作流

### 7.1 固定流程（已形成肌肉记忆）

```
① 想清楚要改什么（涉及架构 → 先写实施文档，见 doc/智能手表-A批实施文档.md 的写法）
② 改代码（一次只做一个主题）
③ 编过：.\build.ps1 build         → 0 error（警告也要看，第三方 deprecation 除外）
④ 模拟器自检：SIM_SELFTEST=1      → 退出码 0（**必须**）
⑤ 涉及中文 → 跑 §4.2 的三条校验 + 必要时重新生成字库
⑥ 实机：烧录 → 按"验收清单"逐条让使用者确认（手感/颜色/观感只能人验）
⑦ 写 doc/version/vX.Y.Z.md（最后一节必须是「本版本改动简单说明」）+ 更新版本号三处
```

### 7.2 配置类改动的三个坑

1. **改 `sdkconfig.defaults` 不 clean 不生效** —— 而且是"部分生效"，最难查。
2. 改完要去**生成的 `sdkconfig`** 里确认真生效了（例如 `grep WPA3_SAE sdkconfig`）。
3. **编译器优化等级会暴露老代码问题**：v0.6.1 从 `-Og` 提到 `-O2` 后立刻 3 处 `-Werror`
   （`strncpy` 不补 `\0` 等）—— **都是真问题**。所以本工程现在是 `-O2`，警告不要随手关。

### 7.3 绝对不要做的事

| 不要 | 原因 |
|---|---|
| **不要用 shell（`Set-Content`/重定向）回写源码文件** | 本工程被这样毁过两次：PowerShell 5.1 把 UTF-8 写成 ANSI；`-NoNewline` 把整个文件压成一行 |
| 不要在 `watch_ui` 里 include IDF 头文件 | 见 §0/§3.1 |
| 不要在持 LVGL 锁时做阻塞操作（NVS/网络/长延时） | 会卡住整个 UI |
| 不要在事件回调里删**祖先**对象 | 读已释放内存（§8 教训 20） |
| 不要在**同一棵对象树**上排两个 `lv_async_call` 删除 | 顺序不保证，会崩（v0.6.1 亲自踩过） |
| 不要"想当然"用 LVGL API | 多条坑都出在这（`lv_btnmatrix_set_map` 只存指针、画布调色板在缓冲区头 16 字节…）；**先翻源码** |

## 十、已知局限与未修项（**务必知道**）

| # | 项 | 说明 |
|---|---|---|
| 1 | **本交接时点有 1 项改动只验证了一半** | `wifi_service.c` 的**凭据只在连接成功后落盘**（见 §4.5 表 #2）。**失败路径已实测**（错密码 → `连接未成功 -> 本次凭据不写入 NVS`，`已保存凭据:（无）`）；**成功路径也已实测**（连上另一台 AP → `已保存凭据: <SSID>`）。⚠️ 但"连 CWQLYK 那台一直 `reason=2`"这个悬案**仍未定论**（见 §10 末条），且原负责人做实验时**清掉了表里那份能用的凭据**，需要重新输一次密码 |

| 3 | 开机自动重连路径**不触发**"凭据过期清理" | `s_conn_used_saved` 在那条路上是 false；用户从界面点网络时会触发。小缺口 |
| 4 | `wifi` 命令帮助串写了 `forget` 但**没实现** | 要么补一行（`h->forget()`），要么改帮助串 |

| 6 | 息屏**没真正关屏**（只关背光） | B 批省电第一档：`esp_lcd_panel_disp_off` + 降刷新率 |
| 7 | 屏幕 SPI 仍 40MHz | 对标工程跑 80MHz，微雪官方也是 40MHz；属可选实验（改 `pclk_hz` 一行），需实机验证 |
| 8 | 显示驱动缺 `wait_cb` | 刷屏时**忙等自旋**（LVGL 部分双缓冲在等 flush 完成）；补回调可省 CPU，属 C 批 |
| 9 | 功能列表行高 43 偏紧凑 | 为让 5 行一屏放下；观感由使用者定 |
| 10 | 没有 OTA | 加 OTA 需要第二个 app 槽 → **分区会移动，必须整片擦**，属独立一批 |
| 11 | **仓库边界**：`doc/` 和 `lvgl_sim/` **不在 git 仓库里**（仓库根是 `firmware/smartwatch`） | 靠手工备份；建议把仓库根上提一层或单独建仓（**待你决定**）。接手后**第一件事就该确认这两个目录有没有跟着代码一起给你** |
| 12 | 参考资料 `相关资料/`（含参考工程、精灵图源）不在仓库 | 生成物已入库，正常编译不依赖它；只有"重新生成精灵图"才需要 |
| 13 | 游戏 | 只有一款；无音效（单音喇叭）；无下蹲/难度 |
| 14 | 健康页 | 空占位，等外接 MAX30102 |
| 15 | 硬件扩展余量 | **只剩 GPIO 2/3/17/18**；I2C 现有地址 0x15/0x6B/0x51，加器件要避开 |
| 16 | **悬案：某台 AP（SSID `CWQLYK`）连不上，`reason=2`** | 已确认**不是本机代码问题**：同一时刻连别的 AP 一切正常（能走完 `auth -> assoc -> run`）。该 AP 曾自己改过加密方式（`authmode=7`→`3`）与信道（11→6）。用过的两条口令（用户提供的正确口令 + 故意错的口令）表现**完全一样**，所以"口令串不对"和"AP 在拒绝我们"两种可能都还成立。**排查方法**：连上别的 AP 后 `wifi connect <SSID>`（不带密码 → 用 NVS 里那份）会打印 `密码字节码`，可用来核对存进去的到底是什么 |

```powershell
python tools\serial_cmd.py COM24 "wifi reset"                       # 先清掉已保存凭据
python tools\serial_cmd.py COM24 "wifi connect <你的SSID> 00000000"  # 故意用错密码
python tools\serial_cmd.py COM24 "wifi status"                     # 期望：已保存凭据:（无）  ← 关键
python tools\serial_cmd.py COM24 "wifi connect <你的SSID> <正确密码>"
python tools\serial_cmd.py COM24 "wifi status"                     # 期望：已保存凭据: <你的SSID>
```

> 第 5 步通过 = "只有连上才存凭据"确认无误。**不通过就把日志发给原负责人。**
> ⚠️ 注意第 3 步：错密码那次连接要**等它彻底失败**（约 10 秒）再看 `status`，否则还没走到判定点。
